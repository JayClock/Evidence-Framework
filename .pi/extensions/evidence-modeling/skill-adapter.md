# 可选 Pi UI 适配

仅在宿主提供 `evidence_ui_question` 或 `evidence_ui_contexts` 且本轮选择使用时读取。本页将 Discovery 的 `references/interview.md` 已确定的展示和用户意图映射到工具；不是另一套访谈流程。普通对话无需加载本页，也无需安装插件。本文件随插件维护，不进入对外安装的 Skill 包；插件通过工具说明暴露使用及返回值规则，Skill 不反向引用本文件或工具名称。

Agent 按 Skill 决定焦点、可选合同、问题及权限，插件不决定下一问题、不保存业务记录、不判断追责结束、不推进阶段。插件只展示传入内容、校验载荷和返回真人输入；互斥与窗口状态不是业务状态。调用前先完成本轮获授权的保存；保存失败不打开下一问题。

## 合同选择

调用 `evidence_ui_contexts` 时传入 `contexts` 和可选 `currentAgreementRef`。只传入 Agent 按 FM 方法从材料直接识别、依据充分的合同上下文。每项包含发现记录 ID `agreementRef`，以及 `name`、`parties`（至少双方角色）、`operatingMainline: cash / target-actual`、`operatingBasis`、`boundary`、`unresolved`、`clarification: open / completed`；不接收 `status`。依据不足的线索不作为选项，参数与证明缺口则保留在 `unresolved`。`operatingMainline` 分别展示为“现金权责”或“目标与实际”。`operatingBasis` 只投影“谁与谁签订什么合同，以实现什么具体经营目的”，口头约定用“达成约定”，现金收入／支出须注明观察主体。所有展示字段不包含资料名称、路径、版本、来源 ID 或参考链接；不能直接复制含来源的记录正文。内部来源引用仍保留。插件不判断材料充分性，载荷合法不等于业务依据充分。

`clarification` 是 Agent 按原约定结束依据核对后的投影，不由插件推断。插件只按投影禁用已结束项；接到选择后 Agent 仍须重新核对记录及权限，不能把禁用按钮当成业务保障。焦点在履约上时沿原节点的约定引用确定当前合同。

| 返回                        | 交回访谈协议的含义                                         |
| --------------------------- | ---------------------------------------------------------- |
| `selected` + `agreementRef` | 选择分析焦点，不是合同存在或边界确认；核对目标再按授权保存 |
| `cancelled`                 | 用户返回或关闭；保留原焦点和原问题，不改用文本强迫再选     |
| `empty`                     | 未识别到合同；核对实际记录，不造占位合同，不当作全局结束   |
| `unavailable`               | 无 UI 或面板占用；按相同记录展示普通编号列表，不伪造选择   |

导航不创建业务问题 ID，也不与业务提问捆绑。编号仅对应本次展示，工具返回的稳定 ID 用于定位原记录，不另存菜单。

## 单点问答

调用 `evidence_ui_question` 时传入 `questionId`、`gapKey`、`position`、`story` 和 `prompt`。前两项沿用发现记录中的原问题标识；不因换展示方式分配新 ID。

`position` 映射当前业务位置：

- 履约：`kind: fulfillment`、`contract`、`fulfillment`、`point: request / confirmation`；可选 `evidence` 是当前端点凭证的业务名称，不是任意支撑凭证的名称。未知名称省略，不按类型拼接后缀。
- 合同识别：`kind: contract` 与 `contract`。
- 协商或领域：`kind: negotiation / domain`、`context` 与 `object`。
- 未定位：`kind: unlocated`，不补造业务位置。

`story` 只含当前节点的有依据叙述，不夹带问题；`prompt` 是一个仍影响当前判断的业务问题。二者与普通对话内容一致，选择页和回答编辑器保留同一份当前进度。不传文件来源列表、影响栏或全局进度；没有必要问题时直接交接，不调用工具凑题。

| 返回                  | 交回访谈协议的含义                                                     |
| --------------------- | ---------------------------------------------------------------------- |
| `answered` + `answer` | 保留原文；Agent 消化其中全部事实及控制意图，不能仅凭状态判定缺口已解决 |
| `switch-context`      | 用户要求查看／切换合同；进入独立导航，不解决原问题                     |
| `deferred`            | 暂缓当前问题，保留原标识及未决依据                                     |
| `stopped`             | 结束本轮，按既有授权保存后停止，不等于追责结束                         |
| `cancelled`           | 关闭或空白提交；没有业务回答，不自动重新打开或改用文本追问             |
| `unavailable`         | 无 UI 或面板占用；普通对话继续同一问题，沿用原问题标识                 |

## 中断与持久化

取消不是不可用：前者等待用户下一次输入，后者允许改用普通对话。工具缺失或报错时说明交互限制，核对是否收到结果；未收到的回答不能猜测。不要循环调用不可用的 UI，也不要把界面不可用当作缺少 FM 方法或业务来源。

已返回的回答先保存原话来源，再按授权维护术语。任一保存失败即停止，分别交接发现记录与词汇表的结果，以及未保存原文；切换展示不能绕过保存失败。恢复先读实际文件，只补齐获授权且未保存部分，不重记已保存回答或重复提问。若跨会话没有留下未保存原文，明确缺失，不能宣称已恢复。

工具返回不是持久化确认。问题、焦点、来源、暂停与结束依据仍只在访谈协议规定的业务记录中维护，不建立插件状态文件，不复制故事、责任图或词汇定义。
