# 聚合设计

## 聚合

| 聚合 | 聚合根 | 成员与来源 FM ID | 命令入口 | 不变条件 Rule ID | 领域事件 |
| :--- | :----- | :--------------- | :------- | :--------------- | :------- |

按不变条件选择小型一致性边界，外部修改经聚合根。不规定聚合数量，不机械映射 FM Context 或 Fulfillment。

## 不变条件

引用 FM Rule，不重复定义公式；说明规则何时检查、失败语义及谁负责执行。前置条件可表达不代表已实现操作调度。

## 事务边界

说明业务上哪些改变必须同时成功、跨聚合允许何种最终一致性和冲突结果。数据库事务、Repository、锁、Outbox/Inbox 等机制留给 Architecture。

## 规则追溯

| 来源 Entity/Rule ID 或表达 gap | 一致性要求 | 聚合内/跨聚合执行位置 | 后续验证 |
| :----------------------------- | :--------- | :-------------------- | :------- |

记录 FM 尚不能表达的操作/状态迁移与依据。极小范围或简单胶水不需要聚合时，在各章节说明不适用理由及替代方案，不补造规则或聚合满足配额。
