# 任务前馈装配协议

本协议定义可移植方法；项目的具体业务范围、架构、命名、howto 与范例由项目文档维护。不要把当前 Skill 仓库的业务名、路径或数据库当作消费项目默认值。

## 来源发现

从消费项目的项目指令进入，定位其 Guides 导航；本仓库入口为 `docs/guides/index.md`。其他项目没有统一导航时，从实际需求、架构、配置、源码与测试定位同类依据，不为凑目录创建空文档，也不因缺少某个约定文件名阻塞无关工作。

四层来源分别是：项目宪法、项目基线、工程指南、当前任务。按任务类型加载必要章节与真实源码符号，不把全仓库资料塞进上下文。Skill 的固定技术 profile 约束实施形式，不提供行业默认业务；与项目架构冲突时停止受影响规划，不能私自换栈或改 profile。

## 按测试工序生成任务

从消费项目 Guides 定位工序指南或等价测试策略；本仓库的项目规则由导航路由，不复制到可移植 Skill。其他项目没有专门工序文件时，从实际架构、测试、规范和范例提取同类依据，不要求新建空文件。

展开候选任务前先实例化本切片的测试策略：报告触发与未触发的工序、每项可观察结果的 Q2 → Q1 支撑、按架构组件划分的功能上下文与替身选择；写不出对应 Q1 或替身边界时先补设计。该记录写入 `plan.yaml.strategy` 和任务记录的 `guides`，不建立工序状态。

1. 先确定软件职责、可观察结果与场景，再选择工序。每种工序说明触发条件、必要输入、行为拥有者、测试边界（真实依赖/替身）、产物、退出条件和前置契约；没触发的工序不生成空任务。
2. 合并与拆分以同一拥有者/操作、可验收结果和测试边界为依据。同一操作的相关场景保留全部检查但不重复实现；不同环境与失败定位边界可拆开。不要把实现和证明该实现所需的回归机械拆成两项。
3. 工作单元唯一拥有，适配任务用有来源的 `design.*` 单元并依赖领域契约。API 不因层次顺序依赖持久化，真实装配才汇合必要适配器；前端组件可消费确定的 HTTP 契约，真实联调另需服务。平台复用先核对代码与复验方法，不按切片重建。
4. 在任务 Guides 记录工序实例的触发理由、选用章节、边界与适用限制，`procedureRefs` 引用实际工序/规范/howto/范例文件；步骤实例化为 `steps`，退出条件连接 `checks` 与 `completionCriteria`。具体命令、输入、反例和失败不变性不能只写在通用工序中。
5. 工序不等于 mode，也不等于 concern 或任务身份；不新增 schema 字段、工序状态或未支持的 concern。确需扩展编译能力时单独登记缺口并授权修改，不能伪造字段已支持。
6. 编译后复核工序适用性、共享去重和证据去向。`coverageComplete` 只证明结构覆盖，API 支持任务闭包也不包括下游验收任务，不代表旅程完成；范围/业务未知保持局部缺口，不能用不选工序绕过已有 API 覆盖。

## 规划时形成 Guides

- 从软件职责与验收选择交付结果；FM 表达的全部业务活动不自动成为已批准 MVP。已有 API 的结构覆盖仍按编译规则维护，范围冲突显式澄清，不能偷偷排除能力。
- 从相关架构、质量属性和术语定位项目决定；未知权限、数据库、审计、语言和集成协议保持未决。纯技术或纯领域工作只受相关缺口影响。
- 将来源路径、稳定源 ID、版本/摘要与适用章节放入 `sourceManifest` 和任务记录的引用字段；文件路径不是虚构的新 FM ID。
- 在任务局部设计明确行为/数据拥有者、公开契约、技术库、事务入口与必要外部边界。共享设计只引用，不在每个任务复制整套基线。
- 用 procedureRefs 引用选用工序及相关规范、howto 与范例的实际项目根相对路径；章节、触发理由和测试边界写入 Guides，在步骤中说明使用顺序与适用限制。不把工序标签当文件路径，不复制打样代码作为新事实源。
- dependencyUsage 说明消费前置的哪些契约，以及怎样核对真实就绪证据。范例和已存在文件不自动等于依赖完成。
- 将每个完成条件连接到具体 CHECK：命令、cwd、环境、输入、预期、反例、失败不变性和证据要求。未知命令或必要依据关联 gap。

## 执行前检查

执行者读取项目实际开工检查。最低要回答：授权/目标/文件范围、来源与审核、直接前置与证据新鲜度、设计边界、工程做法与环境、验证与停止条件。

编译器摘要只覆盖其实际 FM/API 输入，不覆盖所有架构/规范/howto/代码变化。taskKey 不变不代表证据有效；相关来源、指南、实现或 CHECK 环境变化后显式评估重验范围。计划结构检查不能证明上述语义就绪。

未通过时不进入 Action：局部任务设计修订详情，单元/依赖变化返回 Plan，业务事实返回拥有者，环境问题记录局部阻塞。只读任务只报告，不写状态。

## 状态与退出

前馈不是第三套工作流状态：`compiled` 仍由程序计算，`tasks[taskKey].status` 是状态唯一位置，`tasks[taskKey].observedEvidence` 只保存真实执行结果。`review.html` 只是可重建投影，不得成为状态或批准来源；不得新增私有 guides-ready 状态、自动审批或凭文件存在标 done。

一次任务完成后停止；恢复、纠偏或来源变化时重新装配同一任务的 Guides，不依赖聊天记忆。规划只交付计划，不执行产品 CHECK 或预填 observedEvidence。
