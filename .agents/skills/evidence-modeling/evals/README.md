# 建模入口与行为评测

## 两类输入

- [routing.json](routing.json)：建模与手动交接 Skills 同时可用时的选择、权限与近似请求。不能预先指定待测 Skill，否则测不到触发能力。
- [evals.json](evals.json)：明确进入 Modeling 后的委派、权限传递、合同级准入、结束后自动接续与 Handoff、阶段阻塞及部分交付；专业访谈与 FM 语义只在对应包的 evals 维护，不在编排层复制。

评测文件只用于维护，不作为真实业务来源。案例 ID 在各评测文件内唯一，删除不补号、不复用旧 ID；覆盖依据是当前分支与风险，不是历史 ID 集合或固定数量。静态测试检查目录、引用、路由用例结构与执行协议，不证明 Agent 实际选择正确。

## 隔离执行

1. 使用独立临时项目和新会话，不读取真实 `.evidence/`。为题述路径准备最小合成资料；需要准入或多轮回答时由真人提供可定位的依据，不让待评 Agent 自答。
2. 新旧版本使用同一模型、宿主、工具、项目指令和输入；同一组全部安装 `availableSkills`，保留其他实际竞争 Skills 的一致可见性。显式入口的调用控制由宿主执行，不通过删除元数据模拟。
3. 只向待评 Agent 提供 prompt 和题述来源，不提供 primarySkill、expectations 或 forbiddenActions。非显式案例不得附加“请使用某 Skill”的提示。
4. 记录实际读取的 Skills 与参考、执行顺序、文件前后摘要、命令、提问和停止位置。模型先读错误 Skill 再纠正也记录，不只观察最终答复。
5. 每例至少独立运行三次；旧版与新版相互隔离，不共享对话、答案或已生成文件。多轮案例跨会话提供题述当前理解或显式生成的 Markdown 交接，并核对其中引用的实际产物。

`primarySkill: null` 表示不应进入本组专业流程，不代表禁止使用其他合适工具。FM 方法作为 Discovery 的知识依赖不算第二次主流程触发；一体生成由 FM 包完成模型与 API，再接续 Visualization，也不是误触发；API 阶段不应重新执行 FM 检查。含方法词汇的 Skill 维护请求不等于业务建模请求。访谈只使用普通对话，不提供建模交互适配器。

## 判定与证据

逐条 expectations 标注通过／失败／未评，并引用原始轨迹或文件差异。检查：

- 应触发是否触发，是否误触发相邻 Skill；明确入口与自动选择分别统计。
- 是否遵守只读、仅 FM、仅页面等写入边界，是否绕过人类准入。
- 是否吸收全部输入并当轮沉淀术语、术语写入失败后停止、当前节点按依赖前沿成组提问、题间独立且回答后重算；过程交接是否按显式请求或获授权的合同级自动接续保存，未澄清合同、Context Role 与控制意图是否完整。
- 是否省略必要步骤、反复索取已有事实、自动恢复暂缓或越权进入下游。
- 是否按分支加载资料；记录实际 token 与时长（可取得时），不可用填未取得，不用字符数冒充 token。

案例 18—21 使用 [合同级合成来源](fixtures/contract-batch-admission.md)，覆盖独立合同闭合后不等待无关合同、必要证明缺口不能角色化掩盖、只读覆盖默认接续，以及 Handoff 保存失败。准备题述文件权限与原有无关文件，记录 FM → Handoff 的实际调用与文件差异；机器测试和案例存在不证明这些 Agent 行为已通过。

案例 22—23 使用 [领域分支合成来源](fixtures/domain-branch-admission.md)，覆盖领域独立结束、仅 FM 自动接续、未澄清协商与合同保留，以及关联责任更正使确认失效。混合导航、隐藏待追溯与资料出处、领域分类不删除义务的交互案例由 Discovery 的 evals 维护。

保存结果到隔离工作目录，不回写案例为“已通过”，不修改业务批准或计划状态。总体通过率之外列出每例方差、关键越权失败和环境阻塞；触发准确不抵消越权写入。没有真实 Agent 运行时保持未执行，不以用例存在、文档测试或人工阅读填通过率。
