# 文件交接与恢复

本页只定义组合入口如何消费产物、核对引用和交接。专业方法归 FM，访谈选题和控制意图归 Discovery；入口不保存第二套业务事实或准入状态。

## 文件归属

默认路径相对项目根，沿用指定位置与既有文件，不自动迁移：

| 产物         | 默认位置                                             | 拥有者与消费条件                                                                                |
| ------------ | ---------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| 发现记录     | `.evidence/discovery.json`                           | Discovery 保存原话、约定与履约骨架、追溯、异常、实际案例及人类决定；默认 `schemaVersion: "2.0"` |
| 独立问题     | `.evidence/questions.json`                           | 需要拆分已提问题时使用；主记录以 questionsFile 引用，同一问题只维护一处                         |
| 词汇入口     | `.evidence/glossary.json`                            | FM 领域语言方法；standalone 定义或 model 引用，不复制已建模含义                                 |
| 正式模型     | `.evidence/fm/`                                      | FM 在追责结束门槛满足且有编辑授权后维护；发现骨架不是正式 FM                                    |
| FM 检查记录  | `.evidence/checks/fm/`                               | 获授权保存的紧凑运行清单；绑定输入摘要，复验需核对新鲜度                                        |
| API 源与投影 | `.evidence/api/api.json`、`.evidence/api/generated/` | API Design 维护；一体生成在 FM 通过后直接接续，FM 本身不写接口设计                              |
| API 检查记录 | `.evidence/checks/api/`                              | API 任务按授权保存，不替代 FM 当前有效证据                                                      |
| 联合审核页   | `.evidence/views/index.html`                         | Visualization 从当前 FM 与 API 生成，可重建，不保存批准或发现记录状态                           |

发现记录中的 `business.agreements`、`business.responsibilities` 和 `business.evidenceTraces` 分别维护约定、履约骨架及关键数据追溯；其他分析按 Discovery 模板保存。`handoff.focusRef` 指向当前对象，视图只按引用生成。责任闭合引用默认在 `business.responsibilityClosure`，没有同步的“当前请求／确认”或可编辑业务视图副本。

这些记录是有来源的工作理解，不是第二份模型。名称和定义由 Glossary 或已有 FM 唯一维护；模型落实术语时保留 term ID 并将条目改为引用，不重抄定义。

## 恢复一个分支

1. 核对本次意图、文件权限、实际 Git 差异及停止／暂缓状态，不从聊天推测已保存内容。
2. 读取对应分支的实际文件和来源版本；发现记录从 `focusRef` 沿对象、原问题及支撑引用恢复，不从展示摘要倒推事实。
3. 发现记录不是当前 `schemaVersion` 时，报告结构限制并保留原文件；转换须另有明确授权，不在正常访谈中猜测映射或删历史材料。没有当前格式不意味着缺少业务依据，FM 可按实际定位只读核对人类原话。
4. 保存中断时分别核对发现记录、词汇表及已获授权的 FM 文件；它们不是原子事务，只补齐尚未保存且本次获授权的内容。
5. 正式模型编辑恢复前，按 FM 的 `references/responsibility-closure.md` 重新核对当前范围、全部分支、人类终点及结束确认版本。新增责任或约定更正不能沿用旧确认；技术表达修正未改变业务时可复用仍适用依据。
6. 模型、来源、场景或校验器变化后重跑检查，旧报告或页面存在不是新证据；校验失败保留当前文件，不自动回滚。
7. 焦点交给对应执行者。一体生成恢复时核对实际 FM/API 差异及检查，不凭旧页面推测完成；已完成的 FM 未变且准入仍有效，可复验后接续 API，无需无故重写模型。停止或暂缓只在明确恢复意图下继续，模型缺口不自动解除访谈停止状态。

**退出条件**：当前分支、焦点引用、必要来源、实际保存结果及剩余判断均能定位；否则只交接限制。

## FM → API → 联合审核

这是本入口生成／修改模型的默认交付链路，不是并行编辑两个事实源。完整请求一次授权 FM、整体 API 及同一审核页；只修改 FM、只校验或禁止生成页面等更窄要求优先。进入写入前定位所需专业 Skill、实际文件及运行依赖；不把资源缺失当业务未知。

### 1. FM

先消费 FM 的追责结束准入依据，核对本次授权及来源版本；未满足时不编辑 FM/API，也不生成新审核页。满足后由 FM 执行正式表达、词汇引用及适用场景校验，展示实际差异。FM 检查失败或 `inputChanged` 为 true 时不进入 API，保留已改文件并说明未完成。

### 2. API

FM 本次通过后，交给 `evidence-api-design` 消费当前整体 FM，重新执行 inspect，直接维护 `.evidence/api/api.json`、check 并 project 到 `.evidence/api/generated/`。不再等待用户第二次发出 API 请求，也不重复业务确认；整体资源、调用角色、HTTP 契约和全部消费者流程按 API 包的方法维护。

API 技术错误在授权范围内修正重跑；业务事实、身份或基数缺口交接，不反向修改 FM 来取得 API 通过。缺口、检查失败或输入变化时不进入联合审核生成；分别说明 FM 已保存／通过与 API 未完成，保留已有审核页并明确它不是当前有效证据，不把局部成功声称完整交付。

### 3. 联合审核

两源通过后调用 `evidence-visualization` 的生成器，要求 API 必须存在；同页展示模型与接口，不维护另一套审核工具：

```bash
"$PYTHON" -B "$VISUAL_SKILL_DIR/scripts/generate.py" \
  --project-root "$PROJECT_ROOT" \
  --fm-skill "$FM_SKILL_DIR" \
  --api-skill "$API_SKILL_DIR" \
  --require-api
```

变量设置为实际绝对路径。生成器重新检查 FM 与 API，临时 API 投影不重写正式 generated 目录；核对 `modelDigest` 和两源生成前后新鲜度，通过后只原子替换 `.evidence/views/index.html`。联合模式缺 API 不生成模型单独页面；校验失败或输入变化保留已有审核页。按 Visualization 的要求运行最终 HTML 浏览器回归并检查截图，缺环境如实交接，不声称审核通过。

这条链路不是原子事务：FM/API 源编辑可能已经保存，后续失败不自动回滚或删除它们。交接分别列出两源差异、实际检查、API 交付与 HTML 路径，未完成或未验证部分明确可见。页面只是当前版本的只读投影，不自动批准，不修改需求、计划状态或 Git 历史；完成或阻塞后停止。

### 只读与单独投影

只校验运行 FM 检查及现有 API 的 inspect/check，不运行 project 或生成器，不写任何项目文件；API 缺失报告联合检查未完成，明确只查 FM 时仅执行 FM。单独要求联合审核页只授权写页面，使用上述严格生成命令，不编辑两源或正式 API generated。没有 API 的独立 FM 可视化由 Visualization 处理，不将其称为联合审核；不通过隐藏或删除现有 API 制造单独投影。

## 核对交付

### 访谈与术语

核对 Discovery 交接的来源、约定边界、全部主履约、当前请求—确认骨架、凭证追溯和异常新义务，不以对象数量衡量理解程度。适用的单据推演、参与者与角色扮演、变化点引用须可恢复；未执行项如实说明。

消费完整责任图、人类各分支终点及全局追责结束原话的定位，不重做其专业判断。纯领域不补合约，进入正式编辑仍需人类无适用履约责任的确认。停止不是结束确认，局部充分不放行。

原话与术语分别列保存结果。缺少 FM 方法明示词汇尚未更新；未决解释及无模型授权的更正留在发现记录，不另存已建模定义。只有术语保存不能宣称 FM 通过校验。

### 正式模型与检查

核对来源到 FM 对象、属性、关联、规则及场景的映射；完整责任图与实际增改删一致，技术表达限制不能伪装成业务排除。

检查 Schema／CEL／lineage／simulation／timeline 的本次结果、`modelDigest` 和 `inputChanged`；未实际执行场景时 simulationPassed 为 null。Git diff 之外的新文件也须展示，失败说明已改内容，不倒改业务预期。

只校验请求不写任何项目文件。授权留存检查时按 FM 方法保存紧凑运行清单与日志指针，不复制完整输出或覆盖已引用记录。

## 最小交接

- 当前分支、焦点与本次实际变更；
- 文件、对象及来源引用，各文件实际保存结果与未保存原因；
- 实际命令、退出结果、输入摘要及未验证限制；
- 未决判断、受影响范围与下一步选择。

正文留在各自拥有者的文件中。保存、机器检查、人类追责结束及业务批准分别说明；完成本次链路后停止，不自动发起需求、规划或实施任务、提升状态、暂存或提交。
