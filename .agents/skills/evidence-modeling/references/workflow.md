# 文件交接与恢复

本页只定义组合任务如何读取、核对和交接产物。专业分析、访谈和模型校验由入口指定的执行者维护，不在此复制方法。

## 文件归属

默认路径相对项目根，按需创建；沿用已有文件与用户指定位置，不自动迁移：

| 产物         | 默认位置                                             | 归属与读取条件                                                          |
| ------------ | ---------------------------------------------------- | ----------------------------------------------------------------------- |
| 发现记录     | `.evidence/discovery.json`                           | discovery 保存来源、原话、可读视图、实际问题及控制状态；恢复访谈时读取  |
| 拆分问题     | `.evidence/questions.json`                           | 需要拆分已提问题时使用，主记录以 questionsFile 引用；同一问题只维护一处 |
| 词汇入口     | `.evidence/glossary.json`                            | FM 领域语言方法维护 standalone 定义或 model 引用；访谈和模型编辑读取    |
| 模型源       | `.evidence/fm/`                                      | FM 维护当前 JSON、说明与 validation；模型任务读取                       |
| FM 检查记录  | `.evidence/checks/fm/`                               | 获授权时保存绑定输入摘要的紧凑运行清单；复验时核对新鲜度                |
| API 源与投影 | `.evidence/api/api.json`、`.evidence/api/generated/` | API 设计任务维护，建模交接只引用                                        |
| API 检查记录 | `.evidence/checks/api/`                              | API 任务获授权保存，不能作为 FM 当前有效的替代证据                      |
| 可视化       | `.evidence/views/index.html`                         | visualization 从当前输入生成，可重建，不保存业务结论                    |

发现记录不复制模型、词汇定义或完整聊天。model 条目从 FM 目标读取名称与含义；模型编辑落实 standalone 后保留 term ID 并替换为引用。该转换及悬空引用校验按 FM 的领域语言方法执行。

## 恢复一个分支

1. 核对用户本次意图、文件权限和已有 Git 差异，确认目标路径与当前控制状态。
2. 读取该分支需要的产物及其来源定位，不从旧聊天推测已经保存什么。
3. 若此前保存中断，分别核对发现记录与词汇表；两者不是原子事务，只补齐本次授权且尚未保存的内容。
4. 若模型编辑中断或校验失败，保留当前文件与未决项。模型、来源、场景或校验器变化后重跑，不把旧检查或页面存在视为有效证明。
5. 将焦点与限制交给对应执行者。已停止或暂缓的问答只有在明确恢复意图下继续；模型任务返回缺口不自动提问。

**退出条件**：能够指出当前分支、所需文件、实际保存状态和仍受影响的判断；否则只交接缺口。

## 核对产物

### 访谈与术语

消费 discovery 的交接：经营依据、可读业务视图、凭证追溯、实际单据推演、参与者与角色扮演、变化点与边界，以及词汇条目、问题与控制状态。按本次路线核对适用项，纯领域不要求合约。

原话与术语分别列保存结果。缺少 FM 方法时可以保存一般事实和待沉淀项，但须明确词汇表尚未更新；只有术语更新也不能宣称整个 FM 通过校验。未决解释和无模型编辑授权的更正留在发现记录，不另存已建模定义。

### 模型编辑与校验

消费 FM 的交付：实际变更及来源、ready/support/pending 评估、词汇引用、Schema/CEL/lineage/simulation/timeline 结果、modelDigest、inputChanged、时间线与未决顺序。业务判断和 Schema 映射均以 FM 方法为准，组合入口不增设另一套准入规则。

检查覆盖本轮增改删，也覆盖 Git diff 未列出的未跟踪文件。失败时明确当前模型未通过和已经修改的文件，不倒改业务预期或自动回滚。没有实际场景执行时 simulationPassed 为 null，不声称模拟通过。

只校验请求不写任何项目文件。用户授权留存时，按 FM 校验方法保存紧凑运行清单及日志指针，不复制完整输出或覆盖已引用的记录。

## 最小交接

- 本次分支、目标及实际变更；
- 已保存文件与引用位置，未保存内容及原因；
- 实际执行的检查、退出结果、输入摘要和证据限制；
- 仍不能作出的判断、受影响范围与下一步选择。

事实、模型和检查正文留在各自文件中，交接只引用。界面反馈不能替代文件写入证据，保存不等于批准。完成后停止，不自动发起下游任务、审批、暂存或提交。
