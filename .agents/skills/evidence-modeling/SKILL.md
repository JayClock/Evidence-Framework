# Evidence 建模编排

只选择分支、传递授权、核对交付，不重做专业分析或维护私有业务状态。通过宿主原生 Skill 入口或显式读取本文件执行完整流程，访谈使用普通对话。

## Guides

首次进入或恢复时读取项目指令、当前目标、实际文件与 Git 差异。默认产物根为 `.evidence/`，只修改本次授权的文件，保留无关改动，不自动迁移。分派、恢复与阶段接续统一按 [文件交接](references/workflow.md)。

| 用户意图                         | 执行者                                                    | 本轮结果与写入范围                                                                                                                                                                                                 |
| -------------------------------- | --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 讨论方法、只聊不落盘             | FM 或 API 的讨论分支                                      | 解释与展示，不写文件、不开始访谈                                                                                                                                                                                   |
| 访谈、查看／切换上下文、继续澄清 | `evidence-discovery`，消费 FM 方法                        | 按现金权责或目标—实际对比发现约定与双方，再围绕履约判断沿关键数据开展凭证追溯、深入后返回判断、合同一方负责并主动成组澄清、直接消费 Entity/属性定义及当轮统一表达；按授权渐进维护 FM，分支结束后接续下游与 Handoff |
| 生成或修改模型                   | `evidence-fm` → `evidence-api` → `evidence-visualization` | 渐进 FM 与一致性检查；范围结束后 API → 联合审核                                                                                                                                                                    |
| 只校验                           | FM 与 API 各自的只读检查分支                              | 只读报告；明确仅 FM 时不查 API                                                                                                                                                                                     |
| 生成联合审核页                   | Visualization，要求 FM 与 API                             | 只更新页面，缺 API 不降级                                                                                                                                                                                          |
| 停止、暂缓、仅补资料             | Discovery 控制分支                                        | 按更窄授权处理后停止                                                                                                                                                                                               |
| 显式记录建模过程或会话交接       | `evidence-handoff`                                        | 保存 Markdown 交接，返回实际路径                                                                                                                                                                                   |

本入口建模访谈默认包含 FM 渐进维护授权，不等全部澄清结束才首次保存；已有相同授权不逐轮重新申请。凭证与责任角色及所属上下文共同落地；直接识别主要请求—确认交互，配对后包裹履约，不另列责任清单或保存空履约，未包裹交互按原问题继续。模型每批修改检查一致性。普通回答不触发下游；合同或独立领域／协商取得人类结束确认后，才检查整个范围完整性并按授权接续 API、联合审核及 Handoff。纯讨论不授权模型 JSON；只聊不落盘、仅访谈、不生成模型、只读、只修改 FM、不设计 API、不生成审核页或不记录等限制优先。首次分派或交接受阻时，只读 [对应基线样例](examples/README.md)。

## Action

1. **选择执行者。** 根据当前目标与最窄授权选择分支，通过资源发现或指定路径定位专业 Skill 并读取其入口，无需专门的 Skill 调用工具。连续问答交由已选 Discovery 分支增量承接，目标或授权改变、有效合同／领域／协商分支结束信号到达时才接续分派。完成时，执行者、输入、允许文件与停止条件明确。
2. **执行获授权链路。** 按文件交接委派专业拥有者；渐进编辑核对 FM 资源、业务依据与授权，每批检查一致性；范围结束再核对完整责任、人类确认及下游资源，执行显式范围完整性检查。API 消费同一有效范围结果与必要依赖，不重复 FM 检查；通过后才接续联合审核。更窄授权到对应出口即交接；合同或领域／协商分支接续成功或阻塞后仍调用 `evidence-handoff` 保存未澄清部分及实际结果，明确禁止保存时除外。完成时，本分支所需结果已取得，或阻塞点及部分保存清楚。
3. **核对交付。** 按交接协议检查实际文件、输入版本、命令结果和未执行限制，专业检查仍由其拥有者完成。完成时，能区分各阶段成功、完整交付与未决工作，并报告后停止。

## Sensors

- **访谈**：消费 FM 对现金权责或目标—实际对比的判断，实际约定与责任双方、增量发现的协作及按需导航准确；各请求与确认的责任人是所属合同的一方；每轮主动寻找并一起提出全部可同时澄清的独立内容，局部依赖不造成整轮串行；规范名称复用已有映射或按明确含义直接翻译英文。凭证追溯能说明判断、关键数据、来源、深入与返回的关系；原问题、未决依赖、控制意图和模型待改影响准确；范围完整性、人类结束确认与保存分别核对。
- **正式生成**：FM 差异、当前一致性及明确范围完整性、API 对该范围的整体覆盖与契约、最终 HTML 浏览器检查齐备；某一阶段成功不代表整条链路完成。
- **只校验**：核对无项目写入，两源分别报告；API 缺失时联合检查未完成。
- **联合审核**：当前两源、严格联合模式及页面验证可定位；旧页面不是当前有效证据。

合同级结束、领域／协商分支结束、全局追责结束、保存、机器检查与业务批准分别说明；自动 Handoff 的实际路径与未保存内容可定位。

## Steer

- **必要资源缺失**：在受影响写入前停止，交接具体限制，不自动安装或扩大授权。
- **业务依据不足或确认失效**：交接拥有者与缺口后停止，模型任务不自动解除访谈停止状态。
- **检查或保存失败**：保留真实错误与已改文件，按原专业授权修正；分别报告未完成阶段，不自动回滚。
- **完成**：列出分支、文件、实际保存与检查、未决影响后停止。不自动批准，不启动需求、规划、实施或 Git 操作。界面只收集交互，业务保存归专业 Skill。
