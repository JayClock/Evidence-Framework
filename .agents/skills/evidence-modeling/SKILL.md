# Evidence 建模入口

只负责编排、权限与交接。专业业务分析、领域语言和模型表达归 `evidence-fm`；访谈机制归 `evidence-discovery`；正式模型的离线审核页归 `evidence-visualization`。不复制专业方法或建立入口私有状态。

## 1. 定位目标与实际文件

读取项目指令、本次目标、已有来源、记录和 Git 差异，按 [文件交接](references/workflow.md) 恢复。默认根为 `.evidence/`，只修改本次授权的文件，保留无关改动；不自动迁移、转换或删除既有记录。

通过宿主资源发现定位所需 Skill 的实际目录，读取其 SKILL.md，不假设兄弟路径。方法或工具缺失只报告能力限制，不以业务提问弥补。

## 2. 选择一个分支

| 本次意图             | 执行者及读取条件                                                                        | 写入范围与退出条件                                                             |
| -------------------- | --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 讨论方法／只聊不落盘 | FM 的 `references/business-analysis.md`；术语问题按需读 `references/domain-language.md` | 只解释与展示，不保存、不自动进入访谈                                           |
| 访谈、继续澄清       | Discovery；合同、骨架、追溯、单据推演、参与者与角色扮演及变化点按 FM 方法               | 只保存发现记录与词汇表；一个必要问题后等待真人或交接                           |
| 生成／修改模型 JSON  | FM；先核对 `references/responsibility-closure.md` 的人类全局依据，再核对本次编辑授权    | 门槛满足后，先业务分析，再按当前 Schema 映射与校验；展示差异及真实结果         |
| 只校验               | FM 的校验分支                                                                           | 只读报告，不写任何项目文件，也不宣称责任已闭合                                 |
| 生成审核页           | Visualization                                                                           | 从当前重新校验的 FM／已有 API 生成只读投影；不显示未经准入的发现骨架为正式模型 |
| 暂缓／停止／仅补资料 | Discovery 的控制分支                                                                    | 按更窄授权保存新增来源或影响后停止，不自动恢复问答                             |

生成／修改请求提供本次编辑授权，不替代人类追责结束确认，也不是业务批准。直接调用 FM、充分外部说明或已有模型同样核对门槛；未闭合只交接缺口，不局部放行、不自动改为访谈。

## 3. 核对分支交付，不重做专业分析

业务逻辑、领域逻辑和工具／胶水按实际依据选择路线，不强迫所有输入通过合同流程。访谈按 FM 方法的分析依赖推进；正式 JSON 映射是准入后的独立动作。

- **访谈**：从记录引用生成可读视图，全部主履约、当前骨架、追溯、异常与未知均可定位；人类终点和全局结束依据分别检查。原话与术语分别报告保存结果，任一失败即停止，未执行单据推演不声称通过。
- **模型编辑**：人类结束确认仍覆盖当前范围和版本；核对定义拥有者及稳定引用。落实 standalone 后保留 term ID，将条目替换为 FM 引用；目录、命名与结构以当前 FM Schema 为准。实际增改删、真实检查和限制可定位。
- **只读校验**：没有项目写入；没有实际场景执行时 `simulationPassed` 为 null。
- **审核页**：标明输入与生成结果，页面不是业务批准或状态来源。

## 4. 交接后停止

列出当前分支、文件引用、实际保存结果、检查和未决影响。界面只收集交互，不保存业务记录；不可用转普通对话，不伪造回答。

保存、机器检查、追责结束和业务批准分别说明。失败保留真实错误及已改文件，不自动回滚。完成当前分支后停止，不自动进入需求、API、规划、实现或 Git 操作；模型缺口不自动解除访谈停止状态。
