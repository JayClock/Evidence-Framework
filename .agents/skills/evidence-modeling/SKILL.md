# Evidence 建模入口

只负责编排、权限与交接。访谈机制归 `evidence-discovery`；业务分析、领域语言和模型表达归 `evidence-fm`；离线审核页归 `evidence-visualization`。

## 1. 定位目标与文件

读取项目指令、用户目标、已有记录、当前模型与 Git 差异，按[文件交接](references/workflow.md)恢复。默认产物根为 `.evidence/`，沿用已有文件与指定路径，不自动迁移。只修改本次授权的文件，保留无关改动。

通过宿主资源发现定位所需 Skill 的实际目录，读取其 SKILL.md；不假设兄弟路径。缺少资源是执行限制，不转化为业务问题，也不凭记忆补造专业方法。

## 2. 选择一个分支

| 当前请求               | 执行者与读取条件                                                                                                         | 写入范围与退出条件                                                                         |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------ |
| 访谈、继续澄清         | `evidence-discovery`；业务分析读取 FM 的 `references/business-analysis.md`，当轮术语读取 `references/domain-language.md` | 保存发现记录与词汇表中的明确术语，展示可读业务视图；有必要缺口时只问一个问题，否则交接停止 |
| 生成／修改模型 JSON    | `evidence-fm`；先业务分析，再按当前 Schema 映射与校验                                                                    | 仅编辑本次授权模型与对应词汇引用，展示差异、真实检查和未决项                               |
| 只校验                 | `evidence-fm` 的校验分支                                                                                                 | 只报告真实结果，不写任何项目文件                                                           |
| 生成审核页             | `evidence-visualization`                                                                                                 | 从重新校验的 FM／已有 API 生成只读投影，不自动设计 API                                     |
| 暂缓／停止／仅补充资料 | `evidence-discovery` 的控制状态分支                                                                                      | 按当前授权保存新输入并停止，补充资料不自动恢复问答                                         |

只聊不落盘、仅保存资料、只记录冲突等更窄要求优先。访谈和术语写入不授权编辑模型 JSON、关系、规则、验证场景、API 或实现。生成／修改请求授权本次编辑，不表示业务批准。

## 3. 核对分支结果

访谈与模型任务沿业务分析方法选择路线：业务逻辑从经营与权责进入，领域逻辑从对象与规则进入，工具／胶水按适用性判断；混合问题分开分析。单据推演、参与者与角色扮演、变化点均按当前事实依赖展开，不强迫每轮重走所有阶段。

只检查执行者的交付是否齐备，不重做其方法：

- 访谈：可读视图及来源已展示；原话与术语分别保存并报告结果；未执行的推演不声称通过。任一保存失败就停止，恢复先核对实际文件。
- 模型编辑：定义拥有者和稳定引用已核对；独立术语落实后保留 term ID，将条目替换为 FM 引用；目录、命名与结构以当前 FM Schema 为准。实际增改删、校验及缺口均可定位。
- 只读校验：没有项目写入；没有实际场景执行时 `simulationPassed` 为 null。
- 审核页：明确输入版本与生成结果，页面不是状态源或业务批准。

## 4. 交接并停止

按文件交接协议列出本次结果、各文件保存情况、实际检查与未决项。界面只收集回答，不保存业务记录；不可用时转普通对话，不伪造回答。

保存、机器检查、业务批准分别说明。失败保留真实错误和已改文件，不自动回滚。完成当前分支后停止，不自动启动下游 API、需求、架构、开发或 Git 操作；模型返回缺口也不自动解除访谈停止状态。
