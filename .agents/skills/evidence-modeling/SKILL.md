# Evidence 建模编排

只选择分支、传递授权与核对交付，不重复专业分析，不建立私有业务状态。本入口不依赖界面扩展：显式使用宿主原生 Skill 入口，或请求 Agent 读取本文件，都可执行全部分支；可选菜单只是同一目标的输入包装。

## Guides

首次进入或恢复时读取项目指令、本次目标、实际文件和 Git 差异；默认产物根为 `.evidence/`。只修改本次授权的文件，保留无关改动，不自动迁移。连续问答沿已选分支交给 Discovery 增量承接，不重新分派、不重做专业分析；授权或目标变化时重新判断分支。恢复、产物归属和阶段接续按 [文件交接](references/workflow.md)。

通过宿主资源发现或用户提供的路径定位所需 Skill 并读取其 SKILL.md，不假设相邻安装。组合执行是按其指令工作，无需专门的 Skill 调用工具。仅加载本分支所需依赖；已加载且未变化、仍在上下文的方法直接复用，必要内容丢失或变化时再读取。完整生成在修改 FM 前确认 FM 与 Visualization 两个专业包及运行依赖可用。

| 用户意图                             | 执行者                                              | 本轮结果与写入范围                                 |
| ------------------------------------ | --------------------------------------------------- | -------------------------------------------------- |
| 讨论方法、只聊不落盘                 | `evidence-fm` 的讨论分支                            | 解释与展示，不写文件、不开始访谈                   |
| 访谈、查看／切换合同上下文、继续澄清 | `evidence-discovery`，消费 FM 方法                  | 来源记录及当轮词汇表；一次必要问题后等待           |
| 生成或修改模型                       | `evidence-fm`（FM → API）→ `evidence-visualization` | 准入后依次更新两源及派生产物，生成联合审核页       |
| 只校验                               | FM 包内的模型与已有 API 检查分支                    | 只读报告，不写源、报告或页面；明确仅 FM 时不查 API |
| 生成联合审核页                       | Visualization，要求 FM 与 API                       | 只更新页面，缺 API 不降级                          |
| 停止、暂缓、仅补资料                 | Discovery 控制分支                                  | 按更窄授权保存后停止，不继续提问                   |

生成／修改默认一次触发完整链路；“只修改 FM”“不要设计 API”“不生成审核页”等限制裁剪授权。FM 的正式生成默认包含 API，但明确仅 FM 优先；其他独立专业 Skill 的调用不扩大权限。访谈回答、人类追责结束确认或只读请求本身不授权模型 JSON 生成。首次分派或交接受阻时，从 [分派与交接基线](examples/README.md) 只加载权限对照或交接样例；普通续问仍由 Discovery 承接，不重读入口样例。

## Action

按文件交接的分派图传递本轮目标、允许文件、来源定位和停止条件，由专业拥有者执行。正式生成依次消费准入依据、FM 检查、API 交付与联合审核；API 阶段消费同一 FM 结果，不重复 FM 检查，更窄授权到对应终点即交接。不再索取已获授权的重复触发，不以局部切片放行，也不自动改为访谈。

只读分支不执行任何投影写入；单独联合审核只写页面，不重写两源或正式 API generated。分支和阶段边界固定，专业表达由拥有者决定；流程、检查点与交接格式只在 workflow 维护，本入口不维护分析步骤或词汇定义。

## Sensors

- 访谈：来源和词汇分别有保存结果，焦点及未决引用可恢复；不把保存成功当作建模准入。
- 正式生成：核对 FM 实际差异与当前检查、API 整体覆盖与契约结果、最终 HTML 浏览器检查，不能用某一阶段成功代替整条链路完成。
- 只校验：核对没有项目写入；两源分别报告，API 缺失说明联合检查未完成。
- 联合审核：核对两源新鲜度、严格联合模式和页面验证；旧页面不是当前有效证据。

专业检查结果须带实际命令、输入版本和未验证限制；保存、机器检查、人类追责结束与业务批准分别说明。

## Steer

- 专业 Skill 或必要运行依赖缺失：在受影响写入前停止，不转成业务提问。可选界面缺失不阻塞分支，普通对话仍可完整运行。
- 业务依据不足或确认失效：停止并交接缺口；模型任务不自动解除访谈停止状态。
- 校验或保存失败：保留真实错误、已改文件和未完成阶段，不自动回滚；只在当前专业任务授权内修正。
- 交付：列当前分支、文件引用、实际保存与检查结果、未决影响后停止。不自动批准，不启动需求、规划、实施或 Git 操作。界面只收集交互，不保存业务记录；不可用时转普通对话。
