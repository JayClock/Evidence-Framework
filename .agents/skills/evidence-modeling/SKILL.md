# Evidence 建模编排

只选择分支、传递授权、核对交付，不重做专业分析或维护私有业务状态。通过宿主原生 Skill 入口或显式读取本文件执行完整流程，访谈使用普通对话。

## Guides

首次进入或恢复时读取项目指令、当前目标、实际文件与 Git 差异。默认产物根为 `.evidence/`，只修改本次授权的文件，保留无关改动，不自动迁移。分派、恢复与阶段接续统一按 [文件交接](references/workflow.md)。

| 用户意图                         | 执行者                                                    | 本轮结果与写入范围                                                                                       |
| -------------------------------- | --------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| 讨论方法、只聊不落盘             | FM 或 API 的讨论分支                                      | 解释与展示，不写文件、不开始访谈                                                                         |
| 访谈、查看／切换上下文、继续澄清 | `evidence-discovery`，消费 FM 方法                        | 从约定与双方进入履约、合同一方负责、每轮主动成组澄清、直接翻译及当轮词汇表；分支结束后接续建模与 Handoff |
| 生成或修改模型                   | `evidence-fm` → `evidence-api` → `evidence-visualization` | 准入后 FM → 整体 API → 联合审核                                                                          |
| 只校验                           | FM 与 API 各自的只读检查分支                              | 只读报告；明确仅 FM 时不查 API                                                                           |
| 生成联合审核页                   | Visualization，要求 FM 与 API                             | 只更新页面，缺 API 不降级                                                                                |
| 停止、暂缓、仅补资料             | Discovery 控制分支                                        | 按更窄授权处理后停止                                                                                     |
| 显式记录建模过程或会话交接       | `evidence-handoff`                                        | 保存 Markdown 交接，返回实际路径                                                                         |

生成／修改默认一次触发完整链路；“只修改 FM”“不要设计 API”“不生成审核页”等限制裁剪授权。本入口建模访谈默认包含按分支生成与 Handoff：合同或独立领域／协商完整澄清并经人类确认后，按交接协议核对对应准入并调用正式建模，随后保存全部未澄清上下文及关联。合同级责任门槛保持不变；相关未澄清合同使用 Context Role，领域及协商依真实语义表达，不一律套用合同角色。普通访谈回答或只读请求本身不授权模型 JSON 生成；只聊不落盘、仅访谈、不生成或不记录等明确限制优先。首次分派或交接受阻时，只读 [对应基线样例](examples/README.md)。

## Action

1. **选择执行者。** 根据当前目标与最窄授权选择分支，通过资源发现或指定路径定位专业 Skill 并读取其入口，无需专门的 Skill 调用工具。连续问答交由已选 Discovery 分支增量承接，目标或授权改变、有效合同／领域／协商分支结束信号到达时才接续分派。完成时，执行者、输入、允许文件与停止条件明确。
2. **执行获授权链路。** 按文件交接委派专业拥有者；完整生成在写入前确认 FM、API、Visualization 及运行依赖可用。FM 先核对人类追责结束准入，再编辑与检查，API 消费同一有效结果，不重复 FM 检查；通过后才接续联合审核。更窄授权到对应出口即交接；合同或领域／协商分支接续成功或阻塞后仍调用 `evidence-handoff` 保存未澄清部分及实际结果，明确禁止保存时除外。完成时，本分支所需结果已取得，或阻塞点及部分保存清楚。
3. **核对交付。** 按交接协议检查实际文件、输入版本、命令结果和未执行限制，专业检查仍由其拥有者完成。完成时，能区分各阶段成功、完整交付与未决工作，并报告后停止。

## Sensors

- **访谈**：实际约定与责任双方、增量发现的协作及按需导航准确；各请求与确认的责任人是所属合同的一方；每轮主动寻找并一起提出全部可同时澄清的独立内容，局部依赖不造成整轮串行；规范名称复用已有映射或按明确含义直接翻译英文。各关键数据的来源、回溯位置、原问题、未决依赖、控制意图和术语实际保存结果准确；人类准入依据单独核对。
- **正式生成**：FM 差异与有效检查、API 整体覆盖与契约、最终 HTML 浏览器检查齐备；某一阶段成功不代表整条链路完成。
- **只校验**：核对无项目写入，两源分别报告；API 缺失时联合检查未完成。
- **联合审核**：当前两源、严格联合模式及页面验证可定位；旧页面不是当前有效证据。

合同级结束、领域／协商分支结束、全局追责结束、保存、机器检查与业务批准分别说明；自动 Handoff 的实际路径与未保存内容可定位。

## Steer

- **必要资源缺失**：在受影响写入前停止，交接具体限制，不自动安装或扩大授权。
- **业务依据不足或确认失效**：交接拥有者与缺口后停止，模型任务不自动解除访谈停止状态。
- **检查或保存失败**：保留真实错误与已改文件，按原专业授权修正；分别报告未完成阶段，不自动回滚。
- **完成**：列出分支、文件、实际保存与检查、未决影响后停止。不自动批准，不启动需求、规划、实施或 Git 操作。界面只收集交互，业务保存归专业 Skill。
