# Skills 测试与维护

`.agents/skills/` 是方法、运行资源及各自测试／评测的唯一维护源。按被测职责维护，不保留集中副本。本目录检查组合入口、跨 Skill 包契约、文档协作和纯 Skill 路径；需要完整仓库，不是独立专业包的运行依赖。

## 当前覆盖与拥有者

| ----------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| Modeling 的 `evals/`                                                                            | 显式入口委派、权限传递、准入阻塞、阶段接续、部分交付与路由近似请求                       |
| Discovery 的 `evals/`                                                                           | 当前节点访谈、合同导航、领域语言、依赖前沿、控制意图及恢复                               |
| FM 的 `evals/`                                                                                  | 正式表达、生成／阻塞／不适用结果、准入与日常领域语言                                     |
| API 的 `evals/`                                                                                 | 整体 API 设计、只读、HTTP 契约覆盖与投影失败边界                                         |
| Requirements 的 `evals/`                                                                        | 从充分材料直接收敛软件职责、故事与验收，不强制 FM                                        |
| Handoff 的 `evals/`                                                                             | 显式 Markdown 交接、确认覆盖、未决与控制意图、保存失败                                   |

| FM／API 的 `tests/`                                                                             | 引擎、Schema、CEL、lineage、模拟、API与评分器的程序回归                                  |

| Planning／Delivery 的 `tests/`                                                                  | 编译与投影、状态、依赖、文件绑定和只读任务选择                                           |

[目录回归](test_eval_catalogs.py)扫描所有 Evidence 评测文件，检查 `contract_refs` 所引当前包内契约、实际 Skill、输入夹具、FM 结果类别与 ID 唯一性。`files` 默认相对 evals 目录；`files_base: ".."` 表示相对 Skill 根。题面和预期只在改变目标契约后相应修订，资源可达不证明语义正确。

案例身份是“评测文件路径 + ID”，不同评测文件不要求全局连续或唯一。保留有效案例的 ID，删除不补号、不复用旧 ID；当前分支和反例覆盖由专属测试检查，不锁定历史数量或编号全集。编排层只评估委派和交接，专业规则由专业包唯一维护。

成组提问按连续主线验证部分回答、依赖更正、逐问偏好与停止，不为每条规则或不同业务名称保留独立题。专属测试核对合并后的逐轮输入与风险预期，而非要求旧类别继续存在；写入失败、跨合同依赖阻塞、循环／版本和结束准入等独立反例仍各自验证。提问案例去重不删除正常与争议业务推演。

## 方法与维护材料的边界

业务入口只加载当前分支所需的方法、模板、Schema和脚本。tests／evals 仅在维护或明确评测时使用，不把合成输入当项目事实。

Discovery 维护普通对话、当前节点、问题组、控制意图及当轮模型语言核对；跨会话承接提供的理解与材料。显式要求记录过程时使用 Handoff，不维护自动访谈快照或第二份问题记录。FM 维护专业判断与正式表达；正式编辑先核对完整范围的人类追责结束依据。独立 API 维护技术契约与投影，复用 FM 的有效检查。Modeling 分派这些拥有者，完整生成依次取得 FM、API和联合审核，不替专业包执行第二套规则。

## 自动验证

使用满足相关 requirements.txt 的 Python 3.10+ 环境，在仓库根执行：

```bash
npm run skills:verify
# 使用实际 Python 解释器运行相同聚合入口
python3 .agents/skills/evidence-modeling/tests/run_skill_tests.py
# 只运行组合及跨包契约
python3 -B -m unittest discover -s .agents/skills/evidence-modeling/tests -v
```

聚合入口发现各包的 `tests/`及`tests/portability/`，逐套件用独立子进程隔离同名模块，任何失败返回非零。安装测试子目录不设`__init__.py`，由聚合入口显式运行，不能漏跑。

FM评分器回归分别检查正向模型和阻塞结果；合法合同前结构的验证与允许正式编辑分别测试。阻塞案例必须拒绝有效模型、零散规则、场景和编译产物，不能因没有审核状态而放行。模型案例的合成准入来源须与题面一致，不覆盖实际遗漏。

独立安装检查复制完整包到无仓库依赖的含空格路径，运行包内测试、输入准备及真实检查；移除tests／evals后再次核对运行能力，确保维护材料不是运行依赖。源文件前后摘要用于检查输入不变性。

## 真实行为评测与证据

读取[组合入口评测](../evals/README.md)，专业案例按各安装包的evals／README操作。使用隔离项目与独立会话，同一模型、宿主、权限、来源和工具环境比较新旧版本；不共享答案，不读取真实项目的业务源。

真人提供后续输入，环境实际设置写入拒绝、外部变化等条件，待评Agent不自答、不伪造错误。保存原始轨迹、文件差异、真实命令及逐项判定；人类准入、编辑授权、机器校验和业务批准分别核对。

逐项expectations或assertions报告通过／失败／未评，引用具体证据。程序回归、文档结构和评分器测试不证明Agent访谈、生成、路由或执行质量。没有实际运行就保持未执行，不填写行为通过率、token收益或人工批准。历史失败日志和业务证据不在案例清理中删除。
