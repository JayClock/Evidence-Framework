# 合同导航：选择不等于业务确认

以下都是合成样例。合同识别仍使用 FM 方法，列表只投影实际依据充分的约定。

## 1. 首次总览与选择分两轮

### 输入

材料明确买卖双方按采购协议付款、交货；货主与承运方按运输协议付运费、送达。运输的有效签收证明尚未明确。用户要求保存并先选择分析焦点。

### 记录增量

先保存材料原话，再维护采购 A-1、运输 A-2 及各自全部主履约；费率或证明参数缺口归原对象，不阻止已有依据充分的合同识别。按授权维护明确术语。总览轮不创建业务 Q-ID，不提前挑一个履约问题。

### 期望展示

```text
1. 采购协议：买方与卖方，付款与商品交付；尚待逐项追溯，未结束。
2. 运输协议：货主与承运方，运费与送达；有效签收证明待追溯，未结束。

先分析哪个合同上下文？
```

用户随后选择“运输协议”时，核对目标仍可选，先保存选择原话，再更新 focusRef。承接已知双方、运费和送达义务，定位送达确认；如果有效签收证明仍未知，下一轮只追溯这一依据，不重新询问交易怎样成立。原采购责任与暂缓题仍保留。

### 反例与检查

- 展示“运输候选，请确认合同是否存在”：把材料识别推回用户。
- 在选择轮追加“签收由谁提供”：混合导航与业务问题。
- 因选择运输删除采购：把焦点选择当成范围排除。
- 因费率未知不展示合同：混淆参数缺口与识别依据不足。

检查选择只决定分析焦点；不确认边界，不排除责任，不形成追责结束或生成授权。

## 2. 已结束项、只读查看与取消

### 输入

采购 A-1 有人类合同澄清结束原话及覆盖版本，责任与未决项已核对；运输 A-2 仍未结束，当前问题 Q-002 待答。用户只读查看总览。

### 期望行为

仍展示 A-1，但明确不可选择；A-2 可供分析。用户说“切到采购”时说明该项已结束，保持原焦点与 Q-002，不提供重新开启入口。用户取消则等待，不自动选 A-2。只读查看不保存选择或改变状态。

### 反例与检查

- 因列在菜单中就允许切换：忽略业务结束依据。
- 取消后默认选第一项：伪造用户选择。
- 查看总览后恢复已停止问答：把导航当成恢复授权。

没有充分识别依据时不造合同菜单；全部已结束时只展示并返回。合同澄清结束不是全局全部追责结束。来源更正导致结束依据失效时交接冲突，不借导航重新开启。
