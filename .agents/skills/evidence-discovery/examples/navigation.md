# 上下文导航：选择焦点，不确认或排除责任

以下为合成样例，不是当前项目事实或已执行评测；双语名称均为题设。分类、切换与结束规则由 [访谈协议](../references/interview.md) 维护。

## 1. 先识别混合上下文，再单独等待选择

材料明确：读者与内容平台按订阅协议付费换取内容访问，退费条件待澄清；已采用成熟账号方案，提供稳定账号标识及停用结果，内部实现不在范围；企业客户先取得报价，接受后才形成订阅约定。账号停用是否影响已付费权益未知。用户要求先看整体，只聊、不生成。

```text
1. 订阅协议（Subscription Agreement）〔合同〕
   读者（Reader）与内容平台（Content Platform）签订订阅协议（Subscription Agreement），以付费换取约定内容访问。
   现金权责：观察主体为内容平台（Content Platform），收入对应内容提供责任。
   责任边界：付款与内容提供，包含相关退费责任；尚未结束。
2. 账号管理（Account Management）〔领域〕
   复用既有账号（Account）能力，为订阅中的身份判断提供稳定标识及适用结果。
   内部实现不在本轮范围；与付费权益相关的责任仍归订阅协议（Subscription Agreement）；尚未结束。
3. 企业订阅协商（Enterprise Subscription Negotiation）〔协商〕
   企业客户（Enterprise Customer）与内容平台（Content Platform）就报价及接受协商，形成订阅约定。
   边界为合同前的方案与回应；尚未结束。

先分析哪个上下文？
```

经营依据与边界在展示前核对，不让用户选择代替分类验证。费率未知与经营依据不足不同；后者不包装为可选合同。总览不展示资料出处、待追溯栏或内部检查过程，未决责任仍参与判断。

只看合同总览时展示其中合同项，现金方向仍注明观察主体，目标与实际主线不虚构收费。导航轮只问选择，不同时问退款或账号规则。

## 2. 选后按类型承接

用户选择账号管理（Account Management），限定仅访谈、不生成，并暂缓订阅退费问题。承接成熟方案与已知能力，定位“账号管理（Account Management）→ 账号（Account）”，只澄清身份匹配及适用结果的业务连接点，不重问选型或设计登录、安全、存储。

不因划入领域而删除合同责任：停用与付费权益的关联仍保留；影响当前判断时必须澄清，不以“领域没有合同”放行。领域对象不强套履约凭证格式，也不虚构凭证责任人。

用户改选企业订阅协商（Enterprise Subscription Negotiation）时，承接已知报价与回应，只追尚缺依据，不补造 RFP 或履约请求。选择合同则承接已知双方和全部主履约，定位一个请求或确认；不重新问合同是否存在。切换不恢复其他暂缓题。

## 3. 查看、取消与结束分别承接

若订阅协议（Subscription Agreement）已有覆盖当前责任、未决项与版本的人类澄清结束确认，它仍供查看，但不可直接选择重开。用户取消选择时保持原焦点与问题等待，不自动选择第一项；只读查看总览不解除停止状态。同名选择不能定位时，只澄清目标。

本例领域的复用连接范围、适用条件及关联责任查清，正常、边界和反例已实际核对后，下一轮单独展示结果，等待人类确认该范围澄清结束且没有适用履约责任、无需继续追责。未展开且不影响当前判断的内部机制不当作缺口；影响当前范围的付费责任未知仍阻塞确认。

“今天到这里”只是停止，不是分支结束。有效分支结束且来自获授权建模入口时才交回 Modeling；本例仅访谈、不生成的限制仍生效，不写 FM/API 或自动保存交接，不开始下一个上下文。材料更正影响结束依据时说明失效范围并等待处理。
