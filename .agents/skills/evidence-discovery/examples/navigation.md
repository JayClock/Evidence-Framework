# 上下文导航：直接承接与按需选择

以下为合成样例，双语名称为题设，不是项目业务事实或已执行评测。交互规则由 [访谈协议](../references/interview.md) 维护。

## 1. 单一清晰入口直接进入

委托方（Client）与设计方（Designer）已达成设计约定（Design Agreement）：委托方付款，设计方交付图稿；设计助理（Design Assistant）代表设计方办理交付。用户要求先分析交付，仅访谈、不生成。

直接进入设计约定（Design Agreement），承接双方与已知付款、图稿交付责任，定位当前交付请求或确认。设计助理（Design Assistant）是经办人，不替换设计方（Designer）的合同责任。只有完成证明未知时才追该证明，不先询问收费、KPI、其他合同或让用户选上下文。

主要履约用于验证约定理解，分析中新增的条件义务继续补入；当前已知清单不表示完整责任已查清。

## 2. 从凭证发现关联约定

交付判断引用印刷交付证明（Print Delivery Proof）。用户补充，委托方（Client）另与印刷方（Printer）达成印刷约定（Print Agreement），由印刷方交付成品。增量补入该约定及凭证关联，不自动切换到印刷合同，也不展开印刷方全部内部责任。

继续分析图稿交付时，只核对印刷交付证明（Print Delivery Proof）对当前判断的证明含义、责任与匹配条件。若只有一个印刷系统名称而没有上述约定，不据此制造印刷合同。

## 3. 用户要求总览时单独导航

当前还已知图稿库（Artwork Library）的对象身份和版本规则，以及报价未接受的设计协商（Design Negotiation）。用户要求看整体并选择下一步，只聊、不生成。

```text
1. 设计约定（Design Agreement）〔合同〕
   委托方（Client）与设计方（Designer）达成设计约定（Design Agreement），由委托方付款、设计方交付图稿。
   责任边界：付款与图稿交付，包含该约定下的条件义务及异常责任；尚未结束。
   与图稿库（Artwork Library）及印刷交付证明（Print Delivery Proof）关联。
2. 印刷约定（Print Agreement）〔合同〕
   委托方（Client）与印刷方（Printer）达成印刷约定（Print Agreement），由印刷方按约定交付成品。
   责任边界：双方的印刷约定；与设计交付判断关联，尚未结束。
3. 图稿库（Artwork Library）〔领域〕
   提供图稿（Artwork）的身份和版本规则，支撑设计与印刷中的标的匹配；尚未结束。
4. 设计协商（Design Negotiation）〔协商〕
   委托方（Client）与设计方（Designer）就新方案报价及回应协商，尚未形成该方案的设计约定；尚未结束。

先分析哪个上下文？
```

总览只是当前理解，不表示所有合同已经找到。导航只收集选择，不同时问交付证明或报价条件；不展示出处、内部检查过程或缺口字段表。

## 4. 选择、取消与结束分别承接

选择图稿库（Artwork Library）时，从当前对象身份或版本规则进入，不因划入领域而删除合同责任，不让领域能力替合同决定完成条件。选择设计协商（Design Negotiation）时承接方案与回应，不补造 RFP 或履约。

用户取消时保留原焦点和原问题，等待输入；仅查看不解除停止或暂缓。选择另一个合同只改变焦点，不恢复其他暂缓题。

已有当前版本人类结束确认的合同仍供查看，但不可直接选择重开。领域／协商结束按实际范围单独确认，不能替关联合同结束；“今天到这里”只是停止。有效结束且有生成权限时才交回 Modeling，本例仅访谈、不生成的限制继续生效，不自动写 FM/API 或保存交接。
