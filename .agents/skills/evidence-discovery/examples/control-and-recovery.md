# 控制与恢复：吸收事实，按实际权限交接

以下为合成样例，不是项目业务事实。完整规则见 [访谈协议](../references/interview.md)。共同理解与正式模型保存分开，不在访谈中创建定义文件。

## 1. 已知回答与停止意图同时到达

当前为订阅协议（Subscription Agreement）的退款（Refund）履约，退款申请（Refund Application）由读者（Reader）负责，实际主体未知。Q-010 追溯应退金额（Refund Amount），原支付凭证（Payment Evidence）已证明实付金额（Paid Amount）。用户回答：“适用约定按本笔实付全额退还，只补充理解并停止。”

直接复用约定解释金额，不再询问金额实例；核对相关模型定义及待改影响，不把回答当成模型编辑授权：

```text
当前位置：订阅协议（Subscription Agreement）→ 退款（Refund）→ 退款申请（Refund Application）〔履约请求〕
责任人：读者（Reader）；实际主体待明确。

应退金额（Refund Amount）的依据已追到适用约定：按本笔实付金额（Paid Amount）全额退还。支付凭证（Payment Evidence）说明实付，约定说明为什么应退同一金额；这不表示退款（Refund）已完成。

本轮仅更新共同理解，没有修改模型。按要求停止；其他未决责任保留。
```

这里只说明合成情境中已明确的名称与责任，实际输入未给时不补造。

## 2. 更正模型定义不扩大编辑权限

FM 的收稿回执（Manuscript Receipt）Entity 当前被解释为验收通过，用户更正为“只证明收到，不证明质量合格”，明确不改模型 JSON。定位定义拥有者，说明收到与合格的差异及依赖判断、结束确认的失效影响；不另存一份已建模定义，不修改 FM/API。后续修改仍需编辑权限；有来源的更正可渐进保存，受影响范围结束确认与下游结果另行核对。

## 3. 跨会话保留控制，不默认恢复

承接 [凭证追溯案例](tracing.md) 的停止位置：第二版外观标准（Appearance Standard）的 Q3 暂缓，今天全部停止。用户再补验收影像（Acceptance Footage）并要求“仅补资料”：吸收其证明作用及边界，保留 Q3 原标识与停止意图，不继续问。

新会话仅查看仍不提问；明确允许继续实际状态的证明后，读取必要方法、实际文件、依据与控制状态，保留外部新增内容，只追获准来源，不恢复 Q3。取消时保留焦点及未答项等待，不默认同意。停止不是追责结束，相应结束确认仍独立一轮。

## 4. 未包裹交互从原凭证恢复

合成服务约定中，委托方（Commissioning Party）已提出整理要求（Organization Request），确认方式尚未明确。继续时定位 `服务约定（Service Agreement）→ 整理要求（Organization Request）〔履约请求〕`，说明责任人为委托方；整理要求（Organization Request）直接关联服务约定（Service Agreement），该合同依据不会因尚未配对而缺失。没有履约对象或 ID 不阻碍澄清另一端。只有一端时不先建空履约，也不把要求引用的目录等支撑凭证当作结果。

目录来源先得到说明，结果问题仍暂缓时，承接目录依据并保留返回位置。明确恢复结果问题后，只继续确认服务方怎样形成相应结果；配对及责任明确后，才在实际授权内交 FM 包裹。原问答和已有交接足以接续，不另建候选履约实体、责任模型或问题台账。
