# 访谈行为评测

[evals.json](evals.json) 检验逐问澄清、当轮领域语言沉淀、来源与控制状态。明确术语进入唯一词汇表，未决解释留在发现记录；不要求生成模型 JSON。

## 环境与分组

- 案例 1、3、6：检查一般事实澄清、引用、更正与控制状态；可提供 FM 方法检查术语写入，未提供时明确待沉淀项。
- 案例 2、10–14：knowledgeSkills 指定 evidence-fm，由操作者提供实际安装路径；按领域语言方法增量维护词汇表，不执行模型 JSON 生成入口。检查深度来自准则，交互来自访谈。
- 案例 8：只提供本 Skill，明确不提供 FM；一般访谈仍可进行，术语待沉淀及专业判断限制须明示。
- 案例 11：在临时项目准备题述旧词汇表和模型，记录初始内容摘要；验证只更新术语、更正来源及冲突定位。
- 案例 13：由测试环境实际拒绝词汇表写入，再恢复权限；不能让待评 Agent 假装保存失败。

使用新的临时项目和会话，以同一模型、同一业务输入比较有／无访谈 Skill 或独立新旧版本。组合案例两组使用相同的 FM 知识版本与可用性，只改变访谈机制；记录知识来源，不能把增加知识包带来的收益误算为访谈改进。

## 执行与判定

由真人提供回答，多轮案例依次执行 follow_up；恢复只交接实际保存文件，不转发旧对话，也不让待评 Agent 生成自己的用户答案。

保存原始对话、文件变化与所读资源的定位，逐项记录 expectations 的原文依据及通过／失败／未评结论。重点核对先复用后提问、一次一个核心问题、停止／暂缓防重、唯一依据保留，以及是否当轮更新已明确术语、保留未决定义、遵守更窄授权，以及是否误生成模型 JSON 或验证套件。失败恢复检查发现记录与词汇表分别保存的真实结果，不用文档存在替代写入顺序证据。

静态检查只能验证资源边界和文档结构，不能证明一般访谈质量或专业判断完整。输出留在独立工作目录，不写回 Skill 或真实业务材料；没有实际执行就保持未执行，不填写通过率、token 收益或跨 Agent 行为保证。
