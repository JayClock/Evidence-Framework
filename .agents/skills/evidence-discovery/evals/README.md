# 访谈行为评测

[evals.json](evals.json) 保留案例 1、2、3、6，并增加案例 8。它们检验访谈而非正式产物；工作理解不等于模型，未产出正式模型不算失败。

## 环境与分组

- 案例 1、3、6：只安装本 Skill，检查一般事实澄清、引用、更正与控制状态。
- 案例 2：knowledgeSkills 指定 evidence-fm，由操作者提供实际安装路径；只把对应专业参考作为可读知识，不执行其生成入口。检查深度来自准则，交互来自访谈。
- 案例 8：只提供本 Skill，明确不提供 FM；检查一般访谈仍可进行，专业判断不足时说明限制，而非复制知识或猜字段。

使用新的临时项目和会话，以同一模型、同一业务输入比较有／无访谈 Skill 或独立新旧版本。组合案例两组使用相同的 FM 知识版本与可用性，只改变访谈机制；记录知识来源，不能把增加知识包带来的收益误算为访谈改进。

## 执行与判定

由真人提供回答，多轮案例依次执行 follow_up；恢复只交接实际保存文件，不转发旧对话，也不让待评 Agent 生成自己的用户答案。

保存原始对话、文件变化与所读资源的定位，逐项记录 expectations 的原文依据及通过／失败／未评结论。重点核对先复用后提问、一次一个核心问题、停止／暂缓防重、唯一依据保留，以及是否误生成正式词汇表、模型或验证套件。

静态检查只能验证资源边界和文档结构，不能证明一般访谈质量或专业判断完整。输出留在独立工作目录，不写回 Skill 或真实业务材料；没有实际执行就保持未执行，不填写通过率、token 收益或跨 Agent 行为保证。
