# 访谈行为评测

[evals.json](evals.json) 检验经营依据与合同边界识别，以及合同约定、全部主履约、请求—确认骨架、凭证追溯和异常新义务如何引导逐问澄清，以及单据推演、参与者与角色扮演、变化点与边界。检查全局责任图、逐枝递归、人类终点与全部追责结束依据，以及可读业务视图和当轮术语沉淀，不以问题数量或词汇条目数量代替业务理解；不要求生成模型 JSON。

## 环境与分组

- 案例 1、3、6：检查一般事实澄清、引用、更正与控制状态；可提供 FM 方法检查术语写入，未提供时明确待沉淀项。
- 案例 2、10–14：knowledgeSkills 指定 evidence-fm，由操作者提供实际安装路径；按领域语言方法增量维护词汇表，不执行模型 JSON 生成入口。检查深度来自准则，交互来自访谈。
- 案例 8：只提供本 Skill，明确不提供 FM；一般访谈仍可进行，术语待沉淀及专业判断限制须明示。
- 案例 11：在临时项目准备题述 model 引用条目和 FM 目标，记录初始摘要；验证只保存更正来源与待改影响，不在词汇表覆盖已有 FM 定义。
- 案例 15 至 20：提供 FM 方法，分别检查材料优先、凭证逆推、关键值追溯、单据争议推演、实际变化与支撑边界、纯领域分支。临时来源严格按 prompt 准备，不补造缺失的合同或答案。
- 案例 21 至 23：提供 FM 方法，检查已知同一主体跨上下文复用、同名但身份未决、代表办理与责任主体的区分。恢复时只交接发现记录，核对 `business.participants` 的对应关系和来源，不以生成正式模型作为访谈成功条件。
- 案例 13：由测试环境实际拒绝词汇表写入，再恢复权限；不能让待评 Agent 假装保存失败。
- 案例 24 至 28：提供 FM 方法，检查异常新义务继续递归、停止不是追责结束、单条终点不是全局确认、新分支使旧确认失效，以及全部依据一致后保存人类全局原话。准备实际责任图与来源，不能只设置一个完成标记或让 Agent 伪造人类答案。
- 案例 30 至 34：检查合同初始参数与实际结果分离、先骨架后凭证追溯、异常复用同一循环、多约定的引用恢复及记录版本边界。案例 33 按题面在当前模板中准备采购与运输记录、实际暂缓问题和稳定来源，跨会话只交接文件；案例 34 在隔离目录准备题述旧版本原文与摘要，验证未获转换授权时文件不变。其他案例同样使用当前记录结构，不自动转换真实业务材料。
- 案例 35 至 40：提供 FM 方法，检查匿名交易平台现金权责、无现金绩效、只有协议名时的边界缺口、现金合同内的非收费义务、未知费率及托管款不等于平台收入。案例均只聊、不落盘，不提出问题或生成模型；新旧版本比较使用同一匿名材料，不向待评 Agent 提供 expectations。
- 案例 41 至 44：检查当前进度展示、多合同但只聚焦一个请求／确认、端点切换与文件恢复、非履约定位和异常新义务。保存记录仍覆盖全部责任及暂缓问题，但普通问答只显示业务位置、当前信息来源的追溯故事和一个必要问题，不附方法文章信息、文件来源列表、全局进度或准入提醒。有 UI 时同时核对选择页和回答编辑器保留相同位置，无 UI 时核对同样的文本结构。

- 案例 45 至 47：检查首次合同总览、导航选择与单点澄清分层、已结束合同禁止切换（含自然语言）、取消及无 UI 同名选择。在临时目录准备实际发现记录和人类结束依据，不能只设置布尔完成标记；另用未识别到合同和全部已结束输入重复导航，检查不造合同、不自动生成。自动 UI 测试不替代这些 Agent 行为评测。

- 案例 48：检查业务命名、请求本身是凭证、关键数据来源故事、不虚构未知规则及停止后不凑题。UI 自动测试仅验证字符串展示和契约；故事的事实忠实性、一问纪律及跨会话恢复须由真实 Agent 运行核对。

案例的 `files` 相对本 evals 目录解析，由操作者将实际内容随 prompt 提供，不依赖真实仓库路径。案例 35 使用[匿名协议脱敏节选](fixtures/anonymized-marketplace-agreement.md)：去掉品牌、法人全称、网址、联系方式、地址、版本日期及运营迁移安排，只保留判断所需的条款并泛化商品类别。这不是完整协议，不能用于真实建模或替代业务批准；不得恢复原始标识、补齐未提供规则，或把期望答案放入来源材料。

使用新的临时项目和会话，以同一模型、同一业务输入比较有／无访谈 Skill 或独立新旧版本。组合案例两组使用相同的 FM 知识版本与可用性，只改变访谈机制；记录知识来源，不能把增加知识包带来的收益误算为访谈改进。案例 35 至 40 若比较本次识别方法重构，应显式标明 FM 与 Discovery 方法版本共同变化，结论只针对识别方法组合，不宣称是访谈机制单独带来的收益。

## 独立对话与可选界面一致性

案例 49 至 52 使用相同 Skill 与 FM 方法版本，在隔离项目中准备实际来源、焦点和问题，不写真实业务材料：

- 49：不注册任何 UI 工具，不复制宿主适配目录，仅安装 Skill 及其专业依赖，验证从首次总览到逐问、停止、跨会话恢复的完整对话路径。
- 50：同一初始文件、同一模型与真人回答分别运行纯文本和可选界面两组。界面工具及映射由宿主测试环境提供，不由 Skill 引用或安装。比较来源原文、业务结论、原问题状态、焦点、权限与保存顺序，不要求展示格式、时间戳或来源载体逐字一致。
- 51：实际使界面不可用后改用普通对话，再以已明确取消的输入重跑。区分技术不可用与用户取消；另在回答已返回后撤去界面，检查先保存而不重问。
- 52：测试环境真实拒绝词汇表写入，保留已返回回答；恢复权限后仅补保存。不能由待评 Agent 假装故障或将展示切换视为保存成功。

这些是待执行的 Agent 行为案例，文档契约与适配器单元测试不证明语义一致；没有实际执行就保持未执行。

## 材料直接识别与选择承接

案例 53 至 55 检查本轮流程重构：材料充分时直接展示合同、费率未知不阻塞识别、功能线索不混入列表，选择后承接主履约而非重问交易成立；材料不足时不造候选菜单；恢复旧记录时按来源筛选且不擅自迁移。案例 55 在隔离目录按题述准备实际来源和 2.0 记录，保存初始摘要以核对只读不变性。案例 39、45、49 同步覆盖参数缺口和导航后的履约承接。

新旧比较同时固定模型与业务输入，标明 FM、Discovery 和可选 UI 的版本。静态契约及 UI 测试不证明 Agent 能判断依据充分；未进行独立会话与真人多轮执行时，不报告行为通过率。

## 增量读取与事件核对

案例 56–63 验证读取节奏，不以少读文件替代业务正确性。按当前模板在独立临时项目准备采购 A-1、运输 A-2、采购暂缓题 Q-001、送达确认 R-2／Q-002 及实际来源；不修改真实 `.evidence/`，不向待评 Agent 提供 expectations。先保留初始文件摘要：

- 56：新会话只提供文件，检查必要方法与焦点恢复，不重复总览。
- 57：在同一会话先定位问题，再由真人给出 follow_up；方法与文件除本轮授权写入外不变。保留必要的采信依据缺口及已有词汇，检查增量读取、去重和焦点外事实保存。
- 58：准备双方和主履约均有来源、尚未结束的目标合同，检查切换范围而非全库扫描。
- 59：准备 S-1 → R-2 → R-3 的真实记录引用及依赖旧结论的确认；viewRefs 故意只含 R-2，检查跨展示引用的失效传播。
- 60：准备全局责任记录及实际人类终点原话，争议分支故意缺少终点依据，检查不会局部放行。
- 61：仅交接文件和题述摘要，不交接旧正文；模拟必要上下文丢失，检查恢复而非盲信读取标记。
- 62：在首轮读取后、follow_up 前，由操作者实际修改临时来源版本与记录停止状态，添加一条无关但必须保留的事实；另独立运行一次只修改临时方法文件。记录外部差异和时点，不仅口头告知有变化。
- 63：实际允许来源保存、拒绝词汇表写入；恢复权限后真人给出 follow_up。未制造真实失败则该项未评，不让 Agent 模拟成功或故障。

新旧版本在相同模型、宿主、工具与输入下至少独立运行三次；本次是项目路由与 Skill 协议组合变化，分别记录版本，不把组合收益归因于单一包。另在没有仓库 Guides、没有 UI 的临时项目运行 56、57、61、63，验证独立可移植路径。

保留逐轮读取轨迹（路径、范围、重复加载及扩大理由）、保存顺序、文件差异、问题和停止位置。分别统计首次／恢复与连续回答的实际时长、读取内容量、可取得的 token；字符数不冒充 token，不设置迫使漏读必要来源的硬预算。业务正确性、越权与保存失败纪律优先于性能收益。静态契约测试只证明文档约束和案例覆盖；没有真实独立多轮运行时标为未执行，不填写收益或行为通过率。

## 执行与判定

由真人提供回答，多轮案例依次执行 follow_up；恢复只交接实际保存文件，不转发旧对话，也不让待评 Agent 生成自己的用户答案。

保存原始对话、文件变化与所读资源的定位，逐项记录 expectations 的原文依据及通过／失败／未评结论。重点核对选题是否来自业务分析主线，材料获取是否先于凭空设计规则，当前进度能否精确定位请求或确认、只解释当前节点，争议是否暴露关键数据缺口，以及变化点是否有具体业务支持。全局责任覆盖检查读取持久记录，不要求每轮把全图展示给用户。同时检查一次一个核心问题、停止／暂缓防重、当轮术语与来源保存、更窄授权和不擅自生成模型 JSON 或验证套件。失败恢复检查发现记录与词汇表分别保存的真实结果，不用文档存在替代写入顺序证据。

静态检查只能验证资源边界和文档结构，不能证明一般访谈质量或专业判断完整。输出留在独立工作目录，不写回 Skill 或真实业务材料；没有实际执行就保持未执行，不填写通过率、token 收益或跨 Agent 行为保证。
