# 访谈行为评测

[基础案例](evals.json)、[凭证追溯案例](evidence-tracing.json)及[履约入口案例](fulfillment-entry.json)用于隔离验证访谈行为，不是日常问答参考或已执行结果。规则由 [访谈协议](../references/interview.md) 与 FM 方法维护。评判实际读了什么、问了什么、依据如何支撑当前判断，不以栏目齐全、关键词命中或复述样例判通过。

## 当前覆盖

| 目录                     | 覆盖                                                                         | 重点风险                                                                                   |
| ------------------------ | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `evals.json`             | 合同与经营依据、现金单据逆推、语言、身份、领域复用、导航、连续承接、结束准入 | 专业资源、责任双方、实际约定、权限、停止／恢复与完整责任范围                               |
| `evidence-tracing.json`  | 判断 → 数据 → 凭证 → 深入 → 返回判断                                         | 要求与结果的依据、共同前提与独立证明、部分回答、跨合同责任、局部暂缓、依赖更正、循环与版本 |
| `fulfillment-entry.json` | 已签约直接进入履约、影响当前金额的改价争议、平台模板与交易事实               | 复用既有依据、局部回溯、不制造全流程前置问题                                               |

基础案例保留各自独立风险，不按一个表达规则另开多个业务变体。名称身份、法定名称和源标签权限的专门评测由 FM 维护。正常与争议业务推演按实际业务验证，不因提问方式重构而省略。案例身份是文件路径与 ID，删除不补号、不复用，不锁定历史数量。

## 凭证追溯如何判定

`evidence-tracing.json` 每例都有独立合成材料和可观察反例，不能给待评 Agent 提供 expectations 或参考输出。

1. **交付要求与结果。** 比较合成仪表精度，不复述教学样例。先追双方认可要求与实际检验来源；部分回答后深入适用标准或读数形成依据，暂缓与更正可改变独立性。实验室证明不替代卖方交付责任。
2. **金额深入后返回。** 合同金额、口径与对象匹配已给，只缺实付的深层形成依据；核对是否从流水逐层返回结算记录、支付回执及原付款请求，是否直接推导剩余金额，而非重做字段问卷。
3. **跨合同控制。** 共同匹配只问一次，与独立来源同轮问；局部暂缓先不阻塞独立链，更正后成为共同前提则阻塞受影响判断。只有明确解除才恢复，保留原问题及返回位置；一次一问偏好、停止与仅补资料分别遵守。
4. **循环与版本。** 相互引用不是独立证明，同名不同版本不能复用旧适用答案；应定位真实缺失依据，不无限递归、不补造来源。
5. **识别伪追溯。** 对照同类交付材料，要求、结果数值及对象匹配均已充分，只剩校准依据。即使输出位置、责任和一段故事，若实际问题仍是参与人、规则、操作和例外的通用问卷，也判失败。

逐轮核对：每题服务于哪个履约判断、涉及哪项关键数据、已知凭证为何不足、回答后先返回哪里。先复用已知材料，找出全部可同时澄清的独立必要内容；共同依据只问一次，局部依赖不造成整轮逐问。题数由实际缺口决定，没有必要未知不凑题。每题只澄清一个判断，不凭问号数量判断业务独立性。

故事应区分请求依据与结果证明，并自然说明各支撑凭证的所属合同、位置与合同责任方。不要求每轮两侧各问一题，不要求固定段数、题数或分析栏目。箭头表示寻找依据，不是操作时间顺序。来源查清、证明充分、履约完成与人类结束确认分别判断。

## 其他专业边界

`fulfillment-entry.json` 对照三种输入：无成立争议时进入付款完成证明；接受改价是否影响当前金额时局部回溯；只有平台模板时区分责任类型与具体交易事实。与 FM 的 `behavior.json` 分工：Discovery 检查问题选择，FM 检查正式类型表达，不把 Agent 为补齐字段产生的疑问写成业务缺口。

基础案例 98—104 从现金权责与目标—实际对比核对经营发现：收入承担的义务、成本取得的权利、无实际偏差的内部绩效、非付款义务、经营依据缺失、支付协作与代表身份、混合导航及现金单据逆推。不能用固定选项数量或经营标签评分，不为领域或工具补造合同。

案例 11 检查定义更正不扩大编辑授权；49、57、59 检查普通对话、增量读取和更正影响；71 检查没有当前可问项不等于合同或全局结束。实际主体未知不等于合同责任方未知；经办人、上传人及证明提供方不自动成为合同一方。含义明确时直接翻译英文，不为名称制造业务问题。

## 隔离执行与证据

使用独立临时项目、新会话及合成输入，提供 evidence-fm 的实际安装路径和题面权限。files 相对本 evals 目录解析；只将题面和对应输入提供给待评 Agent，评判预期留给独立审核。合成材料不写入正式业务源；输入按[教学材料边界](../examples/README.md)脱敏，不保留真实平台特征或可识别交易信息。

真人依次提供 follow_up，待评 Agent 不自答。跨会话提供实际理解、材料、原问题与控制意图；上下文不足的案例不预先补齐。对比版本时固定模型、宿主、权限、输入和工具环境，至少独立运行三次，保存完整普通对话路径、逐轮问题、读取轨迹、来源及依赖变化、真实工具结果、文件差异与停止位置。

逐项 expectations 和 forbiddenActions 报告通过、失败或未评，引用真实轨迹。静态结构与资源测试只验证文档契约。没有实际执行就保持未执行，不填行为通过率、token收益或人类批准；结果保存在隔离目录，不制造业务任务完成状态。历史失败日志与业务原始证据不随案例维护删除。
