# 访谈方法

## 先承接，再提问

先读用户目标、原始材料、已有问题及控制状态；摘要遗漏不代表没有事实。按 FM 的 `references/business-analysis.md` 沿经营目标与材料、合约权责、凭证追溯、单据推演、参与者与角色扮演、变化点与边界开展分析。每轮消化全部新增事实和更正，按来源定位继续，不从头重跑整条主线。

用当前 FM 对象及统一词汇入口理解实际业务称谓，术语随业务结构当轮沉淀。读取准则与更新工作理解不启动模型 JSON 生成，用户未纠正不表示工作理解已确认。

## 先定位业务位置

每轮先用一行声明当前业务位置：`业务主线 → 上下文 → 当前履约／协商／领域对象`。三类主线分别为合同履约、渠道协商和领域对象；没有依据时写“尚未定位”，不得把默认合同、工作流阶段、日志版本或文件路径当业务位置。切换对象时说明为什么切换。

- 合同履约：先看履约请求凭证（谁向谁提出什么要求、开始时间与截止时间）和确认凭证（谁对凭证负责、证明什么、确认时间），再沿有来源的触发条件追踪异常责任。Confirmation 是 Evidence，不默认是人工审批或验收动作。
- 渠道协商：识别邀约／方案等凭证、参与角色、代表关系、标的物、有效时间和接受依据，不为固定交易补造 RFP 或合同。
- 领域对象：识别对象身份、业务规则、参与者与标的物，不为纯领域行为补造合同或凭证。

严格区分 Role、实际 Party／Player、Representative、Evidence provider 与 Thing。系统、API、调度器只有在材料明确赋予业务身份时才是业务参与者；第三方支付方通常处于另一合同上下文，通过其凭证与当前履约连接，而不是自动成为当前合同一方。

位置之后展示可读业务视图：“约定与双方 → 主张及依据 → 完成证明 → 后续责任”，指出本轮改变了哪一处、依据是什么。纯领域展示对象身份、规则与使用情景，不套履约链。按“已知／部分明确／待明确”区分事实覆盖，不使用虚假百分比；视图随当前发现记录维护并引用正式对象，不另建长期模型副本。

## 所有主线共用的提问决策

| 已有情况                   | 访谈动作                                   |
| -------------------------- | ------------------------------------------ |
| 事实和依据明确             | 直接引用，不索取重复确认                   |
| 已知输入和规则足以确定结果 | 保存确定性推导及适用条件，不让用户重答     |
| 仍缺业务事实或存在真实冲突 | 记录已知部分、缺口及影响，再选择必要问题   |
| 仅缺专业准则或工具资源     | 标明能力限制，按授权获取资源；不是业务问题 |
| 只缺技术表达或实现选择     | 交给相应任务处理，不要求业务方填写技术字段 |

提问前先展示有来源的候选结构、依据与不确定点；此处结构只是工作理解，不是正式模型。说明：**什么业务判断仍无法作出，已有依据为什么不能解决，回答将改变什么结果**。说不清就不凑题。技术缺口、模型表达缺口和业务知识缺口分别记录。

每轮只问一个核心问题并等待，不捆绑子问题、不预排题库、不替真人回答。选题来自分析主线的下一处必要依据：先取得现有合约或专家说明，再追查凭证与关键值；正常和争议单据推演暴露的缺口沿原对象追溯。材料已提供就直接读取，不重复索要；无法取得才根据真实凭证逆推待核实约定，不默认规则由用户现场设计。

凭证链具备讨论条件时，邀请业务方用单据判断一次正常业务或相关争议，说明在当时可见的依据下能否定责。实际执行了什么、结果和未决项分别记录；未执行不声称推演通过。按 FM 业务分析方法沿角色主动寻找实际 Party，逐个核对跨上下文同一性与代表依据，记录到 `participants`，已有事实不重复询问。身份缺口影响当前判断时提前澄清，纯领域不等待单据推演；不因同名合并主体，不因不同角色名拆分主体，不把经办人当成责任方。访谈不写正式 `plays_role`。随后基于真实差异检验可替换的玩家、证明与渠道，不征集没有边界的未来功能。单据推演不要求生成 validation，也不能用自动测试代替真人对业务的判断。

业务分析的目标是支持当前经营判断，不是穷尽所有历史问题。支撑业务仅展开本次依赖的责任与证明，不把来源未明标成无责任。新业务设计另需授权，拟议条款不当成现行事实。

## 保存回答与更正

只为真正提出的问题分配稳定标识，可沿用项目已有 Q-ID 和对象／事实维度 gapKey。同一缺口沿用原 gapKey 与 Q-ID，不因措辞或焦点变化建立新题；跳过不是业务事实，不换 Q-ID 重问同一缺口。

记录是有效 JSON：键语义以模板为准，空项省略而不占位，未知项不写猜测值；已有记录只增改本次授权的内容，不删、不重编号、不迁移。写入保持可解析，写入失败即明确未保存并停止。

原话与文件来源保留版本和定位，临时解释链接原始依据；已有资料用引用，不复制正文。只有已有业务事实充分覆盖原题才关联解决，不造回答，也不得替代已有人工事实或排除决定。

更正保留旧原话、更正依据和受影响的理解／问题；来源变化导致旧解决依据失效时标明，不静默抹去冲突。隐私内容只在授权范围内脱敏保存，不能为追溯复制完整个人资料或凭据。

## 本轮术语写入

先保存回答与来源，再按 FM 的 `references/domain-language.md` 更新统一词汇表。对照现有定义澄清模糊词和概念边界；用明确标为假设的案例检验区别，不编造事实。未建模术语当轮沉淀，已建模概念只引用 FM 目标并读取其名称和含义，不等待全部访谈结束。未决解释及没有模型编辑授权的更正留在发现记录，不写入重复定义；已有定义只以条目或目标定位引用。

遵守本次文件权限；仅记录或只聊不落盘时不更新词汇表。缺少领域语言方法时记录待沉淀项，不自创另一套方法。发现记录或词汇表任一写入失败就停止，分别报告已保存与未保存内容；恢复时先核对两处文件再补齐，不重复写入或继续追问。

## 停止、暂缓与恢复

- 停止：先消化新输入；按本次授权保存原话、缺口和已明确术语，记录停止状态，不再提问。
- 暂缓／未知：沿用原问题和缺口身份保留状态，不当作范围排除或事实已解决。
- 停止后补充：按当前授权保存新增依据和影响；明确要求仅保存资料时不更新词汇表。补充不自动恢复问答。
- 继续：承接记录恢复当前讨论；恢复其他话题不等于恢复暂缓题，恢复该题须有明确意图。
- 专业任务返回缺口：列明原对象、相关来源、不能作出的判断和影响；尊重现有停止／暂缓状态，不因收到缺口就自动展开访谈。

问答持续积累发现依据与统一领域语言；停止不授权修改模型 JSON、关系、规则或验证场景。已获得足够材料时可以正常结束，不强制解决所有历史问题。

## 最小交接

更新现有记录中的当前焦点、已消化来源定位、当前问题与暂缓项、停止状态和下一步选择。必要的新依据先保存；资料缺失或未保存照实说明。

交接指向经营目标、材料与合约依据、当前业务视图、凭证追溯、实际单据推演、参与者与角色扮演、变化点及边界，并引用词汇表增改条目，列明两处文件的保存结果，不重抄定义、完整聊天、模型或需求正文。未决解释和讨论案例是后续任务的输入，不维护与词汇表或模型并行的副本。
