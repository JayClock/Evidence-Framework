# Evidence 业务访谈

负责交互、记录和恢复；业务判断使用 FM 方法，不在访谈包维护第二套建模知识。普通对话是完整交互路径，无需界面扩展；可选 UI 只包装相同内容并返回用户输入。

## Guides

读取用户本轮全部输入、已有来源、实际记录、词汇表与停止／暂缓状态。先按 [访谈协议](references/interview.md) 判断本轮授权；只聊不落盘、仅保存资料和停止请求优先，不将普通回答解释成生成授权。

交互方式由宿主提供，具体工具映射不属于本包。用户要求纯文本或界面不可用时直接按访谈协议对话；不要为了访谈要求安装界面，也不把可选 UI 当成专业方法依赖。

默认发现记录为 `.evidence/discovery.json`，词汇入口为 `.evidence/glossary.json`。按 [记录模板](assets/discovery-template.json) 的 `schemaVersion: "2.0"` 维护键语义，不逐字段填表。只修改本次授权的文件，保留无关改动，不自动迁移、转换或重编号。

通过资源发现定位 `evidence-fm` 实际目录，不假设兄弟路径。按当前判断读取其参考：

| 需要解决的判断                     | FM 包内参考                            |
| ---------------------------------- | -------------------------------------- |
| 经营依据、边界、骨架及专业分析路线 | `references/business-analysis.md`      |
| 关键值、计算及业务时间依据         | `references/provenance.md`             |
| 明确术语、定义归属及当轮保存       | `references/domain-language.md`        |
| 责任终点、全局追责结束及确认失效   | `references/responsibility-closure.md` |
| 对话单据推演与正式模拟的区别       | `references/scenario-validation.md`    |

方法缺失时明示专业判断限制与待沉淀术语，不用业务问题弥补工具缺失。tests/、evals/ 不作为业务材料。

## Action

每轮执行一次：吸收来源 → 保存 → 核对依赖 → 展示并等待；回答后重新判断，不预排题库：

1. 消化新增事实、更正与控制意图；材料已有的信息直接复用。
2. 先保存原话与来源，再按 FM 方法更新相关记录及引用；保留冲突、历史原话和确认失效影响。
3. 按授权当轮沉淀明确术语。已有 FM 定义只引用，不另写同义定义；仅保存资料时不更新词汇表。
4. 首次依据材料直接识别合同上下文或用户要求查看／切换时，按访谈协议展示合同上下文总览并等待选择；已澄清结束项只展示、不可切换。只展示 FM 方法核对后依据充分的合同，不展示候选供用户确认；选择只决定分析焦点，不与业务提问捆绑。选择后承接已知双方与全部主履约，进入单点追溯后，从记录引用生成当前位置和简短故事，讲述凭证中的信息从哪里来、已追到哪里；必要时自然接一个问题。履约位置精确到合同、履约项及请求或确认，已识别凭证展示业务名称、类型作辅助标签；不展开全局，不附方法文章信息或准入提醒，不维护故事或来源链副本。
5. 若存在阻止当前判断的业务来源缺口，在故事后只问一个核心问题并等待真人，不展示机械的缺口栏；没有必要问题则交接。达到准入方法规定的条件时，展示完整版本并等待人类明确确认全部追责结束，不自行宣布完成。

问题选择与视图表达由当前业务依赖决定，不固定问卷顺序；保存顺序、每轮问题上限及文件权限不可跳过。发现结构不是正式 FM，不生成模型 JSON、规则、验证场景或 API。

## Sensors

提出下一问前核对：

- 本轮事实与更正有来源定位，已知内容没有被重复索取；当前焦点和全局未决项可从引用恢复。
- 发现记录与词汇表分别有真实保存结果；定义归属遵循 FM 方法，未保存内容明确可见。
- 总览只包含实际来源支撑的合同识别结果，未决线索不包装成候选合同；结束依据可定位，已结束项不可选择，自然语言切换同样检查；取消不改焦点。
- 追溯故事与当前记录及请求／确认端点一致，业务名称不被类型后缀替代，不混入其他合同或履约；故事说明业务信息来源，文件出处留在记录，不放进日常展示。
- 问题确实影响业务判断，只有一个核心问题，没有让业务方填写技术槽位。
- 实际单据推演、人类终点与全局结束依据分别标明；未执行不声称通过，停止不当成追责结束。

这些是本轮交互证据，不是模型校验或业务批准。结构检查不能证明访谈质量。

## Steer

- 任一写入失败就停止，不提出下一问；恢复先核对两处文件，只补齐授权内未保存内容。
- 记录版本不符：停止结构写入，保留原文件并交接限制；转换另需授权。
- 停止、暂缓或仅补资料：处理获授权新增内容后停止，不自动恢复问答；下游返回缺口也不解除该状态。
- 无写入权限：给可复制内容，明确未保存。交互界面不可用则按原焦点和问题转普通对话，不伪造回答；已收到的回答先保存，不重复索取。取消保留原问题并等待，不当作技术不可用重问。
- 交接：给当前焦点、来源与对象引用、原问题、控制意图、各文件保存结果及未决影响后停止；不自动开始建模、批准或进入下游。
