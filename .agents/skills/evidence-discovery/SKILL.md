# Evidence 业务访谈

围绕业务判断逐问澄清，与用户形成共同理解。每轮吸收全部输入，更新当前分析，选择一个必要问题并等待回答；明确术语按授权当轮沉淀。

## Guides

按 [访谈协议](references/interview.md) 承接本轮目标、材料、当前理解与控制意图。首次进入或恢复时定位当前节点并加载必要方法；连续问答只核对相关依据与受影响术语。已加载且未变化、仍在上下文的方法直接复用。

通过资源发现定位 `evidence-fm` 实际目录，按当前判断读取其参考：

| 当前判断                       | FM 包内参考                            |
| ------------------------------ | -------------------------------------- |
| 经营依据、边界、骨架及分析依赖 | `references/business-analysis.md`      |
| 关键值、计算及业务时间依据     | `references/provenance.md`             |
| 术语含义、定义归属及当轮沉淀   | `references/domain-language.md`        |
| 责任终点、全局结束及确认适用性 | `references/responsibility-closure.md` |
| 正常与争议单据推演             | `references/scenario-validation.md`    |

进入单点追溯、合同导航或控制与恢复动作时，从 [行为基线](examples/README.md) 加载对应样例。业务判断以本轮实际材料、用户决定与 FM 方法为准；资源缺失时说明当前判断限制。

## Action

吸收全部输入 → 更新当前理解与依赖 → 按授权沉淀术语 → 导航、单点澄清或结束本轮。

- **导航**：依据材料直接识别经营依据与独立边界充分的合同，首次或用户要求查看／切换时展示总览。每项标注经营主线，说明谁与谁签订什么合同、实现什么目的；用户选择分析焦点后，承接已有双方与全部主履约。
- **单点澄清**：先展示当前位置，再用简短故事说明凭证中的信息追到了哪里，自然接一个必要问题。履约位置精确到合同、履约项及请求或确认，凭证使用业务名称；领域与协商使用各自的上下文与对象。
- **依赖推进**：自行读取可查事实，从前置依据已经具备的未决判断中选下一问。答案改变理解后重新核对依赖，优先追到当前责任分支终点，再回到兄弟分支。
- **术语沉淀**：按 FM 方法当轮维护唯一词汇表 `.evidence/glossary.json`。未建模概念保存明确的定义，已建模概念引用当前 FM；明确只聊不落盘或仅补资料时按更窄授权处理。
- **追责结束核对**：展示完整范围、责任图、终点及推演，等待人类明确确认全部追责结束。

## Sensors

下一问前核对：全部新增事实与更正已吸收；已知事实已复用；当前故事有实际业务依据；问题的前置依赖已具备；每轮只有一个核心问题；术语定义归属及实际保存结果准确；人类确认覆盖当前业务理解。

## Steer

更正沿依赖核对受影响结论及确认。暂缓保留原问题与未决依据，停止或仅补资料时处理本轮获授权内容后结束。术语写入失败立即停止，说明错误及未保存术语；恢复时核对实际条目并补齐授权内容。

普通对话与可选 UI 使用同一业务内容。界面不可用时沿原焦点和问题转普通对话，取消时保留当前焦点等待。跨会话按提供的材料与交接承接；缺少关键上下文时明示限制，澄清必要缺口。

本轮结束时简述当前判断、必要未决项、控制意图及术语实际保存结果；下一步由用户选择。
