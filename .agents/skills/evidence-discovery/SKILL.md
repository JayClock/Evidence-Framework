# Evidence 业务访谈

负责把问题问清楚，不维护另一份正式业务模型。可以独立进行通用访谈，也可结合专业准则处理具体建模缺口。

## 1. 读取材料与适用准则

读取用户材料、现有问题与访谈记录；恢复时承接原来的焦点和状态。访谈机制只在 [访谈方法](references/interview.md) 维护。

遇到 FM 专业判断时，通过宿主的资源发现能力定位已安装的 `evidence-fm`，或读取用户提供的包路径；只读取相关参考，不调用模型生成流程：

| 判断涉及什么                           | FM 包内读取位置                     |
| -------------------------------------- | ----------------------------------- |
| 合同履约、领域身份、渠道协商与责任缺口 | `references/business-analysis.md`   |
| 关键数据的业务来源与时间含义           | `references/provenance.md`          |
| 业务案例与模型验证边界                 | `references/scenario-validation.md` |

这些是知识入口，不是假设存在的兄弟目录或专门工具。准则不可用时，继续一般事实澄清并明确专业判断的限制，不凭记忆补写格式要求，不要求用户用业务回答弥补知识包缺失，也不宣称已完成专业模型审查。

## 2. 执行访谈

1. 消化全部新增材料、回答、更正及控制意图。
2. 复用已知事实和有效依据，给出简短的工作理解；推断与未知明确标记。
3. 根据当前目标及适用准则，说明哪个判断仍不能作出、缺什么依据、回答会改变什么。
4. 只对必要业务缺口提问，等待真人；答案回来后先更新记录，再决定下一步。已有信息足够时整理并停止，不为模板凑题。

缺口可以来自用户叙述，也可以来自 FM 的输入复核。技术表达、资源安装和业务知识缺口分开；访谈不替用户作决定。

## 3. 保存访谈依据

按 [访谈记录模板](assets/discovery-template.md) 更新项目已有记录；没有时告知默认使用 `docs/business/`。保存原话与来源定位、临时理解、实际提出的问题及其状态。工作术语与讨论案例留作材料，不另行生成正式词汇表、模型、规则或验证套件。

采用现有文件与标识；已有记录不删、不重编号、不自动迁移。正式产物由后续任务消费这些来源生成，访谈只引用已有模型及案例，不维护同步副本。没有写入权限或用户只聊时，给可复制内容并明确未保存。

## 4. 结束与交接

按访谈方法处理停止、暂缓和继续；交接只给当前焦点、来源与问题定位、有效控制状态及下一步选择。新增原话先写回记录，已有正文只引用。

用户明确要求生成／更新模型时，可切换到 `evidence-fm`；收敛软件范围时可选择 `evidence-requirements`。结束访谈不是执行这些任务的授权，FM 返回缺口也不自动恢复已停止的访谈。

参考只随当前问题按需读取；evals/ 仅用于维护或明确评测，不作为本项目的业务来源。
