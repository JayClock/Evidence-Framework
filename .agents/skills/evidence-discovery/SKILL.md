# Evidence 业务访谈

每轮理解全部输入，处理受影响判断，直接核对相关 Entity 及其属性的名称与含义，再围绕同一业务焦点主动寻找可以同时澄清的内容，把相关请求、确认及支撑凭证当前可问的独立必要问题一起提出并等待真人；用户要求一次一问时遵守。合同凭证的责任人就是所属合同的一方，业务含义明确的名称直接翻译英文，不等待人类提供英文。问答与控制由本包维护，专业方法由 FM 维护。

## Guides

先读 [访谈协议](references/interview.md)，确定当前节点、原问题、授权与控制意图。首次进入或恢复时加载必要方法；连续问答复用仍在上下文且未变化的方法，只核对新增输入与受影响依赖。

通过资源发现定位 `evidence-fm`，按当前判断读取包内参考：

| 当前判断                                               | FM 包内参考                            |
| ------------------------------------------------------ | -------------------------------------- |
| 现金权责、绩效约定与责任双方、主要履约、骨架及增量发现 | `references/business-analysis.md`      |
| 领域复用、业务连接点及必要的内部规则                   | `references/domain-modeling.md`        |
| 当前判断的依据不足、冲突或需要深入                     | `references/provenance.md`             |
| 模型语言理解、日常表达及定义归属                       | `references/domain-language.md`        |
| 责任终点、全部追责结束及确认适用性                     | `references/responsibility-closure.md` |
| 正常与争议单据推演                                     | `references/scenario-validation.md`    |

追溯问答、上下文导航或控制与恢复时，从 [样例索引](examples/README.md) 只读对应文件的相关章节；边界反例供维护评测使用，不在日常问答中全量加载。判断使用实际材料与用户决定；缺少专业资源时交接具体限制。合同或独立领域／协商澄清结束且具备生成权限时，通过资源发现定位 `evidence-modeling`，交回对应建模分支；仅访谈或只读时不扩大权限，完整接续协议由该入口维护。

## Action

1. **按经营权责更新理解。** 吸收本轮全部事实、更正和控制意图；按 FM 方法从收入流与成本结构出发，以现金权责、目标—实际对比找到实际约定与责任双方，用主要履约检验理解，已知经营依据、主体和责任直接复用。未知收支或内部绩效关系先澄清，不凭任意承诺认定独立业务合同。沿凭证增量发现其他约定与协作，保持当前焦点；边界疑问按 FM 方法局部核对，不把全局分类或合同清单当成进入条件。完成时，当前约定、责任、依赖与必要未知可解释。
2. **核对模型语言。** 按 FM 方法直接读取 `.evidence/fm/` 中相关 Entity 及其属性，复用规范名称与定义；尚无模型时承接明确材料，缺英文直接翻译。发现定义更正时核对目标与影响；有模型编辑授权时交由 FM 增量维护，没有则只交接，不为保存术语创建占位 Entity。只聊不落盘、仅保存资料等更窄授权优先。完成时，本轮表达与定义拥有者一致，共同理解与已保存模型分开。
3. **推进一个业务焦点。** 先消费当前判断已有的约定、参数与凭证；有影响结论的真实业务缺口才组织问题，没有就交接。明确目标或单一清晰入口直接进入；多个独立入口需要确定优先级或用户要求查看／切换时才导航。按访谈协议执行合同凭证或领域对象／协商方案的成组澄清及本轮交接。领域优先复用成熟方案、澄清业务连接点，必要时才深入；角色选择按 FM 语义，不默认创建完整领域上下文。领域与协商按对应位置和依据展示，不强套凭证。展示主焦点、各活跃凭证的当前位置与合同责任方、简短追溯故事，必要时说明业务目标；主动寻找全部可同时澄清的独立内容，共同前提与其他独立问题同轮提出，各来源链依据回答分别深入与回溯。只有用户要求逐问或查找后确实只有一个可问项时才单问。导航、单合同结束确认、领域／协商分支结束确认及全局结束确认分别单独一轮。完成时，提出本轮问题后等待真人，按停止／暂缓意图结束本轮，或将获授权的有效合同／领域／协商结束信号交回建模入口。

## Sensors

展示与下一轮前核对：现金权责或目标—实际对比的依据与责任关系可解释，当前约定与责任双方准确，新增协作与受影响边界已核对，功能清单未直接当作上下文；资料出处与内部检查过程未混入业务展示；全部输入已吸收；已知事实已复用；故事忠实且聚焦当前节点；故事、问题与交接使用同一中文（英文）规范名称；各请求与确认的责任人是所属合同的一方，不被经办人或证明提供方替换；每轮主动查找并成组提出全部独立可问内容，共同依据只追一次，局部依赖不造成整轮串行，各链深入与回溯、部分回答已分别承接；含义冲突未被静默覆盖；每题能说明已有材料仍不足以作出的当前判断，不把补字段或操作步骤当作业务缺口；各题前置依据具备且彼此独立；部分回答、未答与暂缓分别承接；更正后重算依赖；Entity 及其属性的定义归属与真实文件结果准确；人类确认覆盖当前理解。

## Steer

- **更正**：沿依赖核对结论与确认失效影响，保留未受影响事实。
- **暂缓、停止或仅补资料**：处理本轮获授权内容，保留原问题与未决依据后停止；继续问答需要明确意图。
- **部分回答或取消**：吸收已答内容，未答项不默认同意；取消保留焦点等待。不靠换问题标识恢复暂缓题。
- **本轮交接**：有模型编辑授权时将已知内容及更正交给 FM，凭证与责任角色共同落地后检查一致性；责任角色未知不保存该凭证，实际主体未知不造 Participant。没有该授权不写模型 JSON。简述当前判断、必要未决项、控制意图和真实保存结果；获授权的有效合同／领域／协商结束信号交回建模入口自动接续，其余下一步由用户选择。不自动恢复其他合同或暂缓题。
