# Evidence 业务访谈

只负责选题、等待、记录和恢复；业务分析、参与者与角色扮演、单据推演及变化点判断由 `evidence-fm` 唯一维护。发现骨架不是正式模型，访谈不生成模型 JSON。

## 1. 恢复本次意图与来源

读取用户目标、原始材料、实际发现记录、问题与 `.evidence/glossary.json`，按 [访谈协议](references/interview.md) 恢复当前对象及控制意图。没有写入授权只分析；只聊不落盘、仅保存资料、只记录冲突或停止等更窄要求优先。

默认记录为 `.evidence/discovery.json`，按 [记录模板](assets/discovery-template.json) 的 `schemaVersion: "2.0"` 键语义维护。只修改本次授权的文件，不自动迁移、重编号或转换既有记录；格式不匹配先交接限制，结构转换另需明确授权。

通过宿主资源发现定位 FM 包的实际目录并读取所需方法，不假设兄弟路径：

| 当前判断                                                                      | FM 包内方法                            |
| ----------------------------------------------------------------------------- | -------------------------------------- |
| 合同、请求—确认骨架、凭证展开、领域与渠道、单据推演、参与者与角色扮演、变化点 | `references/business-analysis.md`      |
| 关键数据与业务时间的来源、匹配及派生                                          | `references/provenance.md`             |
| 全部主履约、异常递归、人类终点和正式建模准入                                  | `references/responsibility-closure.md` |
| 当轮术语、定义拥有者及保存                                                    | `references/domain-language.md`        |
| 对话单据推演与正式验证的边界                                                  | `references/scenario-validation.md`    |

资源缺失可做一般事实澄清，明确专业判断限制与待沉淀术语；不把资源安装问题变成业务问题，不宣称已完成专业审查。

## 2. 处理一轮，不跳过保存

按访谈协议执行一个循环：

```text
消化全部新增输入与控制意图
  → 先保存原话与来源，更新对应对象及引用
  → 按 FM 方法当轮维护明确术语
  → 从引用生成全局视图与当前焦点
  → 有必要业务缺口才提出一个问题并等待，否则交接
```

合同主线按 FM 方法先定位约定和全部主履约，再展开当前请求—确认骨架、凭证追溯与异常新义务；领域与协商走各自分支。工作理解使用发现记录 ID，不提前创建 FM 对象；词汇名称和定义只引用其唯一拥有者。

**退出条件**：新增事实及更正已消化；当前焦点、全局责任图、来源与未知可定位；发现记录和词汇表分别有真实保存结果。任一写入失败就停止，不提出下一问；无写入权限给可复制内容并明示未保存。

每轮只问一个必要业务问题，不自答、不预排题库。所有分支已有终点依据时展示完整版本，等待人类明确确认全部追责结束；不自行宣告结束，不把停止当成准入。

## 3. 按引用交接并停止

交接只引用约定、履约骨架、凭证追溯、实际单据推演、参与者与角色扮演、变化点、全局责任及原问题，不复制事实正文。问题只维护在主记录或 `.evidence/questions.json` 一处。

术语当轮保存：未建模概念写 standalone，已建模概念只建 model 引用。未决解释、已建模概念的更正和待改影响留在发现记录，不覆盖模型定义。访谈写入不授权模型 JSON、关系、规则、验证场景、API 或实现。

结束访谈不自动建模，收到下游缺口不自动恢复已停止或暂缓的问题。界面只收集回答，不保存记录；不可用转普通对话。evals/ 仅用于维护评测，不作项目业务来源。
