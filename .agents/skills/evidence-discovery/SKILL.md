# Evidence 业务访谈

负责访谈的选题、等待、保存与控制状态。业务分析和领域语言由 `evidence-fm` 提供，访谈不维护另一套建模知识。

## 1. 承接目标与材料

读取用户目标、新增材料、已有记录、问题和统一词汇表，恢复当前焦点与停止／暂缓状态。先读[访谈方法](references/interview.md)，按本次权限决定可以保存什么。

默认记录位于 `.evidence/discovery.json`，术语位于 `.evidence/glossary.json`；沿用已有文件和指定路径，不自动迁移。只修改本次授权的文件。只聊不落盘、仅保存资料、只记录冲突等更窄要求优先。

通过宿主资源发现定位 FM 包的实际目录，按当前判断读取：

| 当前判断                                             | FM 包内方法                         |
| ---------------------------------------------------- | ----------------------------------- |
| 经营与权责、单据推演、参与者与角色扮演、变化点与边界 | `references/business-analysis.md`   |
| 术语区别、定义拥有者及当轮写入                       | `references/domain-language.md`     |
| 关键金额、身份、版本或业务时间依据                   | `references/provenance.md`          |
| 案例推演与正式验证的边界                             | `references/scenario-validation.md` |

资源缺失时可继续一般事实澄清，保存待沉淀项并明确词汇表尚未更新；不让用户回答安装问题来弥补专业方法缺失。

## 2. 完成一轮

按访谈方法执行：消化全部新增事实与控制意图，先保存原话与来源；展示带来源的业务位置和可读视图，按 FM 方法当轮维护术语，再决定是否提问。

**退出条件**：本轮新增输入均已处理，视图变化、依据与未知可区分；发现记录与词汇表各有保存结果。两处任一写入失败即停止，不继续追问；没有写入权限则给可复制内容并明确未保存。

仍有影响当前判断的业务缺口时，说明已有依据为何不足、回答改变什么，再只问一个必要问题或请求一份材料并等待真人。事实能自行查明就先读取；目标已有足够依据则停止，不为填满模板制造问题。业务未知、技术选择和资源缺失分别处理。

## 3. 保存与交接

按[记录模板](assets/discovery-template.json)的键语义维护有效 JSON，只保存有内容的部分。需要拆分已提问题时用 `.evidence/questions.json`，主记录以 questionsFile 引用，同一问题不重复维护。稳定问题身份、更正追溯、停止与恢复遵循访谈方法。

普通访谈授权发现记录和已明确术语的增量写入。未建模概念写 standalone，已建模概念只建 model 引用；未决解释或没有模型编辑授权的更正留在发现记录。术语写入不授权编辑模型 JSON、关系、规则、验证场景、API 或实现。

交接引用当前业务视图、分析结果、词汇条目、各文件保存结果、未决问题与控制状态，不复制模型或定义正文。模型编辑、软件需求和 API 设计分别交对应任务；结束访谈和收到下游缺口都不自动授权执行它们或恢复已停止的问答。

界面只收集交互，不保存记录；不可用时转普通对话。evals/ 仅用于维护评测，不作业务来源。
