# FM Modeling 组合入口

这是用户显式调用的编排入口。方法分别归属 `evidence-discovery` 与 `evidence-fm`；本入口不复制访谈纪律、FM 语义、来源追溯或场景规则。

## 开始

读取用户目标、项目约定、已有发现记录、正式模型、候选和检查记录。新产物默认统一放在项目根的 `.evidence/`，具体子目录见工作流程；沿用已有文件或用户显式指定路径，不自动迁移。这里的产物目录不是宿主状态仓库，不读写宿主拥有的 `state.json`、审批或其他运行状态；项目文件权限与提交要求仍优先。通过宿主资源发现定位已安装 Skill，不假设兄弟目录或固定安装路径。随后识别本次意图：

- 讨论或澄清：只整理材料、问题和交接。
- 生成模型：评估材料并形成完整候选，不直接替换正式模型。
- 只校验：运行只读检查，不改模型源文件。
- 保存当前候选：仅处理用户明确指向且已经展示的准备结果。
- 暂停或结束：保存已取得的依据和控制状态后停止。

资源缺失是执行限制，不是业务问题。缺少 `evidence-discovery` 时可以消费充分材料，但不要自创访谈机制；缺少 `evidence-fm` 时不能声称完成专业建模、检查或发布。只读环境提供可复制的最小交接并明确尚未保存。

## 组合流程

读取 [工作流程](references/workflow.md)，只执行与当前意图有关的分支：

1. 消化全部新增输入；需要澄清时遵循 `evidence-discovery`，新回答必须先保存再重新判断。
2. 需要专业判断、候选或验证时遵循 `evidence-fm`；材料足够时不为模板制造问题。候选按 Context／Role／责任边界、Evidence 主线与时间、Evidence→Thing、Other Evidence→Evidence、CEL Rule、Evidence Instance／`basedOn` 的顺序形成。
3. 生成请求止于完整候选、Evidence 图与时间线、真实检查和差异展示。无来源的相对顺序保持未决；普通回答、停止、机器通过都不是保存授权。
4. 用户明确授权保存已展示的准备结果后，才按 `evidence-fm` 的发布方法调用独立 CLI。
5. 保存最小交接并停止，不自动进入需求、架构、开发、审核或其他交付流程。

界面工具可用时可改善提问与差异查看；不可用时用普通对话展示同样信息。业务事实最终以项目文件实际写入为准，不能把界面返回当作已经保存。
