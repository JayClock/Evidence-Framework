# FM Modeling 组合入口

这是用户显式调用的编排入口。访谈方法归属 `evidence-discovery`，建模与校验方法归属 `evidence-fm`。本入口只组合当前意图，不复制专业准则。

## 开始

读取用户目标、项目约定、发现记录、当前模型及检查记录。新产物默认放在项目根的 `.evidence/`，具体布局见 [工作流程](references/workflow.md)。沿用已有文件与用户显式指定路径，不自动迁移。产物目录不授予宿主状态写权限，不改 `state.json`、审批或运行记录。

通过宿主资源发现定位已安装 Skill，不假设兄弟目录或固定安装路径。识别本次意图：

- 讨论／澄清：整理材料、回答、问题与交接，不修改模型。
- 生成／修改模型：用户请求即为本次范围内的编辑授权，直接编辑 `.evidence/fm/`，随后校验并展示差异。
- 只校验：运行只读检查，不修改模型、场景、发现记录或报告文件。
- 生成可视化审核页：定位 `evidence-visualization` 并读取其 `SKILL.md`，使用其自带生成器从重新校验的 FM／已有 API 生成离线只读 HTML；本入口不重复维护展示方法和工具，不修改业务模型或自动创建 API。
- 暂停／结束：保存已取得且获准记录的依据与控制状态后停止，不启动建模。

资源缺失是执行限制，不是业务问题。缺少 `evidence-discovery` 时可以消费充分材料，但不自创访谈机制；缺少 `evidence-fm` 时不能声称完成专业建模或校验。只读环境给可复制的交接并明确未保存。

## 组合流程

1. 消化全部新增输入。需要澄清时遵循 `evidence-discovery`，回答必须先保存，再判断下一个必要缺口；保存失败停止推进。
2. 用户要求生成或修改时遵循 `evidence-fm`，评估 ready、support、pending，直接维护一个当前模型目录。材料足够时不为模板制造问题，未知事实不编成规则。
3. 按 Context／Role／责任边界、Evidence 主线与时间、Evidence→Thing、Other Evidence→Evidence、CEL Rule、Evidence Instance／`basedOn` 的顺序建模。
4. 运行真实检查，修正本次范围内的表达错误后重跑。模型修改即落盘；失败时如实报告当前文件未通过校验，不声称目录始终有效，不自动回滚。
5. 展示实际增改删、来源、检查摘要、时间线、未决顺序及业务缺口。检查结果绑定 `modelDigest`；文件变化后旧检查不能证明当前模型有效。
6. 保存获授权的最小交接后停止。Git 用于查看差异和版本恢复，不自动提交、暂存或回滚。写入、机器检查与业务批准相互独立，不自动进入 API、需求、架构或开发。

界面工具仅用于提问；不可用时转普通对话。差异和检查结果通过普通对话展示，不能把界面回答当作文件已经保存。
