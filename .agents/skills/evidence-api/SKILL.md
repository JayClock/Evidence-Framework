# Evidence API 设计

本包独立维护技术契约与派生产物。业务事实与 FM 校验归 `evidence-fm`，完整生成的阶段接续归 `evidence-modeling`。API 只读消费已结束确认且完整性检查有效的明确范围及必要依赖，不消费所有尚在生长的对象。

## Guides

先确定讨论、设计编辑、只读校验或仅生成投影。读取项目权限、实际来源、已有文件与 Git 差异，只修改本次授权的文件，保留无关改动，不自动迁移。只聊不落盘不写文件；只校验不修复。

| 当前动作           | 必要参考                                                                                |
| ------------------ | --------------------------------------------------------------------------------------- |
| 讨论 API 方法      | [设计方法](references/api-method.md)，按问题选读 [HTTP 契约](references/api-contracts.md) |
| 设计或修改整体 API | [设计流程](references/api-design.md)、格式、HTTP 契约与 [校验纪律](references/api-validation.md) |
| 只校验或仅生成投影 | 校验纪律；投影必须通过完整检查，不编辑设计源                                            |

表达以当前业务依据和 Schema 为准，不靠历史链路样板。默认输入为 `.evidence/fm/` 与其外的 `.evidence/api/api.json`，输出 `.evidence/api/generated/`；项目产物不写入安装目录。领域语言直接消费当前 Entity 及其属性的规范名称与含义，不修改 FM，也不创建额外定义文件。

**红线（不可协商）**

- 只消费 `checkVersion: 5`、`consistent: true`、`complete: true`、明确 `scopeRefs/contextRefs`、空错误与缺口、`inputChanged: false` 且摘要匹配的 FM 结果；只有 `valid: true` 不可消费。
- 派生属性不进入请求体。请求体只收形成输入与证据引用；金额、期限、数量、时间差由服务端按 FM 规则计算并回填表示。
- 每个接口都必须有完整契约与成功消费步骤；身份、权限、数量与实例归属不靠技术猜测补齐。

## Action

1. **承接输入与权限。** 定位项目、本包与 FM 包的实际绝对路径，核对允许文件与当前整体模型。消费有效 FM 范围结果；没有结果时交给 `evidence-fm` 的只读检查分支取得一次结果，再返回本包，不由 API 工具隐式重查。完成时，来源、运行依赖、FM 结果与分支出口明确。

2. **维护获授权契约。** 讨论只解释判断与未知；编辑按设计流程遍历明确范围及依赖中的全部对象与场景，不默默过滤不完整对象，不以同合同局部履约切片交付。形成资源、角色能力、HTTP 契约及可接续消费者流程，维护唯一 `api.json`；派生字段只出现在表示与响应，不出现在请求体。完成时，接口与非接口活动均有依据，请求字段与 FM 的派生口径一致。

3. **检查并交付。** 按 Sensors 消费同一 FM 结果执行 API 自身检查；无错误与 gap 后按授权生成完整投影。只校验不 project、不生成页面。完成时，实际差异、整体覆盖、检查与未执行项可定位；来自 Modeling 时交回入口接续联合审核。

## Sensors

读取校验纪律，设置实际绝对路径与已满足依赖的 Python：

```bash
"$PYTHON" -B "$API_SKILL_DIR/scripts/fm_api.py" check \
  --project-root "$PROJECT_ROOT" --fm-skill "$FM_SKILL_DIR" \
  --fm "$FM_ROOT" --fm-check "$FM_CHECK_FILE" --api "$API_FILE"

# 仅有投影授权且完整检查通过时：
"$PYTHON" -B "$API_SKILL_DIR/scripts/fm_api.py" project \
  --project-root "$PROJECT_ROOT" --fm-skill "$FM_SKILL_DIR" \
  --fm "$FM_ROOT" --fm-check "$FM_CHECK_FILE" --api "$API_FILE"
```

**阻塞级**：FM 结果缺失、失败、摘要失配或输入变化；设计结构无效、悬空引用；整体对象或场景未覆盖；接口缺少完整契约或成功消费步骤；请求字段把派生属性当入参。出现任一即停止接续，不生成投影。

**警告级**：运行说明不完整；技术选型缺少业务依据；接口说明与业务能力不一致。警告级须在交付说明中逐项列出。

**信息级**：接口计数、覆盖范围、输出路径与输入摘要。

`inspect` 为只读索引命令，复用 `--fm-check` 核对摘要与范围而不重跑 FM 检查；`runtimeValidated` 为 false，说明产物完成静态契约与测试向量校验，运行态环境留待部署验证。

## Steer

- **技术表达错误**：只在 API 授权内修正并复验，不反向修改 FM 或业务预期。
- **发现派生字段被当作入参**：移除该请求字段，改由服务端按规则计算；需要新的形成输入时回 FM 核对属性含义，不在 API 侧猜。
- **业务身份、权限、数量或来源缺口**：停止受影响阶段，交接来源拥有者；不自行访谈或补造事实。
- **FM 结果缺失、失败或摘要失配**：返回 FM 只读检查阶段，不隐式重跑，不扩大为模型编辑。
- **环境、保存或检查失败**：保留真实错误与已改文件，分别报告部分结果；不自动安装、回滚或重建旧页面。
- **完成**：报告文件、实际检查与未决项后停止。不自动生成页面、需求、实施或 Git 操作。
