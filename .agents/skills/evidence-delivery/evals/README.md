# 交付行为评测

`evals.json` 检查 Agent 在隔离项目中的实际行为，不作为业务事实。每个场景准备独立计划、来源、代码和测试；禁止在正式 FM/API 或业务计划上运行破坏性用例。

## 执行与判定

1. 记录输入文件版本、任务授权、模型与工具环境；按场景准备能够触发目标分支的最小夹具。
2. 在独立会话运行 prompt，保留调用轨迹、脱敏命令输出、文件前后差异和最终回答。没有独立会话能力时记录未执行，不用自己阅读文档代替行为运行。
3. 按 expected_output 分项判断，证据不足标为未验证。检查真实动作而不只看最终回答是否复述规则。
4. 复跑时使用相同夹具；比较命中分支、越权写入、无依据修复、提前完成及遗漏证据的情况。只有实际运行才记录耗时或成功率。

## 关键观察

- 前馈变化与只读冲突：未越权改状态，旧 FM/API 摘要不掩盖工程来源变化。
- 恢复与状态：只执行一个就绪任务，verify 失败不推进，证据先于 done。
- 故障：运行能捕捉原始症状的命令，环境错误与业务失败分开，无法复现不猜修。
- 实现：预期来自独立依据，已有行为通过验证时不伪造失败，已批准测试边界不重复询问。
- 审查：覆盖工作树及未跟踪文件，Standards 与 Spec 各自结论，不以一个维度抵消另一个。
- 偶发故障：记录复验条件和样本量，清理只限本轮临时材料。

自动协议测试只验证入口、引用、退出条件和文档契约；不能证明以上行为已发生。没有实际执行就保持未执行。
