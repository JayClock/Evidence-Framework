# 小步实现

用于 implementation 任务；只读验证按已有 CHECK 复跑，不为了补一段失败记录改坏代码。先完成入口的 Guides，确定本任务行为、测试边界与独立预期，再进入循环。

## 确定测试边界

从任务 design、procedureRefs 和 CHECK 读取公开行为入口、真实依赖与替身限制。已由授权任务确定的边界直接复用；边界不足时补局部设计，涉及业务决定则交拥有者，不重复让用户批准每条测试。

领域测试通过实体、角色对象或公开契约观察规则；HTTP 测试观察协议；持久化测试可检查 SQL、行数、写后重读与回滚。每种测试只能证明其边界内的行为，不能用 mock 通过代替真实装配。

预期值来自规则、验收、已核实案例或独立计算，保留来源。避免复写被测算法来生成断言，也不要让快照更新替代业务判断。

**退出条件**：能指出当前测试入口、具体输入、独立预期和失败后不变性；否则先修 CHECK 设计。

## 一次一个行为

1. **红**：选择一个尚未证明的行为或反例，写测试并实际运行。失败须由目标行为未实现或错误引起；依赖缺失、编译错误和启动失败不是业务红灯，先分开处理。已有实现使测试直接通过时，核实测试确实覆盖该行为，记录已有行为验证，不伪造红灯。
2. **绿**：只实现使当前测试通过的必要变化，保留行为与数据拥有者；运行当前测试及受影响的近邻回归。避免一次铺完所有测试或提前实现未来能力。
3. **整理**：在已通过检查的保护下做当前任务内的局部重构，再运行同一组检查。跨模块重划边界或机械全仓修改返回规划，不借重构扩范围。
4. **继续**：对照本任务验收选择下一个行为，直到正常、边界、反例和失败不变性均有对应证据。用已有 CHECK 聚合结果，不为每次循环新增任务或状态文件。

用户明确选择普通实现与回归时，按该约定执行并记录没有测试先行的事实；故障修复仍先建立能捕捉原始症状的复现。不得把该例外写成已经执行红绿循环。

## 收束

删除或归位本轮临时调试材料，保留必要失败日志和回归测试。运行本任务全部 CHECK 与项目质量检查，再进入双维度审查。局部测试通过只表示当前循环变绿，不表示任务完成。

真实结果写入现有 observedEvidence：对应 CHECK、命令、cwd、退出码、输出定位、红/绿或已有行为验证、未覆盖项。报告事实，不填预期执行结果，也不增加测试循环状态字段。
