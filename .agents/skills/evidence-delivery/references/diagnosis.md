# 故障诊断

用于故障、行为回归和性能异常。诊断保持当前任务的文件与操作权限；只读请求只调查和报告。日志、请求和命令展示前脱敏，凭据从环境读取，不保存认证头或完整个人资料。

## 1. 建立症状信号

先明确用户观察到的输入、预期、实际症状及环境。可阅读代码和配置以构建复现，但在获得失败信号前不认定根因或试修实现。

优先使用已有测试；其次选择 HTTP/CLI 脚本、浏览器断言、脱敏请求回放或最小临时运行器。选能进入真实故障路径的最窄边界，不要求所有问题都启动完整应用。

**退出条件**：有一条已经实际运行的命令及脱敏输出，能断言用户的具体症状，而不只是“进程没有报错”。区分业务失败与环境失败；无法复现时列出尝试、结果和所需环境/材料，停止猜修。

偶发问题记录运行次数、失败次数、输入、随机种子和并发条件，先提高可观察概率；一次通过不证明修复。性能问题固定数据规模、测量方法与基线，预期阈值来自验收或已确认比较口径。

## 2. 缩小案例

逐次减少输入、调用、配置或步骤，每次只改一项并重跑。保留触发原始症状所需的调用链和真实依赖，不为了快速单测把故障条件 mock 掉。

**退出条件**：能解释保留项为何必要，或明确进一步缩小受到什么限制；缩小后的失败仍与原始症状相同。

## 3. 验证假设

列出与现有证据相容的候选原因，按证据排序。每项写成“若 X 是原因，改变 Y 后应观察到 Z”，说明如何证伪。已有证据唯一定位时不凑数量，有多种可能时不只挑最顺眼的一种。

每次探针对应一个预测，只改变一个变量。优先断点、针对性日志或性能剖析；临时探针使用唯一标识，便于清理。记录观察和被排除原因，不用相关性代替因果证据。

**退出条件**：至少一个假设有区分性证据支持；否则回到复现或报告限制，不开始无依据的修复。

## 4. 修复并复验

将最小复现转为能覆盖真实故障模式的回归测试，实际看到失败后再修复。不存在合适测试边界时报告设计缺口，不以浅层测试冒充回归保护；是否调整设计按任务权限处理。

运行回归测试，再运行未缩小的原始场景和相关 CHECK。性能沿同一口径比较，偶发故障报告复验样本量与残余不确定性。移除本轮临时探针，保留必要日志；涉及用户已有材料只交接，不删除。

**退出条件**：原始症状已复验、回归结果真实、临时探针已清理，或明确留下局部阻塞。worker 交接根因、命令、输出定位及限制，由主 Agent 核验后唯一归入现有任务证据，不建立独立故障状态源。随后回到 Sensors，worker 完成项目质量检查，再由独立 reviewer 双维度审查。
