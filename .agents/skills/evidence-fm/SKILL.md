# Evidence 业务建模

从收入流与成本结构出发，用现金权责、目标—实际对比发现约定与责任双方，再以合同、履约与凭证链组织责任。Discovery 管理访谈问答，本包维护专业判断与正式表达；API 由 `evidence-api`、页面由 `evidence-visualization` 独立维护，阶段接续归 `evidence-modeling`。

## Guides

先确定讨论、正式编辑或只读校验。讨论只解释判断，不写模型 JSON；读取项目权限、实际来源、当前文件与 Git 差异，只修改本次授权的文件，不自动迁移。默认源为 `.evidence/fm/`；Entity 及其属性直接承担统一语言，不维护额外定义文件；项目产物不写入安装目录。讨论直接消费 Entity 名称、定义与属性含义；含义明确且缺英文时直接翻译，不改既有源标签或标识。

**红线（不可协商）**

- 关键数据项必须有提供方：合同参数、前序凭证属性、领域对象属性，或形成方记录的结果事实。
- 金额、期限、数量、时间差能由已建模输入得出时，写成派生规则并挂到属性；不得用实例值、默认值或自由参数替代规则。
- 派生值只读取已建模属性；规则不得藏在没有来源的标量绑定里。
- 履约请求直接引用所属根合同；每项履约恰有一个请求与结果端；未知保持缺失。

## Action

1. **核对判断与授权。** 按 Guides 读取当前判断、实际输入与模型差异，确认本轮编辑授权、允许的文件与分支出口。渐进编辑不等待追责结束；只读、只聊不落盘、停止与仅补资料按更窄授权执行。完成时，所需依据、允许文件与出口可定位。

2. **落表达与关键数据台账。** 先按双方义务找到主要履约项，主要责任梳理与请求—确认识别合为同一动作；请求从首次保存起直接关联根合同，配对后包裹履约，单端凭证不建空履约；Context 与真实内容共同保存。对每张凭证列出金额、期限、数量、时间差等关键数据项，逐项判定提供方与表达：合同参数先落为属性，凭证再挂到责任角色与上下文，最后写派生规则或标注结果事实。派生属性只在实例中保留测试值，属性本身必须指向规则；结果事实在 meaning 写明由谁形成、由哪条完成规则核对。直接编辑当前模型，核对增改删、稳定身份与引用。完成时，本批对象、规则与每个关键数据的结论可定位，未知按实际保留。

3. **检查并交付。** 一次检查同时得到一致性与关键数据台账，范围结束另用 `--scope` 核对完整责任、适用场景与派生图。按 Sensors 分级报告，未通过不接续下游。完成时，获授权文件、检查结果与未完成阶段分别可报告。

## Sensors

检查在建模引擎内运行，不需要解释器。两种等价入口：

- 在桌面端或已接入的 Harness 内调用 `run_sensors` 工具，它返回一致性、关键数据台账、追溯日志校验与场景结果；
- 没有工具时执行 `npx evidence-model check "$FM_ROOT" > "$FM_CHECK_FILE"`，范围结束追加 `--scope "$CONTEXT_ID"`（可重复）。

两者输出同一份报告：`errors` 是阻塞项，`gaps` 是范围缺口，`keyDataSummary` 是台账结论。

**阻塞级**：文件写入失败；一致性错误（请求未直连根合同、空履约或空上下文、坏引用、CEL 失败、依赖环）；范围完整性未通过或适用场景模拟失败；派生指针与规则目标不一致。任一出现立即停止接续。

**警告级**：台账 `needsDecision` 待决项；模拟器暂不支持求值的规则；更正来源后待重算项。交付前必须逐项给出闭环结论或明确登记为缺口。

**信息级**：`consistent: true`、台账分类计数、`modelDigest` 与输入未变、未改动无关文件。

自动化检查通过后，逐项执行下列业务语义判定：

- **现金权责锚定**：合同是否挂到具体收入义务、支出权利或内部绩效目标。
- **主要履约成对**：双方是否各自是至少一项主要履约项的权利方。
- **请求—确认对偶**：每项履约是否有明确请求端与结果确认端。
- **违约阶梯闭环**：异常是否有补偿或升级路径，并推到可指名的责任终点。
- **易变策略隔离**：计价、分佣、分发方式是否为合同参数或规则，而非硬编码。
- **定义归属**：新增名称与定义是否归 Entity 或属性拥有者，并与既有规范名称一致。
- **关键数据来源**：每个 `needsDecision` 项是否已给出合同参数、前序凭证属性或结果事实结论；没有结论的项按缺口保留。

## Steer

- **表达错误**：在当前授权内修正并复验。
- **关键数据缺来源**：先补参数、前序凭证或派生规则；规则确实无法表达（工作日历、阶梯、外部行情）时记录为能力限制或业务缺口，不手填数值。
- **新责任、来源冲突、身份／权限／数量缺口或确认失效**：停止受影响阶段，交接具体对象与缺口；不自行提问，不解除访谈停止状态。
- **环境或保存失败**：保留真实错误与已改文件，不自动安装、不自动回滚、不重建；分别说明已保存、未通过与未执行。
- **完成**：报告实际差异、来源定位、检查结果与未决项后停止。不自动生成页面、设计 API 或操作 Git。
