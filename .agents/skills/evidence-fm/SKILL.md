# Evidence 业务建模

本包维护业务分析、领域语言与正式 FM。业务分析从收入流与成本结构出发，以现金权责、目标—实际对比发现业务，再通过合同与履约组织责任；不将经营逻辑降为可选线索。Discovery 管理访谈问答，本包维护专业判断与正式表达；API 设计由独立的 `evidence-api` 维护，阶段接续归 `evidence-modeling`。

## Guides

先确定讨论、正式编辑或只读校验。读取项目权限、实际来源、已有文件与 Git 差异，只修改本次授权的文件，保留无关改动，不自动迁移。只聊不落盘不写文件；只校验不修复、不保存项目报告。

字段结构直接消费 Schema，跨对象约束定位语义校验器，文档不复制字段表或 JSON 模板。专项按 [规则索引](references/README.md) 选择；首次处理某类表达时，从 [正式表达基线](examples/README.md) 只读对应样例，续问复用未变化内容。样例不是当前业务事实或准入依据；tests/、evals/ 仅用于维护。

默认源为 `.evidence/fm/`；Entity 及其属性直接承担统一语言，不维护额外定义文件。获授权检查记录放在 `.evidence/checks/fm/`；沿用已有指定位置，项目输出保持在 Skill 安装目录之外。

## Action

1. **核对分支依据。** 按 Guides 读取当前动作所需方法和实际输入。渐进编辑先核对当前业务依据及本轮编辑授权，不等待追责结束；范围交付另核对完整责任与人类结束确认；相关未澄清合同按语义使用 Context Role，不隐藏当前合同必要缺口；只读检查与语言讨论按各自权限执行。完成时，所需依据、允许文件与分支出口可定位；编辑授权不是业务批准。
2. **维护获授权表达。** 讨论只解释判断、依据与未知，当轮直接消费 Entity 的名称和定义及属性含义，复用已有规范映射，含义明确且缺英文时直接翻译，不等待人类提供英文；讨论不授权模型 JSON 编辑，显示翻译不自动改写既有源标签或标识。正式编辑按流程映射来源，主要责任梳理与请求—确认识别合为同一动作；配对后包裹履约，单端凭证不建空履约；Context 与真实业务内容共同保存，不建空上下文，最小内容按[责任方法](references/responsibility-closure.md)核对。直接编辑当前模型及 Entity/属性定义并核对差异；校验分支直接进入 Sensors。完成时，本轮增改删及定义拥有者清楚，未知与限制按实际保留。
3. **检查并交付。** 讨论只交接解释；需要校验的分支执行 Sensors 的适用检查。每批修改检查当前图的一致性并报告完整性缺口；范围结束时使用 `--scope` 检查完整性和适用场景，交接模型根、明确范围与依赖、实际差异及同一次有效结果；独立调用只交付 FM，不自动设计 API。来自 Modeling 时返回入口，由其按授权委派 `evidence-api`，交接后停止。完成时，获授权文件、检查与未覆盖能力均可定位，未完成阶段单独报告。

## Sensors

设置实际绝对路径和已满足依赖的 Python，读取校验纪律后执行：

```bash
"$PYTHON" -B "$FM_SKILL_DIR/scripts/check_fm.py" "$FM_ROOT" > "$FM_CHECK_FILE"
```

模型每批编辑后运行一次一致性检查；范围结束时以 `--scope "$CONTEXT_ID"` 显式检查整个独立范围及必要依赖。`consistent`、`complete` 与模拟结果分别报告，只有 `complete: true` 的当前范围结果可用于获授权下游。语言讨论不增加独立检查。`FM_CHECK_FILE` 是模型目录之外的临时 JSON，只读请求使用项目外临时目录。先核对退出码与内容，失败不接续；已有有效结果直接交接，API 不重复 FM 检查或模拟。

分别报告定义归属／引用、Schema、CEL、lineage、simulation、timeline 的实际结果。`modelDigest` 绑定输入，`inputChanged: true` 使结果失效；未执行场景时 `simulationPassed: null`。模型、场景或校验器变化后重新检查。

范围完整性检查结果可交给独立的 `evidence-api` 消费；API 技术校验由该包维护。机器通过不等于业务批准。

## Steer

- **表达错误**：在当前授权内修正并复验。
- **新责任、来源冲突、身份／权限／数量缺口或确认失效**：停止受影响阶段，交接具体对象与缺口；不自行提问或解除访谈停止／暂缓。
- **环境或保存失败**：保留错误与已改文件，不自动安装依赖，不自动回滚；分别说明已保存、未通过与未执行。
- **FM 摘要失配**：按本轮检查授权重新核对当前 FM，交接有效结果；下游失败不撤销已保存 FM。
- **完成**：报告实际差异、来源定位、检查和未决项后停止。独立调用不自动生成页面；另行要求时定位 `evidence-visualization`，来自 `evidence-modeling` 时交回入口。需求、实施、批准和 Git 操作保持各自授权边界。
