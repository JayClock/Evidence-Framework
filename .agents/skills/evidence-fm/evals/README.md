# FM 生成与行为评测

本目录与运行脚本、schemas、测试一起随 Skill 维护，可单独复制使用。评测输入不是业务来源或已通过报告。

## 案例分支

- [evals.json](evals.json)：FM 技术生成／修复、不适用及阻塞案例，供 `run_modeling_evals.py` 准备或评分。`outcome` 分别为 `model`、`not-applicable`、`blocked`；模型案例明确仅 FM 授权，不触发 API 或页面。正向案例附有[合成准入来源](fixtures/modeling-admission.md)，先核对对应合同级或分支准入、责任图、人类终点及适用结束原话，声称整体结束时才另核对全局确认；缺口仍须阻塞，合成确认不覆盖实际遗漏。
- [behavior.json](behavior.json)：独立行为案例 4、9、29、30、31、32，检查同合同未决责任阻止切片建模、独立领域或合同满足自身准入后先建模、不以无关合同或全局确认阻塞、领域自身准入缺失，以及外部能力、不同确认类型与凭证责任的只读讨论。由独立会话和人工逐项检查，不交给技术产物评分器。
- [domain-language.json](domain-language.json)：日常表达案例，检查跨问答、故事、任务、测试与交接的规范名称一致性，同名异义、只读缺词及保留既有标识的边界。按实际消费场景加载相应 Skill 和同一版本的领域语言方法，由独立会话评价，不交给 FM 技术产物评分器。

各分支保留原 ID，不混作同一编号空间。API 行为评测由独立的 `evidence-api` 维护，不交给 FM 技术产物评分器；没有实际执行不记为通过。

按 `outcome` 选择评分路径：`model` 检查 Schema v4、确定性编译、履约合同归属、成员、请求区间、CEL、角色及场景；纯领域不强求非空履约。`blocked` 检查缺口说明及没有正式或局部 FM 产物，不能因生成有效模型且无审核状态而通过；`not-applicable` 检查有依据的不建模说明。案例 13、16 的缺口说明作为评测输出保存为 Markdown，不要求任何项目 discovery 目录或固定问题记录。技术评分器检查已生成产物，不认证人类身份或证明准入核对实际发生；是否遵守合同级或相应分支门槛及适用全局结束要求，须另按行为案例及原始交互评价。候选复用、被支持的复用与人工确认分开。

角色身份只按来源明确程度映射：来源明确具体玩家才建 Participant + plays_role，仅有上下文身份则保留 Role。人仍须审核领域身份、关系、目标批准与及时回应的区别，以及简单胶水是否隐藏了领域规则。机器通过不证明业务语义完整。

## 本地运行

先使用满足本包 `requirements.txt` 的 Python 3.10+ 环境，将 `SKILL_DIR`、`PYTHON`、`WORKSPACE` 设置为实际绝对路径。输出目录须获授权，不覆盖真实业务模型。

```bash
# 只准备输入，不调用 Agent，也不代表评测通过
"$PYTHON" "$SKILL_DIR/evals/run_modeling_evals.py" --workspace "$WORKSPACE" --prepare-only

# 使用实际可用的外部 Agent 命令；含空格的路径须在模板中加引号
"$PYTHON" "$SKILL_DIR/evals/run_modeling_evals.py" --workspace "$WORKSPACE" --only 11,12,13,14 \
  --command-template 'agent-cli --prompt-file "{prompt_file}" --output "{output_dir}"'

# 评分已有输出
"$PYTHON" "$SKILL_DIR/evals/run_modeling_evals.py" --workspace "$WORKSPACE" --grade-only

# 本包确定性回归，不是 Agent 行为评测
"$PYTHON" -B -m unittest discover -s "$SKILL_DIR/tests" -v
```

案例 files 相对本目录解析，夹具位于 `fixtures/`，与调用目录无关；prompt 直接使用当前 Skill 名称，不做调用名替换。外部命令经分词后执行，不经过 shell；工作目录为指定 WORKSPACE。模板可用 skill_dir、workspace、eval_dir、input_dir、output_dir、prompt_file、eval_id、eval_name。未指定输出目录时使用调用目录下的 evidence-fm-workspace/iteration-1。

[测试样例](../tests/context_samples.py) 在临时目录构造纯领域、合同前、混合与 KPI 合成模型。测试覆盖编译、lineage、约束反例和评分器负例；直接计算 CEL 真值不是单据模拟或领域状态机执行。

## 行为评价

为 behavior.json 使用独立临时项目和会话，只安装本 Skill；同一模型与输入分别运行有 Skill／无 Skill 或新旧版本，不共享答案。缺少必要业务依据时观察是否只返回具体缺口，不自动进入访谈。后续补充由真人按案例给出，保存对话、文件 diff 和逐条 expectations 的原文依据及通过／失败／未评结论，不让 Agent 自答。

案例 13 保留五类结算缺口，案例 16 保留合同前事实及截止依据缺口；两者未取得人类追责结束依据时均不生成任何正式模型、规则或场景，只交接缺口，不自行访谈。评分器只观察指定输出目录，项目文件是否未变、是否提问及是否真实核对准入仍须用执行轨迹和文件前后差异判定。合成准入来源不用于缺口案例 13、16；这些案例不能借其他案例的结束原话放行。自动输入准备或技术产物评分不替代这项人工行为判定。

日常表达案例检查实际输出与文件差异，逐项区分完整中文（英文）规范名称、输入别名、上下文及未保存内容。案例 0 至 2 核对日常表达、同名异义、含义歧义与只读边界；案例 6 核对缺英文直接翻译、复用已有映射及获授权后保存；3 至 5 核对两种语言指向同一身份、上下文名称与 ID 对齐、定义唯一归属及正式归位权限、别名歧义和法定名称保留。结构回归只证明消费入口和案例仍可达，不证明 Agent 表达质量；后续输入由真人给出，Agent 不自答。

没有实际运行就标未执行，不填写通过率、token 收益或行为保证。业务审核、模型校验、单据模拟及生成质量是独立结论；不能为了通过评分改变既有预期。
