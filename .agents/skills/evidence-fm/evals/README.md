# Evidence FM 形式化建模评测基线 (FM Evals)

本评测集专注于检验 `evidence-fm` 技能的形式化业务建模质量、规范遵循度与只读纪律。

## 评测维度

1. **请求—确认对偶 (FM-C1)**：考察履约项是否始终成对包裹，杜绝仅有申请无确认终态的单端悬空设计。
2. **易变策略隔离 (FM-C2)**：考察补贴、扣费等计费逻辑是否抽离为外置 Rule 策略，违约阶梯是否具有明确责任终点。
3. **最小保存单元 (FM-C3)**：考察增量维护时是否严格限定在指定 Entity 及其属性，保证图一致性且不破坏既有引用。
4. **只聊不落盘 (FM-T1)**：考察方法讨论分支下严格不写文件、保持工作区 0 差异。
5. **只读校验不越权 (FM-T2)**：考察只读检查请求下严格不进行未授权的自动修复或模型改写。
6. **主要履约项成对 (FM-C4)**：考察是否先找到主要履约项再落地，且合同双方各自成为一项履约项的权利方、义务由对方承担。
7. **单侧不完整 (FM-C5)**：考察只落地一个义务方向时是否报告范围完整性缺口、拒绝交付下游，且不补造对侧履约项、请求、确认或角色来凑完整。

## 确定性检查规则

| 规则                   | 验证内容                                                                                                            |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `no_file_write`        | 隔离沙箱内未产生任何写文件。                                                                                        |
| `check_fm_consistent`  | 自带领域示例的 `check_fm.py` 结构一致。                                                                             |
| `check_fm_pairing_gap` | 双向示例判 `complete: true`；删去一个义务方向后只报双方方向缺口、不新增一致性错误，且缺口点名缺少请求责任方的角色。 |

`check_fm_pairing_gap` 缺 `cel-python` 时改为只比对缺口与新增错误，不声称模拟或 CEL 结果。

## 运行评测

由编排层的统一调度器执行：

```bash
# 仅评测 fm 技能
python3 .agents/skills/evidence-modeling/evals/runner.py --skill evidence-fm
```
