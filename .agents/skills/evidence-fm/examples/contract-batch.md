# 合同级建模与未澄清外部边界

这是合成表达样例，不提供真实人类准入或编辑授权。当前服务合同已核对全部主履约、各层异常、必要证明、终点与实际推演，并有人类单合同结束确认；关联运输合同的内部权责尚未澄清，仍保留在整体范围中。

## 1. 只表达消费方已知边界

当前服务合同上下文为 `context.agreement`。其所需运输协作边界已明确，使用尚无玩家的 Context Role：

```json
{
  "type": "entity",
  "id": "role.transport-context",
  "category": "role",
  "kind": "context",
  "label": "运输协作（Transport Collaboration）",
  "contextRef": "context.agreement",
  "notes": "当前服务合同所需的运输协作边界；运输合同内部履约与异常责任尚未澄清，见本轮交接。该角色不证明送达。"
}
```

不创建虚构运输 Contract、Contract Context、内部履约或 `plays_role`。当前合同的交付确认及其依据仍按已明确事实表达；如果送达证明的责任、形成依据或采信条件未知，当前合同也不满足准入，不能用此角色替代证明。

## 2. 交接未澄清部分

FM 返回实际文件、角色 ID、检查结果及限制，组合入口调用 Handoff 保存运输合同的已知约定与责任双方、未决责任、原问题、暂缓意图和恢复位置。合同级确认只覆盖服务合同；运输合同尚未结束，也不宣称全局追责结束。交接只引用词汇表、正式模型与原有记录，不复制定义或建立第二份问题状态。

## 3. 后续接入

运输合同闭合且有编辑授权后，保留 `role.transport-context`，通过实际 Context 的 `plays_role` 接入，检查来源、跨合同关联及服务合同确认是否仍适用。已有模型不自动删除，未变化的合同不重复生成；具体证明需要角色化时仍使用 Evidence Role，而不是 Context Role。

回归使用当前模型校验器验证无玩家角色合法、凭证不能引用该角色、它不能补齐履约确认，以及真实 Context 玩家接入后角色身份不变。机器检查不证明合同闭合或 Agent 自动接续成功。
