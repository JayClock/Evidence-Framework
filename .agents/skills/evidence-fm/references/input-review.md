# 建模输入复核

消费外部说明、访谈记录或现有模型修订要求，先核对追责结束准入，再判断正式表达。这里只复核依据、返回具体缺口，不内置访谈流程。

## 1. 核对追责结束与授权

按 [全部追责结束](responsibility-closure.md) 读取人类定义的范围、所有主履约及各层异常、终点确认、未决问题与人类全局结束原话。确认覆盖当前材料和责任图版本；直接编辑请求、已有 JSON 或外部充分说明都不能替代这些依据。

任一责任分支未闭合、终点未经人类确认、全局结束确认缺失或失效时，不生成或修改模型、规则、验证场景及对应词汇引用。保留现有文件，交接缺口；不通过拆分主履约、缩小范围或只编已知部分放行。只读校验、未建模术语沉淀与明确不生成模型的分析按各自权限执行，不宣称建模准入已满足。

## 2. 核对来源与正式映射

门槛满足后，读取来源版本、必要原文、统一词汇表、已有模型与案例 ID、问题状态及最新更正。按 [领域语言方法](domain-language.md) 解析定义拥有者：standalone 提供未建模概念，model 引用当前 FM 的唯一名称和含义；新更正与目标冲突时先保存来源与影响，不在词汇表覆盖模型定义。发现记录是业务依据，不是可直接复制的正式模型。

按 [业务判断准则](business-analysis.md)、[来源追溯](provenance.md) 和 [场景校验](scenario-validation.md) 核对业务结构、全部关键数据及预期，再按 [批次评估](batch-assessment.md) 建立事实到对象、属性、规则和场景的映射。已知事实复用，确定性推导保留适用条件。

业务责任仍未知或出现新分支时返回准入核对，不开始局部编辑。业务已明确而仅缺 JSON／CEL 表达时由 FM 处理；表达能力或技术验证缺口如实交接，不倒改业务规则制造通过。

## 3. 返回缺口与恢复

复用原问题／对象标识，列出来源、已有事实、尚不能作出的判断、受影响分支及所需依据；区分责任闭合缺口与技术表达限制，不代造回答。

缺口交给访谈任务。是否恢复澄清由人类决定；未安装访谈能力时仍可输出缺口并停止，不复制另一套访谈机制，不自动恢复已停止的讨论。

补充材料到达后重新核对范围、全局追责结束确认的新鲜度及既有编辑授权。业务变更不被旧确认覆盖时，须重新完成受影响分支并取得覆盖当前整体的人类确认；历史原话与现有模型保留。
