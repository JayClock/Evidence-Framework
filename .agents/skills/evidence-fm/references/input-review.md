# 建模输入复核

消费外部说明、访谈记录或现有模型修订要求，判断本批次能生成什么。这里只输出可用事实、依赖和缺口，不内置访谈流程。

## 1. 核对已有依据

读取来源版本、必要原文、已有模型与案例 ID、问题状态及最新更正。访谈中的术语、关系和案例是工作材料，不直接当作已确认的正式模型；重复内容引用来源，不再复制一套记录。

按 [业务判断准则](business-analysis.md) 识别相关结构，按 [来源追溯](./provenance.md) 核对全部关键数据，按 [场景校验](scenario-validation.md) 检查已有预期。明确事实可复用，规则充分可确定性推导，冲突与局部未知原样保留。

## 2. 判断能纳入什么

采用 [批次评估](batch-assessment.md)，以本职责实际必要事实为界：

- 依据充分的部分可生成，支撑事实只纳入实际被消费的投影。
- 业务已知而仅缺类型展开、YAML 或 CEL 表达时，由 FM 完成，不转成业务问题。
- 必要业务依据仍缺失时，将受影响事实留为 pending；不为产出删掉必需规则，也不让不相关未知阻塞整个模型。
- 没有可纳入职责时保存评估与原因，保留已有模型，不虚构无责任或不适用。

## 3. 返回具体缺口

复用原问题／对象标识，列出原始来源、已有事实、不能作出的判断、受影响职责及所需依据。其余未知留在说明，不生成预排问题清单，不代造用户回答。

缺口交给访谈任务处理；用户选择继续澄清后可使用 `evidence-discovery`，由它决定当前问题及交互状态。本包未安装访谈能力时仍可输出缺口并停止，不临时复制一套访谈机制，不自动恢复已停止的讨论。

补充材料到达后重新核对事实依赖和既有授权；只有仍有效的生成／更新请求才继续对应产物操作。未知、暂缓、停止和有依据的排除不是同一状态，也不能用字段存在或机器通过替代业务依据。
