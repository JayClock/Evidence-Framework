# 建模输入复核

消费外部说明、当前业务理解或现有模型修订要求，先核对追责结束准入，再判断正式表达。这里只复核依据、返回具体缺口，不内置访谈流程。

## 1. 核对追责结束与授权

按 [追责结束准入](responsibility-closure.md) 读取整体范围、本轮合同或合同组的全部主履约及各层异常、终点确认、未决问题与合同级人类结束确认；声称整体结束时另核对全局确认。独立领域或协商消费相应分支的范围、规则／方案、关联责任、正常反例及人类分支结束确认；满足自身准入后可先建模，不等待无关合同或全局追责结束。确认覆盖当前材料和责任图版本；直接编辑请求、已有 JSON 或外部充分说明都不能替代这些依据。

当前合同的必要责任分支未闭合、终点未经人类确认、合同级结束确认缺失或失效时，不生成或修改该范围的模型、规则、验证场景及对应词汇引用。保留现有文件，交接缺口；不通过拆分同一合同主履约或只编已知部分放行。其他未澄清合同按 [语义](semantics.md) 使用 Context Role，未决内部责任交接，不要求无关合同全部结束；必要外部证明未知仍阻塞当前合同。只读校验、未建模术语沉淀与明确不生成模型的分析按各自权限执行，不宣称建模准入已满足。

## 2. 核对来源与正式映射

门槛满足后，读取来源版本、必要原文、统一词汇表、已有模型与案例 ID、问题状态及最新更正。按 [领域语言方法](domain-language.md) 解析定义拥有者：standalone 提供未建模概念，model 引用当前 FM 的唯一名称和含义；新更正与目标冲突时先说明受影响判断，不在词汇表覆盖模型定义。访谈形成的共同理解提供业务依据，不是可直接复制的正式模型。

按 [业务判断准则](business-analysis.md)、[来源追溯](provenance.md) 和 [场景校验](scenario-validation.md) 复核约定与责任双方、主要履约及沿凭证发现的协作关系，再核对完整责任图、全部关键数据及预期；不能仅凭已有 Context 或双方 Role 齐全跳过识别。按 [批次评估](batch-assessment.md) 建立事实到对象、属性、规则和场景的映射。已知事实复用，确定性推导保留适用条件。

本轮合同的必要业务责任仍未知或出现影响本轮的新分支时返回准入核对，不开始局部履约编辑；其他合同内部未决项按合同级边界交接。业务已明确而仅缺 JSON／CEL 表达时由 FM 处理；表达能力或技术验证缺口如实交接，不倒改业务规则制造通过。

## 3. 返回缺口与恢复

复用原问题／对象标识，列出来源、已有事实、尚不能作出的判断、受影响分支及所需依据；区分责任闭合缺口与技术表达限制，不代造回答。

缺口交给访谈任务。是否恢复澄清由人类决定；未安装访谈能力时仍可输出缺口并停止，不复制另一套访谈机制，不自动恢复已停止的讨论。

补充材料到达后重新核对范围、合同级及适用全局追责结束确认的新鲜度与既有编辑授权。业务变更不被旧确认覆盖时，须重新完成受影响分支并取得覆盖受影响合同或合同组的人类确认；声称整体结束时另取全局确认。历史原话、已有 Context Role ID 与现有模型保留。
