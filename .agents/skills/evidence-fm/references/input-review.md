# 建模输入复核

消费外部说明、当前理解或修订要求，核对业务依据、编辑权限及事实冲突，不内置访谈流程。FM 随理解持续生长，不以追责结束阻止首次保存。

## 1. 权限与当前依据

读取当前目标、允许文件、实际来源及版本、已有模型与 Git 差异。纯讨论、只读、仅访谈、只保存资料、不生成模型或停止等限制优先；已有相同编辑授权无需每轮重新申请。

按 [业务分析](business-analysis.md) 核对现金权责或目标—实际对比、实际约定、责任双方、主要履约及沿凭证发现的协作。能够确定的内容可渐进表达，未知不猜测；已有 Context 或 Role 不代替业务判断。

## 2. 最小表达与一致性

按 [责任方法](responsibility-closure.md) 让凭证与责任角色及所属上下文一起落地：普通凭证有责任角色，合同有双方责任角色；已有角色复用，实际主体未知不造 Participant，责任角色未知暂不写凭证。经办人与证明提供方不替代合同方。

按 [领域语言](domain-language.md) 直接核对 Entity/属性名称与含义，缺英文按明确含义翻译，不另存定义。对象、属性、关系、规则和履约按当前问题共同生长；未明确的类型、必填性、时间参数或规则保留缺失，不能以占位 ID 或恒真规则冒充事实。

按 [批次评估](batch-assessment.md) 映射来源与稳定 ID；新更正先说明受影响判断，保存有依据的变化并检查当前完整图一致性。错误引用、非法 CEL、矛盾、依赖环与凭证缺责任归属不是完整性缺口，不因渐进建模放行。

## 3. 范围结束与缺口

仅在范围结束或下游交付时，按责任方法核对合同完整主履约、各层异常、终点、完整责任图、推演及人类结束确认，执行显式范围完整性检查。领域／协商按实际独立范围核对规则／方案、关联责任与正常反例，不补造合同。全局结束另取人类确认，不阻塞无关独立范围。

必要未知只阻塞受影响范围的完整性与下游，不撤销已知事实保存权限。复用原问题／对象标识，交接已有事实、来源、尚不能作出的判断与所需依据；不建立第二份问题记录，不自行提问或恢复停止状态。

补充材料或更正使受影响的旧检查、人类确认与下游结果失效，继续维护已知模型，再核对受影响范围的新版本与结束确认。历史证据保留，不自动删除或回滚；表达与运行限制如实报告，不倒改业务预期制造通过。
