# 表达模式选择

本页只帮助选择已有方法，不定义字段、关系种类或新的建模规则。结构直接读取 [Schema 入口](format.md#结构契约)，对象含义看 [语义](semantics.md)，业务分析与范围判断回到各自方法。

## 按当前问题选择

| 当前问题                                     | 表达模式                                                                                             | 注意边界                                             |
| -------------------------------------------- | ---------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| 合同责任、请求、确认和派生规则怎样组合       | 每个主要义务成对落成请求与确认，确认只看已完成结果，派生规则绑定已建模属性                           | 双向覆盖不等于整份合同责任已经结束                   |
| 领域身份与行为条件怎样表达                   | 对象身份与属性直接归领域 Entity，行为条件落成读取该实体属性的 Rule                                   | 不补造合同，静态通过不证明领域操作已执行             |
| 同合同引用、共享结果与跨上下文证明有什么区别 | 同合同引用只指向本合同对象；跨上下文结果经 Evidence Role 声明采信，具体凭据留在提供方上下文          | 分组不是上下文边界，类型线不是实例完成证明           |
| 当前合同怎样保留未澄清协作边界               | 用尚无玩家的 Context Role 记录所需能力与未知，不虚构合同、内部履约或玩家                             | 边界角色不补齐必要证明，也不制造外部合同事实         |
| 业务宏流程与核心业务模式怎样提炼沉淀         | 对比业务变体共性规律（如周期订阅、配额扣减、兑换核销），将易变能力抽象为角色，沉淀核心模式           | 模式提炼不改变具体合同上下文的权责边界               |
| 业务名称、别名和同名异义怎样使用             | 消费当前 Entity 的 `label` 与 `aliases`，输出统一回规范名称，同名异义保留歧义                        | 讨论中的翻译不自动修改模型或接口                     |
| 规则怎样绑定已有对象并判断结果               | 绑定把变量对应到已建模对象或明确输入，表达式只做确定性计算与判断                                     | 规则参数不能变成当前业务默认值                       |

## 没有现成模式时

先按 [业务分析](business-analysis.md) 或 [领域建模](domain-modeling.md) 判断实际含义，再在当前契约内表达，不根据某个模式是否存在决定业务是否成立。绩效与目标—实际、协商、取消退款、补偿和工具集成均按真实责任分析，不在此增加固定流水线或默认条款。

需要可运行回归样例时，只维护一份模型源及必要场景，放在 `tests/fixtures/` 由测试消费；它不进入提示词，也不构成业务依据或编辑授权。用临时副本验证反例，不覆盖来源预期。检查方法见 [校验纪律](validation.md)。
