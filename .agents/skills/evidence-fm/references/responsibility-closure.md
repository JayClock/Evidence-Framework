# 合同级与全部追责结束：正式建模准入

本页唯一维护责任闭合的方法与建模门槛。访谈任务负责选题、等待、理解更新和控制状态；FM 输入复核消费这里规定的依据，不自行发起问答。追责结束是责任及其后果已经查清，不是等待现实中的争议处理完。

## 1. 人类定义范围，先找齐所有主履约

从经营目标、适用合约、专家说明及真实凭证识别本次业务涉及的上下文、双方和所有主履约。有条件才发生的义务、完成后继续产生的义务也须纳入，不能只列正常操作。

保留整体业务范围及全部合同清单，同时明确本轮建模的合同或相互依赖的合同组。合同级准入以独立责任边界为单元，不要求无关合同同时澄清；未澄清合同继续保留为未决，不从整体范围删除。

范围与主履约清单由人类定义或明确确认，核对确认覆盖的范围及适用业务版本。Agent 可以展示候选和遗漏风险，不能自行缩小范围、以实现切片替代业务范围，或为了放行排除退款、赔付、兄弟义务。外部支撑业务按已确认边界处理，保留本范围所消费的责任与证明；第三方接手不等于责任结束。

## 2. 所有主履约及各层异常逐枝递归

每项主履约和异常新义务都按 [业务分析](business-analysis.md) 先画请求—确认骨架，再追溯约定依据、期限、完成证明与采信规则，然后检查全部适用异常：逾期、拒绝、部分完成、结果不符等。骨架允许显露局部未知，但正式准入仍要求必要责任依据全部明确。适用性和不适用理由也须有依据，不用固定题库替代分析。

```text
主履约 → 异常触发与依据 → 新履约及其请求、期限、完成证明
                                  ↓
                         新履约仍不完成怎么办
                                  ↓
                  继续展开全部分支 → 人类确认的责任终点
```

优先把当前分支追到终点，再回到兄弟分支与下一项主履约；材料或身份依赖需要切换时说明原因。不限制递归深度，不能找到一项退款或赔付就停止；每个新增义务仍须检查其各层异常。相同义务可以复用记录及来源，但不能用循环引用伪装终点。

完整核对本范围主履约清单、责任图、当前分支和剩余缺口。日常进度只展示当前业务节点，不每轮展开全局；需要人类范围或全部追责结束确认时，单独核对并展示其覆盖的完整版本。已知事实直接复用；未检查、待答、暂缓、冲突及来源失效的分支都保留为未决，不能在记录中隐藏兄弟分支。正常和争议单据推演检验当时的凭证能否支持判断，暴露新责任或证明缺口就回到原分支继续追查；案例结果纳入当前业务理解，核对真实推演及所用依据。

## 3. 人类决定终点，不能以“找不到”替代

终点须有适用约定或专家说明，并有可定位的人类确认：

- 法律救济／终极履约：人类确认该分支已到法律处理边界。保留责任及依据，不自动扩成诉讼管理软件，也不自动认定所有异常最终都走诉讼。
- 按约终止且没有后续义务：人类确认不存在追加责任。若无需另一方确认就自动终止，保存终止依据，不补造独立履约；仍有退款等义务时不得称为终点。

Agent 只提出候选解释，不代替人类裁决，不凭业务常识补造罚息、赔偿或终点。“外部处理”“范围外”“不知道”“没材料”“再也想不出”均不是终点依据。确认一条分支不代表其他分支已经闭合。

## 4. 核对追责结束门槛

正式 FM 的生成、修改、修复、术语落实为模型及验证场景编辑，都先核对适用范围的门槛；直接调用 FM、输入外部充分材料或修改既有模型不构成豁免。

### 合同级准入

一个合同澄清完毕后，可以独立进入建模；责任无法独立判断的多个合同作为一组核对。进入前须同时满足：

1. 本轮合同边界、约定与当前合同的全部主履约清单有明确来源和人类确认，整体范围中的其他合同仍保留。
2. 当前合同所有主履约及各层异常已检查并递归展开；每项新履约的必要权责、期限、完成证明和判断依据明确。
3. 当前合同所有分支到达人类确认、有依据的责任终点；没有未检查、待答、暂缓、冲突或失效的必要责任依据。
4. 当前合同完整责任图与适用单据推演已经核对，实际结果与未执行项分别记录，没有遗留责任判断缺口。
5. 人类明确确认当前合同澄清结束，该确认覆盖上述清单、责任图、终点及推演的适用业务版本；本轮生成权限另行核对。

相关未澄清合同使用 Context Role 表达当前合同所需的外部边界，具体表达按 [语义](semantics.md)。当前合同消费的证明含义、责任、形成依据、匹配与采信条件仍须明确；不能以 Context Role 隐藏当前合同的必要责任或证明缺口，也不能用“外部处理”代替责任终点。对方内部履约未展开本身不阻塞，影响当前判断的未知才阻塞受影响合同或合同组。

单条终点确认、问题组答完、编辑请求、用户沉默、文件存在或机器通过均不替代当前合同结束确认。不能把同一合同的付款和退款拆开，只放行付款；不能把该合同尚未闭合的异常改成外部合同来绕过门槛。

### 全局追责结束

本范围全部合同都闭合后，仍单独核对完整责任图、跨合同关联与整体推演，等待人类明确确认全部追责结束。该确认覆盖整体业务版本，用于说明整体澄清结束，不作为已闭合独立合同的前置等待条件。合同级交付不宣称整体范围已经结束，Context Role 不代表其对应合同已澄清或批准。

停止或暂缓不等于追责结束。人类可以随时停止问答，但未满足的合同级或全局门槛保持未满足，不自动恢复访谈。缺少专业资源或记录保存失败同样不能放行受影响写入。

纯领域、独立合同前或简单胶水不补造合同和履约：展示实际范围及依据，由人类明确确认本范围没有适用履约责任、无需继续追责，才可按相应建模分支处理。Agent 不能仅凭“没有合同”或空清单自动豁免。明确不生成模型的分析、术语沉淀和只读校验不要求先完成建模准入；只读结果不证明责任闭合。

## 5. 承接、复核与变化

进入或恢复正式编辑时，消费提供的业务材料、当前完整理解及人类明确决定，逐项核对：

- 人类确认的范围与全部主履约清单，区分整体清单与本轮合同或合同组。
- 支撑本轮判断的约定、专家说明与适用版本。
- 本轮合同或合同组的全部主履约、异常检查、分支结构及实际推演。
- 各分支的人类终点决定及其约定依据；同一决定覆盖多条分支时，明确全部覆盖范围。
- 所有未检查、待答、暂缓、冲突或失效的责任判断及所属合同，区分当前必要缺口与其他合同内部未决项。
- 本轮合同级结束确认及所覆盖版本；声称整体结束时另需人类明确确认全部追责结束及其覆盖的整体业务版本。
- 未澄清合同及其 Context Role、当前合同所消费的证明约定与未决依赖。

核对结论须来自明确的人类决定与实际业务理解，确认载体采用本次提供的形式。缺少任一必要内容时交接具体缺口，不能以完成标记或局部摘要放行。

恢复与模型编辑前重新核对材料及确认适用性。新增主履约、异常分支、范围变化或约定更正后，旧确认不覆盖新内容；说明失效影响，重新完成受影响分支并取得覆盖受影响合同或合同组的人类结束确认；声称整体结束时重新取得全局确认。纯技术表达修正未改变已确认业务时可以引用仍适用的确认，不重复访谈。已有模型和历史证据保留，不自动删除、回滚或追认其已满足门槛。

追责结束、编辑授权、机器检查和业务批准分别说明。该门槛只决定是否能进入正式建模，不批准生成后的模型；追责结束确认本身不授权 API、需求或交付。来自获授权建模访谈的单合同结束信号时，由组合入口接续正式建模及未澄清部分的 Handoff；专业准入只交接依据，不自行编排。已获一体生成授权时，FM 通过后由组合入口接续 API 与联合审核，不以门槛替代本次编辑授权。
