# 全部追责结束：正式建模准入

本页唯一维护责任闭合的方法与建模门槛。访谈任务负责选题、等待、保存和控制状态；FM 输入复核消费这里规定的依据，不自行发起问答。追责结束是责任及其后果已经查清，不是等待现实中的争议处理完。

## 1. 人类定义范围，先找齐所有主履约

从经营目标、适用合约、专家说明及真实凭证识别本次业务涉及的上下文、双方和所有主履约。有条件才发生的义务、完成后继续产生的义务也须纳入，不能只列正常操作。

范围与主履约清单由人类定义或明确确认，保存原话、适用版本和定位。Agent 可以展示候选和遗漏风险，不能自行缩小范围、以实现切片替代业务范围，或为了放行排除退款、赔付、兄弟义务。外部支撑业务按已确认边界处理，保留本范围所消费的责任与证明；第三方接手不等于责任结束。

## 2. 所有主履约及各层异常逐枝递归

每项主履约和异常新义务都按 [业务分析](business-analysis.md) 先画请求—确认骨架，再追溯约定依据、期限、完成证明与采信规则，然后检查全部适用异常：逾期、拒绝、部分完成、结果不符等。骨架允许显露局部未知，但正式准入仍要求必要责任依据全部明确。适用性和不适用理由也须有依据，不用固定题库替代分析。

```text
主履约 → 异常触发与依据 → 新履约及其请求、期限、完成证明
                                  ↓
                         新履约仍不完成怎么办
                                  ↓
                  继续展开全部分支 → 人类确认的责任终点
```

优先把当前分支追到终点，再回到兄弟分支与下一项主履约；材料或身份依赖需要切换时说明原因。不限制递归深度，不能找到一项退款或赔付就停止；每个新增义务仍须检查其各层异常。相同义务可以复用记录及来源，但不能用循环引用伪装终点。

每轮展示本范围主履约清单、已有责任图、当前分支和剩余缺口。已知事实直接复用；未检查、待答、暂缓、冲突及来源失效的分支都保留为未决，不能隐藏兄弟分支。正常和争议单据推演检验当时的凭证能否支持判断，暴露新责任或证明缺口就回到原分支继续追查；案例结果引用已有发现记录，不创建第二份案例集。

## 3. 人类决定终点，不能以“找不到”替代

终点须有适用约定或专家说明，并有可定位的人类确认：

- 法律救济／终极履约：人类确认该分支已到法律处理边界。保留责任及依据，不自动扩成诉讼管理软件，也不自动认定所有异常最终都走诉讼。
- 按约终止且没有后续义务：人类确认不存在追加责任。若无需另一方确认就自动终止，保存终止依据，不补造独立履约；仍有退款等义务时不得称为终点。

Agent 只提出候选解释，不代替人类裁决，不凭业务常识补造罚息、赔偿或终点。“外部处理”“范围外”“不知道”“没材料”“再也想不出”均不是终点依据。确认一条分支不代表其他分支已经闭合。

## 4. 核对追责结束门槛

正式 FM 的生成、修改、修复、术语落实为模型及验证场景编辑，都先核对同一门槛；直接调用 FM、输入外部充分材料或修改既有模型不构成豁免。

进入建模前须同时满足：

1. 本次范围、约定与所有主履约清单有明确来源和人类确认。
2. 所有主履约及各层异常已检查并递归展开；每项新履约的必要权责、期限、完成证明和判断依据明确。
3. 所有分支到达人类确认、有依据的责任终点；没有未检查、待答、暂缓、冲突或失效的责任依据。
4. 完整责任图与适用单据推演已经核对，实际结果与未执行项分别记录，没有遗留责任判断缺口。
5. 人类明确确认全部追责结束，原话引用当前范围、主履约清单、责任图、终点及推演的可恢复版本。

只有以上依据均成立，才能核对本次编辑授权并进入正式建模。单条终点确认、编辑请求、用户沉默、文件存在或机器校验通过都不能替代全局确认；即使人类说“结束了”，记录仍有未决分支也不能放行。

停止或暂缓不等于追责结束。人类可以随时停止问答，但门槛保持未满足，不自动恢复访谈，不写正式模型。缺少专业资源或记录保存失败同样不能放行。

纯领域、独立合同前或简单胶水不补造合同和履约：展示实际范围及依据，由人类明确确认本范围没有适用履约责任、无需继续追责，才可按相应建模分支处理。Agent 不能仅凭“没有合同”或空清单自动豁免。明确不生成模型的分析、术语沉淀和只读校验不要求先完成建模准入；只读结果不证明责任闭合。

## 5. 保存、恢复与变化

在项目已有发现记录中维护范围、主履约、各分支及终点的稳定定位与来源。默认使用 discovery 的 `business.responsibilityClosure` 汇总约定、履约、异常检查与推演的稳定引用；不另建隐藏状态、不在 FM 保存 `status` 或 `approved`，也不以手填布尔值替代依据。词汇名称与定义仍由 Glossary 或已有 FM 唯一维护。

- `scope`／`scopeSourceRefs`：人类确认的范围及来源。
- `basisRefs`：约定、专家说明和版本。
- `mainFulfillmentRefs`／`chainRefs`：发现记录中全部主履约、异常检查、分支结构及推演的稳定引用；无正式模型时使用记录定位，不编造 Entity ID。
- `terminalDecisions`：分支引用、终点解释、约定依据与 `humanSourceRefs`。同一终点可覆盖多条分支，但须明确覆盖范围。
- `unresolvedRefs`：全部未决分支及问题引用；核对当前内容，不能靠删除引用清空缺口。
- `completionSourceRefs`：人类明确确认全部追责结束的原话，以及它所覆盖的记录版本；未取得时省略，不代造回答。

恢复与模型编辑前重新核对实际记录及其来源。新增主履约、异常分支、范围变化或约定更正后，旧确认不覆盖新内容；保留历史原话与失效影响，重新完成受影响分支并取得覆盖当前整体的人类结束确认。纯技术表达修正未改变已确认业务时可以引用仍适用的确认，不重复访谈。已有模型和历史证据保留，不自动删除、回滚或追认其已满足门槛。

追责结束、编辑授权、机器检查和业务批准分别说明。该门槛只决定是否能进入正式建模，不批准生成后的模型，也不自动启动 API、需求或交付。
