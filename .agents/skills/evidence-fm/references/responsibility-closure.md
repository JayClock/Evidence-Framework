# 责任范围结束与下游交付

本页唯一维护范围完整性与人类结束确认，不把追责结束作为首次写入 FM 的条件。FM 是一份随讨论、凭证追溯和推演持续生长的模型；有业务依据和编辑授权即可维护已知内容。保存、一致性、范围完整性、实例模拟、人类结束确认及业务批准分别判断。

## 1. 渐进保存的最小单元

凭证（Evidence）与责任角色（Party Role）及所属上下文一起落地。普通凭证必须有 `responsibleRoleRef`；合同凭证必须同时引用双方 `roleRefs`，并纳入所属合同上下文的根。角色已存在就引用，不重复建角色。责任角色明确但实际个人或组织未知，可以没有 Participant 或 `plays_role`；责任角色未知则暂不写该凭证，不虚构占位角色。经办人、上传人、证明提供方不能替代合同责任方。

履约请求（Fulfillment Request）从首次保存起，必须通过 `Request -> Contract` 的 `references` 关系直接引用所属合同上下文的根合同（Contract），与请求、合同及责任角色共同落地。`contextRef` 只表达上下文归属，不能代替合同依据关联；引用其他请求、确认或支撑凭证也不能替代这条关系。缺少该关联是一致性错误，不是范围结束时才补齐的完整性缺口。尚不能明确对应合同时，保留已有业务记录中的疑问，暂不写该请求，不补造合同或引用。

上下文（Context）必须与其实际业务内容共同保存，不能只保存名称或以空子上下文占位。合同上下文连同真实合同及双方角色；领域上下文连同实际领域根对象；合同前协商上下文至少已有一份真实邀请、方案或回应凭证。尚未展开的外部协作按语义使用已有消费方中的角色，不创建空 Context 或虚构玩家。没有履约不等于空上下文：已有合同及双方角色、正在识别交互的合同可以保存，完整性仍待后续核对。

对象、属性、关系、规则和履约按当前业务问题共同生长，不先穷尽全部 Entity 再补其余结构。属性名称与业务含义明确时可以先保存；未知类型、必填性、时间参数、关系或完成规则保持缺失，不补默认值、占位 ID、恒真完成规则或假凭证。已经表达的引用、归属、时间含义、CEL 和依赖必须一致；凭证缺责任归属是一致性错误，不是允许暂缺的完整性字段。

履约项的最小结构是已配对的请求—确认交互：有且仅有一个请求，以及有业务含义的确认结果端。只找到一端时，按上述合同关联及责任要求保存有依据的凭证，暂不包裹；空履约、缺请求或缺结果端均是一致性错误。多个确认、共享确认及明确归属的确认角色按语义关联，普通支撑证明不算结果端。完成规则、期限和数据来源可继续澄清。未包裹交互沿用已有业务记录与交接，不另建责任清单、候选履约或影子模型。

## 2. 人类定义范围，持续补全所有主履约

从实际约定与责任双方进入，直接识别双方主要请求—确认交互并包裹为履约，以此检验理解，沿凭证增量发现关联约定。主要责任梳理与请求—确认识别合为同一动作，不拆成两次分析。保留整体业务范围及全部已知合同，持续补全本合同全部主履约，包括条件义务及完成后继续产生的义务；不要求先穷尽全局再写模型。

范围与完整主履约清单由人类定义或明确确认。Agent 可以提示有材料依据的责任遗漏，不展示供用户筛选的候选合同，不能自行缩小范围，不能用实现切片排除退款、赔付或兄弟义务。范围结束以独立合同或确实独立的领域／协商为单元；同合同的付款和退款可以渐进表达，但不能只把付款切片认定为合同完整或交付下游。

## 3. 所有主履约及各层异常逐枝递归

按 [业务分析](business-analysis.md) 直接识别主要及异常新义务的请求—确认交互，配对后包裹履约，再追约定依据、期限、完成证明与采信规则，再检查逾期、拒绝、部分完成、结果不符等全部适用异常。只有单端凭证时不包裹，不补造确认；未知仍留在已有交接，不建立第二份问题台账。

```text
请求—确认配对并包裹主履约 → 异常触发与依据 → 新请求—确认配对并包裹异常履约
                                  ↓
                          新履约仍不完成怎么办
                                  ↓
                  继续展开全部分支 → 人类确认的责任终点
```

优先追当前分支，再回兄弟分支与其他主履约；依赖需要切换时说明原因。不限制递归深度，不以一次退款或赔付结束追查，不以循环引用伪装终点。正常和争议单据推演暴露新责任或证明缺口时，继续更新理解与模型，不因发现未知停止一切已知内容的维护。

## 4. 人类决定终点

终点须有适用约定或专家说明，并有人类确认。法律救济／终极履约保留责任与依据，不自动扩成诉讼软件，不自动认定所有异常走诉讼。按约终止且没有后续义务须有人类确认；仍有退款等义务就不是终点。不补造独立确认步骤。

“范围外”“外部处理”“不知道”“没材料”“再也想不出”不是终点。第三方接手不转移原合同责任。停止或暂缓不等于追责结束，继续问答须有明确意图，不因模型维护或检查自动解除停止状态。

## 5. 合同范围结束

日常进度只展示当前业务节点，不每轮展开全局；范围结束时完整核对本范围双方主要请求—确认交互、已包裹履约、责任图与剩余缺口；未包裹交互与已有业务记录中的未明责任同样参与核对，不能因没有履约 ID 就消失。指定合同或相互依赖的合同组进入下游前，核对：

1. 人类确认的范围与全部主履约清单、实际约定、双方责任及适用业务版本。
2. 全部主履约与各层异常展开完整，各项新义务的请求、期限、完成证明、采信规则和责任方明确。
3. 各分支的人类终点决定及其依据；未检查、待答、暂缓、冲突或来源失效的必要责任不隐藏。
4. 完整责任图、正常与反例推演、必要外部证明及真实机器检查结果。没有执行的模拟明确报告未执行。
5. 人类单独明确确认当前合同澄清结束，覆盖当前清单、责任图、终点与推演版本；另核对下游编辑授权。

缺少任一必要内容只阻塞受影响范围的结束和下游交付，不撤销已知模型的保存权限。单条终点、问题组答完、生成请求、机器通过均不代替合同结束确认。

相关未澄清合同通过真实需要的 Context Role 保留外部边界，具体表达按 [语义](semantics.md)。外部内部履约未展开本身不阻塞，当前合同消费的证明含义、形成依据、匹配、采信及责任未知才阻塞当前判断。不以角色隐藏必要缺口，不把同合同未闭合义务改名为外部合同。

## 6. 领域、协商与全局结束

纯领域、独立协商不补造合同或履约。领域按成熟方案的复用连接范围或明确获授权的深入范围核对对象、规则、身份、能力、结果、条件、限制及关联责任；成熟方案内部未展开不自动阻塞，不表示内部已验证。协商核对真实邀请、方案、回应与接受依据，不虚构尚未成立的义务。

相应分支的正常、边界与反例、必要依赖及人类单独结束确认须覆盖当前版本，并由人类明确本范围没有适用履约责任、无需继续追责，才可向下游交付。没有适用实例模拟时报告未执行及原因，不造凭证来取得通过。独立范围可先结束，不等待无关合同；不能将未闭合合同改名为领域绕过责任核对。

全部合同结束后，另核对跨合同关联、完整责任图和整体推演，等待人类明确确认全部追责结束，覆盖整体业务版本。全局确认不是独立合同结束的前置条件，也不授权 API、需求或实施。

## 7. 检查、变化与恢复

每批修改扫描当前完整模型的一致性；范围结束时以独立 Context ID 显式选择整合同及必要依赖，检查完整性与适用场景。`consistent: true` 不表示完整；`complete: null` 表示未检查范围完整性；`simulationPassed: null` 表示未执行模拟。机器不能证明责任已经全部发现或人类确认有效，按 [检查纪律](validation.md) 分别交接。

新增主履约、异常、范围变化或约定更正使受影响的旧检查、人类确认及下游结果失效；保留已有证据，不自动删除或回滚。继续保存有依据的更正，重新完成受影响范围检查与结束确认后才能交付下游。技术表达修正未改变业务时可引用仍适用的人类确认，但源摘要改变仍须重检。

恢复先核对实际模型、来源、差异、编辑授权、未决责任和控制意图。未保存或部分写入失败立即停止，列明各文件真实结果；“一起落地”是最小语义保存单元，不声称多文件具有事务保证。只读校验不写文件，不要求先补齐责任；编辑授权、检查成功、范围结束和业务批准互不替代。
