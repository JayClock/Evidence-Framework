# 渐进表达的批次评估

评估解释当前业务依据与 FM 表达，不是人工回答、业务批准或范围排除。只有一份持续生长的 FM，沿用已有交接保存未决项，不建立第二套状态。

## 1. 划定本批已知内容

核对当前编辑授权、实际来源与更正，按 [业务分析](business-analysis.md) 复核经营依据、约定、责任双方、主要履约与协作边界。每批围绕实际业务问题共同演进对象、属性、关系、规则、履约与上下文，不按类型预先穷尽全部 Entity。

按 [责任方法](responsibility-closure.md) 确定最小保存单元：凭证与责任角色和所属上下文共同落地，合同必须有双方角色；实际主体未知可以不建 Participant，角色未知暂不写凭证。不把未澄清术语制造为占位 Entity。

## 2. 映射与检查

1. 读取本批事实、必要原文、相关模型与案例，核对来源版本。
2. 建立事实到 Entity ID、属性名、Relationship、Rule 与 Fulfillment 的对应，定义归 Entity/属性唯一维护。
3. 明确已知与未知：属性类型、必填性、时间、关系、完成条件未清楚就不填默认值，不写假凭证或恒真规则。
4. 只维护获授权且有依据的内容，编辑后核对实际 JSON、稳定身份、引用与差异，保留无关改动。
5. 检查当前完整图一致性，另外报告完整性缺口；未执行模拟不称通过。

| 类型         | 本批表达核对                                                               |
| ------------ | -------------------------------------------------------------------------- |
| Domain       | 实际对象、身份、能力、属性、关系与规则；按复用连接或授权深入范围，不补合同 |
| Pre-contract | 真实邀请、方案和回应及双方角色；不补造尚未成立义务                         |
| Contract     | 经营依据、实际约定、双方角色与已知主履约；完整责任持续补全                 |
| Fulfillment  | 已知请求、期限、完成证明和规则共同生长；未知保持缺失                       |

## 3. 结束、变化与停止

范围结束才核对全部主履约、各层异常、责任终点、完整责任图、正常反例与人类单独结束确认，并以独立 Context 检查完整性及必要依赖。同合同可以逐步表达，不能只将付款切片认定为完整而排除退款；独立范围不等待无关分支。

新责任或更正使受影响的旧完整性结果、确认和下游产物失效，不停止一切已知内容维护。冲突内容不任选一方当事实，保留来源并交回缺口；技术问题在授权内修正复验。停止或暂缓不等于追责结束，不自动恢复问答。

保存失败立即停止，报告实际已保存与未保存部分，不自动回滚；下游失败不撤销 FM。只读校验不要求先补齐责任，也不授权修复或项目写入。
