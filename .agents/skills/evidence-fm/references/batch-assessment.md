# 追责结束后的正式表达评估

评估是 Agent 对已有业务依据与 FM 表达的解释，不是人工回答、业务批准或范围排除。采用项目获授权的记录保存来源映射与表达限制，不维护另一套准入状态。

## 1. 先核对全局准入

按 [全部追责结束](responsibility-closure.md) 核对人类确认范围内所有主履约、各层异常及责任终点，并定位人类明确确认全部追责结束的原话及所覆盖版本。存在任何未决责任分支、未确认终点或失效依据时，本范围不进入建模；不能将付款与赔付分别分级后只写付款，也不能把来源充分的主体或金额投影作为绕过门槛的理由。

只读验证不要求先编辑或补齐责任，不据此声称责任已经闭合。纯领域／合同前的无适用履约判断同样消费人类确认依据，不由 Agent 根据类型推断豁免。

## 2. 映射已确认业务

门槛满足后：

1. 读取本次范围全部发现、约定、终点确认及相关模型、问题和案例，核对来源版本与变化；按 [业务分析](business-analysis.md) 复核每份约定的经营依据、来源与责任边界，已有对象不替代该判断。
2. 建立主履约、异常分支、终点及其支撑事实到 FM ID 的对应关系；尚无正式对象时沿用发现记录定位。
3. 核对各项正式表达的必要事实与结构，保留原规则、边界和异常预期。
4. 区分可按当前 Schema 表达的业务与技术表达／运行验证限制，不省略已确认责任，也不为表达方便补造规则。
5. 编辑后核对实际 JSON、引用与完整责任图的一致性，展示增改删及仍不能证明的部分。

| 类型         | 表达核对                                                     |
| ------------ | ------------------------------------------------------------ |
| Domain       | 人类确认范围内的对象身份、属性、关系和规则，不补造合同或凭证 |
| Pre-contract | 真实双方、凭证、有效性、回应与规则，不补造已签合同           |
| Contract     | 经营依据与边界理由、身份、双方、适用约定及完整责任图的归属   |
| Fulfillment  | 相关承诺、请求、期限、完成证明、各层异常与终点依据           |

## 3. 变化与停止

发现新主履约、异常、责任解释冲突或约定更正时，停止正式编辑，按准入方法重新核对并交回缺口；不把局部事实充分当成继续写入许可。技术问题在授权范围内修正后复验，不能修改业务预期或把未知写成自由输入、无责任或范围外。

已存在的正式事实不因重新核对而自动删除；保存失效影响和原依据，撤回或改写须属于本次授权。人类停止或暂缓时只交接实际保存结果，不把控制意图当作追责结束。
