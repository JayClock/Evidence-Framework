# 模型即统一语言

Entity 及其属性即统一语言。业务概念的名称、含义和身份直接由当前 FM 维护，日常讨论、需求和交付都消费同一模型；不另设术语表、定义索引或英文词典。此方法由 FM 维护；提问与控制状态由访谈任务维护。

## 定义拥有者

- Entity 的规范名称取 `label`，业务定义取 `notes`，已有别名取 `aliases`，稳定身份取 Entity ID。
- Entity 属性的规范名称取 `label`，业务含义取 `meaning`；用所属 Entity ID 与属性名定位，不用数组下标或文件路径当身份。
- `contextRef`、`parentContextRef` 及当前 Context ID 说明业务上下文。对象移动或显示名更正不改变业务身份；属性名更正须按授权修复所有引用。
- Relationship 与 Rule 在模型内说明概念间的关系和规则，引用 Entity 及其属性，不另造一份术语定义。规则说明仍由 `description` 承载。

目标缺少业务说明时报告定义缺口，不用名称充当定义，不从代码、ID 或文件名反推业务含义。名称相同或译名相同都不证明业务身份相同。

## 双语规范名称

业务概念使用完整的 `中文（英文）`，采用全角括号，每次使用保持同一个名称，不只在首次出现时附英文。两种语言和别名指向同一 Entity 或属性，不增加独立英文字段或另一套身份。

- 英文优先复用已有规范映射；没有映射且业务含义明确时直接翻译英文，不等待人类提供或确认英文名称。同一概念保持同一译名。
- 只有含义或中文叫法存在业务歧义时才澄清，不把翻译作为独立业务问题。显示翻译不自动修改 Entity ID、属性名、代码标识或接口字段。
- 已有单语模型标签含义明确时，对话可直接展示双语名称；源标签更新仍属于正式 FM 编辑，不能把显示翻译写成源文件已经更正。
- 人名、机构的法定名称、原文引用、现有代码和外部协议名称保留实际叫法；责任角色及其他业务概念直接译为双语名称。

## 日常表达

提到业务概念时，直接读取当前上下文中的相关 Entity 及其属性，核对名称与含义，不要求额外的术语准备阶段。

- 按完整双语名称、中文部分、英文部分、`aliases`、Entity ID、属性名和上下文定位相关模型对象。别名用于理解输入；多命中保留歧义，不按同名、翻译或出现频率自动合并。
- 输出沿用当前 `label`，同一概念不轮换同义词。首次需要时简短说明输入叫法与规范名称的对应关系，之后直接使用规范名称。
- 当前位置、追溯故事、问题、需求故事、验收条件、任务标题、诊断假设、测试名称、审查意见和交接都沿用规范名称。代码、API 与 SQL 使用各层命名风格，但明确映射到同一 Entity ID 与属性名。
- 尚无模型时，承接材料中已经明确的含义和中文叫法，缺英文直接翻译；未知保持未决，不为保存术语创建占位 Entity。不把对话中的共同理解声称为已经保存的模型定义。
- 原文引用、既有代码标识和外部字段保持原样。不批量改名，不改写历史证据，不为语言统一擅自改变接口契约。消费语言不扩大写入权限：只读仍不写文件，待更正内容明确为未保存。

输出前核对规范名称、已有映射、上下文及必要未知。边界首次出现时按需看 [日常表达样例](../examples/domain-language.md)。实际表达的一致性由访谈与审查核对，不能以模型结构检查代替。

## 每轮访谈

1. **定位定义拥有者。** 沿 [业务分析主线](business-analysis.md) 读取本轮相关 Entity 及其属性，核对含义由谁维护；没有模型时承接实际材料。完成时，新概念、已有定义和同名异义可区分。
2. **澄清概念边界。** 吸收全部事实与更正，核对模糊叫法及必要区别。来源冲突先指出差异，未澄清不任选其一覆盖；假设与合成内容不作事实。完成时，明确依据或必要未知可解释。
3. **当轮统一表达。** 复用模型规范名称或按明确含义直接翻译，故事、问题与交接使用同一名称。仅有访谈授权时不写模型，不创建额外定义文件。完成时，表达指向同一业务身份，实际保存与讨论分开。
4. **按归属处理更正。** 已建模概念的更正属于 FM 修改。说明 Entity ID、属性名、当前含义及受影响判断；取得覆盖当前业务的人类追责结束依据及模型编辑授权后才更新目标。完成时，待改影响或授权内实际修改清楚，未受影响事实保留。
5. **交回访谈。** 交接当前判断、必要未决项、控制意图及真实文件结果，不虚报定义已保存。完成时，下一步边界准确，提问与等待仍归访谈任务。

连续问答不要求每轮全文重读全部 FM 或方法。已加载且未变化的内容复用；新增材料、更正、上下文丢失或身份歧义时沿受影响依赖扩大读取。正式写入前核对实际文件并保留无关改动。

## 正式编辑与检查

新建 Entity、增加属性或更正名称与含义都属于正式 FM 编辑。先按 [追责结束准入](responsibility-closure.md) 核对相应范围及人类确认，再核对编辑授权；不是每个讨论中的词都需要创建 Entity，普通访谈回答不触发编辑。

获准后，直接维护 Entity 的 `label/notes/aliases` 与属性的 `label/meaning`，保持稳定身份，核对引用及下游映射；关系和规则仍须有独立业务依据。检查按 [FM 校验纪律](validation.md) 执行，使用同一次有效 FM 结果交接下游，不增加单独的语言校验链路。

Schema、CEL、lineage、simulation 与 timeline 的实际结果分别报告；结构通过不证明定义正确或业务已批准。多文件保存不宣称原子事务，失败保留真实错误及各文件结果，停止受影响行动，不自动回滚。

## 交接

只引用实际 Entity ID、属性名、来源与获授权产物，说明更正影响及真实保存结果；定义正文仍在模型，不复制一份可编辑定义。未建模的共同理解与未决项按显式或入口授权保存在现有建模交接中，不另建术语状态。停止不扩大权限，历史来源和未决责任保留。
