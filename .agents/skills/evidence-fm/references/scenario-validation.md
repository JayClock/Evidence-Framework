# 从业务案例到模型校验

案例用于检验业务理解和模型表达。访谈中的单据推演与模型生成后的机器校验分别记录，不能相互替代，也不复制一份业务访谈案例集。

## 1. 访谈中的单据推演

凭证链已经能解释主要权责时，按 [业务分析方法](business-analysis.md) 选正常业务和相关争议，由业务方根据当时可见的单据判断金额、适用版本、时间及责任。优先复用真实脱敏单据，没有实例时明确标为合成；不提前展示后续证据。

观察现有信息能否支持判断，而不是只检查流程能否走完。争议暴露的缺口回到原始约定和关键数据追溯，未知预期保持未知，不编造赔偿或审批。对话中的角色扮演不需要 model.json、Python 或 validation 文件，只在已有发现记录保存案例依据、引用、实际结果及未决项；原话与术语依照访谈权限维护。

未运行真人推演时明确未执行。Agent 自行演算不等于真人确认，机器回放通过也不表示业务方认可模型。用户另行授权模型编辑后，才把已有案例映射为可执行场景。

## 2. 复用预期，定位覆盖

在模型 validation 场景或现有业务案例中保留稳定 ID，并关联原案例／规则及版本。原有输入、预期和未决项只维护一份；更新说明引用其路径与 ID。需要建立可执行实例时记录转换关系，不把合成实例冒充真实事件。

| 受影响的规则             | 选择覆盖                                                 |
| ------------------------ | -------------------------------------------------------- |
| 正常履约或资格成立       | 验证满足来源规则时的可观察结果                           |
| 凭证依赖必需补充证据     | 验证证据先存在且可见；缺失、错配、时间不符时不能形成目标 |
| 存在阈值、期限或身份边界 | 验证等于边界与边界两侧；数值和预期从已知规则推导         |
| 已约定违约、更正或补偿   | 保留原事实与新增结果，验证有依据的异常触发和后续责任     |

未提供规则时保留未知；没有适用性要说明理由。原始来源冲突则链接双方原文及待决项，而不是任选一个方便通过的预期。更正来源后复核相应场景，保留版本关系。

## 3. 选择实际可执行的验证

- Evidence 案例：按 [追溯与模拟](traceability-and-simulation.md) 的 Validation Suite 定义实例、步骤和预期，再用 [统一校验入口](./validation.md) 执行；来源已存在的用例直接复用，不另造一套验证数据。
- Domain 对象的操作、关系基数、事务或状态机：本模拟器不执行这些行为。记录业务案例及下游验证缺口，结构校验或 CEL 编译不能冒充领域行为模拟，更不能把 Thing 改成 Evidence。
- 暂无适用单据场景：区分未执行与有依据的不适用；声明了但为空或损坏的套件仍是失败，不以底层工具的空结果当作通过。

单据模拟按固定 asOf 和每步可见凭证执行，不使用机器当前时间或泄露后续答案。迟到确认不自动消除已发生的违约；更正与补偿使用新增凭证，旧凭证仍可追溯。这些约束的具体 JSON 与执行规则以 [追溯与模拟](traceability-and-simulation.md) 为准。

## 4. 解释结果而不是倒改预期

机器结果不符时，检查源模型映射、场景构造或实现。业务预期只有在原依据确被更正时才能修订，不能为通过测试而降低条件。

校验结果按 [最小验证记录](./validation.md#最小验证记录) 保存；交接只引用该记录与仍未覆盖的业务案例。用例存在、机器实际执行、结果通过与具名人工确认分别报告。未运行人工角色扮演或 Agent 评测时明确保留未执行，不借自动回归得出访谈质量结论。
