# 指令文件腐化：AGENTS.md 越来越长，Agent 反而变笨了

## Bad Smell

指令文件腐化指的是规则只增不减：为一个例外往入口文件加一段、同一条规则在多个文档各写一份并逐渐矛盾、保留“以前是……现在是……”的兼容说明、生成内容被手工修改后与源脱节。规则累积之后，优先级冲突、例外条款和模型对长文本中段的注意力衰减会让 Agent 的行为越来越难预料。

本项目入口目前仍然很小，但要盯住这些信号：`AGENTS.md` 出现越来越多“但是/除非”；同一约束在 Skill、指南和任务模板里出现多个版本；过期表述靠注释保留而不是被替换；评审时无法指出 Agent 的行为偏差来自哪条规则。一旦出现，先处理分层与优先级，而不是继续加规则。

## Solution

项目用分层入口、单一来源、可执行检查和替换式重构控制指令规模。治理重点在持续维护，落点是优先级确定、矛盾检测与定期清理三件事。

### 分层入口：只路由，不装细节

- `AGENTS.md` 共 39 行：27 行正文（行动入口、不变量、流程与状态、验证底线）加 12 行 OpenWiki 受管块；入口不写操作手册。
- [Guides 导航](../guides/index.md)的四层职责表把知识分成项目宪法、项目基线、工程指南与任务 Guides，并声明“这里只路由，不保存第二份事实、任务状态或完成证据”。
- 任务 Guides 只写局部差异和引用；稳定基线由对应文档唯一维护，任务不复制整套指南。

### 优先级与冲突裁决

不变量定义不可协商边界，来源权威表为每类问题指定唯一权威位置；冲突时停止行动、交回拥有者，机制细节见[隐式约定](隐式约定：规则只存在于人的脑子里.md)一篇。优先级存在，规则才不靠新旧或篇幅竞争。

### 矛盾与过期检测：guides:verify

- [Guides 检查器](../../tools/guides/check.mjs)：扫描 9 个必读文档加 `docs/` 全树与 planning/delivery 的 references/assets；必查文档存在、本地链接可解析（相对路径、URL 编码、尖括号路径）、拒绝过期架构表述；忽略围栏示例、远程链接、锚点与模板变量；只扫描维护中的文档，不扫生成产物与历史证据。
- [检查器回归](../../tools/guides/check.spec.mjs)覆盖八类边界，包括“拒绝过期架构指南而不是保留兼容段落”“只扫维护文档与工作流模板，不扫生成事实或历史证据”“链接检查不写回文档”。
- `npm run guides:verify` 由 `guides:test`（检查器回归）与 `guides:check`（实际扫描加 Prettier 格式检查）组成；`guides:check` 同时进入 `npm run lint` 与项目质量底线。规划与交付 Skill 的 `test_guides_contract.py` 另查指南路由与模板契约；[测试工序](../engineering/procedures.md#工序维护的检查与退出)要求维护时同步导航、Skill、模板并保留人工复核。

### 清理纪律：替换而不是叠加

- [Guides 导航](../guides/index.md)的维护纪律：“正文直接描述当前有效约束，不保留兼容入口或过期方案说明。替换文档时同步引用它的导航、Skill、任务模板和检查；不删除业务原始材料或历史执行证据。”
- Git 历史用破坏性重构替换旧结构（`refactor(harness)!` 系列与 `docs(openwiki)`），入口文件在多次重构中保持小体积，而不是靠追加说明维持兼容。
- 生成内容有明确归属与刷新路径：`AGENTS.md`、`CLAUDE.md` 的 `<!-- OPENWIKI:START -->` 受管块由 OpenWiki 写入，生成页不手改，[.openwikiignore](../../.openwikiignore)限定读取集。

### 演进触发条件

- 当前没有规则登记表（编号、来源、优先级、适用条件、过期条件、状态）和定期矛盾审计 Skill：优先级靠不变量与来源权威表，清理靠替换式重构与检查器回归。
- 过期检测目前只有一条具体词例（旧架构表述的固定词）；语义矛盾（同一约束在不同文档给出不同结论）仍靠人工复核，未编号入检查。
- 规则数量继续增长后，为规则补编号与过期条件、把矛盾检测做成固定动作（复用 `guides:verify` 或加定时任务），清理时留痕而不是直接消失。
- 新增规范要同时更新导航、Skill 与任务模板，并指出对应测试或人工评估；`guides:verify` 能拒绝已知过期表述，但不判断语义冲突，后者仍需人工复核。
