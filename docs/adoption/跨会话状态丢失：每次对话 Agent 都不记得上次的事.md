# 跨会话状态丢失：每次对话 Agent 都不记得上次的事

## Bad Smell

一次访谈里，用户确认了移动支付订阅登记后的动作，又补充 local/test 场景该用哪些固定值。换个会话做实施，如果 Agent 只看当前聊天，它可能重新追问，也可能把测试夹具误写成生产标识生成规则。另一种丢失发生在开发中：Agent 发现生产身份没有依据，本轮把 403 验收保留为缺口；下轮若只看到测试通过，就可能把身份问题当作已经解决。

这个仓库有访谈、建模、需求、规划和交付几个独立环节。会话结束时，进度、测试结果之外，还有用户回答、执行中发现的差异和局部设计决定要交给下一环节。只保存一段聊天摘要，既不能保证后续环节读到它，也很难分清一句话是偏好、待核实的观察，还是已授权的决定。

## Solution

这里采用文件交接，但没有新建一份通用的跨会话记忆。知识按职责写进已有来源：用户的业务回答先进入发现记录，明确术语在当轮进入唯一词汇表；模型 JSON、软件范围和 API 设计由各自的拥有者按授权更新；实施中的设计、缺口与真实检查结果进入当前任务记录。下一次会话从 [AGENTS.md](../../AGENTS.md) 和 [Guides 导航](../guides/index.md)重新定位这些文件，不靠上一轮的对话。

### 用户回答先保存，再交给下游

[访谈方法](../../.agents/skills/evidence-discovery/references/interview.md)要求保存回答原话与来源定位，把临时理解和正式事实分开；更正要保留旧依据与影响，停止或暂缓也要记录，恢复其他话题不会自动恢复暂缓的问题。明确术语按 FM 方法当轮沉淀；交接指向当前焦点、来源、问题状态和词汇表增改条目，不重抄定义或聊天全文。发现记录与词汇表任一保存失败就停止，分别交接保存结果。[Skills 说明](../../.agents/skills/README.md)明确要求跨会话从实际保存的文件恢复，没写成功就要说明未保存。

仓库里的 [订阅业务发现记录](../../.evidence/discovery.md)给出了一个具体例子。B09 保存了用户对合同登记、自动生成付款请求和 local/test 固定值的回答，还单列 `Q-MOBILE-FIXED-VALUES-001` 的问题状态、解决依据及下游消费位置。其中 `PAY-001` 等标识只作为本切片的 local/test 夹具，不被提升为生产规则。[计划的来源清单](../plans/smart-domain/plan.yaml)引用这份发现记录与该问题 ID，下游接的是文件和定位，不是上一轮会话的印象。访谈结束本身也不扩大模型 JSON 编辑权限或授权继续开发。

### 发现和决定进入各自负责的记录

开发时发现接口与文档不一致，不能在任务笔记里写一句“以实际行为为准”就算处理完。[Guides 导航](../guides/index.md)区分业务、API、范围、架构、当前代码和检查结果的权威位置；冲突要说明差异，停下受影响行动，交由对应拥有者确认。任务内能解决的实现错误留在当前任务，业务来源变化则返回上游，重算受影响计划和检查。

局部实施决定留在 [`plan.yaml`](../plans/smart-domain/plan.yaml) 的任务 `guides`、`design`、`files` 与 `procedureRefs` 中，写明本次怎么做、为什么这样做、允许碰哪些文件。执行进度只在 `tasks[taskKey].status`，检查结果在同一任务的 `observedEvidence`，没有命令、退出码和实际观察，不能靠“上次通过”宣布完成。尚无结论的事进 `gaps`，连同影响范围和下一步动作保存。例如 `GAP-IDENTITY` 写明可信身份与实例归属尚未决定：它不阻塞隔离的 local/test 主链，却阻塞 403、他人实例拒绝和生产接口验收。这样的发现不会因为某一项测试通过就消失。

如果后来收到相反的用户回答，也不能用“最新一句话”覆盖旧来源。访谈保留更正链，实施先核对新回答的适用范围、授权及受影响来源。一个只对 local/test 有效的选择，不能直接改写生产方案。

### 新会话从文件恢复，并重新检查新鲜度

[交付生命周期](../../.agents/skills/evidence-delivery/references/lifecycle.md)把恢复顺序写得很具体：读宪法、Guides 与 Git 差异，核对 FM/API 和计划输入，运行 `plan_state.py verify`、查询结构候选，再只加载当前任务、直接前置和引用来源。结构候选不等于可以开工；还要检查授权、设计、环境、CHECK，以及架构、规范、代码变化是否使旧证据失效。[测试指南](../engineering/testing.md)也要求区分真实执行、缓存命中和历史证据。

这套做法解决的是有归属的业务与交付信息的接力，不是自动收集一切聊天偏好。仓库目前没有把每次用户偏好、执行发现和裁决统一归档的通用知识队列，也不声称所有即兴反馈已跨会话同步。若某条反馈还没进入它应去的文件，下一次会话仍可能不知道；写入失败时应明确交接未保存，不能把一段临时摘要当成持久状态。
