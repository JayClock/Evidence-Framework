# 测试工序：从业务切片生成计划

本页维护本项目的工序选择与任务生成规则，不维护业务事实、任务状态或完成证据。软件职责来自 [范围](../requirements/scope.md)与[故事验收](../requirements/stories.md)，实现边界来自[架构](../architecture/overview.md)、[模块设计](../architecture/modules.md)与[领域映射](../architecture/domain-mapping.md)。技术细节、命令和代码分别引用规范、[测试指南](testing.md)与[真实范例](examples.md)，不复制第二套基线。

## 使用入口

规划者从 [Guides](../guides/index.md)进入，使用 [planning Skill](../../.agents/skills/evidence-task-planning/SKILL.md)提取工作单元，再按本页选择工序、生成显式切片及 CHECK。执行者只加载当前任务采用的工序和直接前置产物。

- **业务切片**：本次软件负责的可观察结果，不是整个 FM Context。
- **工序**：可复用的任务生成与验证方法，明确触发条件、测试边界、产物和退出条件。
- **任务**：工序针对具体拥有者、操作和场景的一次实例化，有唯一工作单元归属与 CHECK。
- **mode**：本次是 implementation、verify、design、setup 还是 manual；工序不等于 mode，也不等于 concern 或 taskKey。

先确认软件执行、判断、接收结果或辅助人工的责任。未确认范围只能形成明确带缺口的候选切片，不能以 FM/API 存在或结构覆盖完整代替批准。工序目录不是“每个实体执行全部工序”的流水线。

## 工序选择矩阵

| 变化或风险                               | 选择工序           | 前馈来源                              |
| ---------------------------------------- | ------------------ | ------------------------------------- |
| 行为拥有者、公开契约、数据或事务归属未明 | 边界与契约设计     | 架构三篇、相关源与质量属性            |
| 规则、身份、角色、生命周期、关联行为变化 | 领域行为           | 领域映射、相关规则/场景、后端规范     |
| 存储、查询、XML 装配、迁移、事务机制变化 | 持久化适配         | 模块设计、数据库 howto、后端规范      |
| HTTP 能力、输入、错误、表示或导航变化    | HTTP 契约          | 对应 API 契约、API 规范与隔离测试范例 |
| 接入适配器、跨模块协作或运行配置变化     | 应用装配与模块协作 | 模块设计、运行配置、真实装配范例      |
| 已确认软件范围包含页面交互变化           | 前端交互           | 故事、消费者流程、前端规范            |
| 一个可交付切片需要验证整体结果           | 业务旅程验收       | 故事验收、质量属性、实际环境          |

安全、并发、业务时间、数据所有权和禁止依赖等风险穿过相关工序，不靠最后一次总检查替代。平台/环境准备只在前置能力缺失时安排；既有基础先定位源码和复验方法，不重复搭建。外部 Context 或证明角色不自动触发远程接入任务。

### 边界与契约设计

- **触发与输入**：新拥有者、模块协作或一致性边界无法由现有设计说明；读取相关源、软件职责、[模块设计](../architecture/modules.md)和[质量属性](../requirements/quality-attributes.md)。
- **粒度与产物**：围绕一个可独立评审的边界决定任务；记录公开契约、内部实现、数据拥有者、允许依赖及事务入口。可直接确定的局部设计写入实现任务，不强制为每个实体另建设计任务。
- **测试边界与退出**：按具体场景审查拥有者与契约能否完成行为，检查反例、事务失败范围及禁止访问。以设计审查 CHECK 记录审查方法、预期和差异；文档存在不等于设计已通过，更不等于业务批准。
- **前置与转向**：消费真实源与已有设计。必需业务依据缺失交回来源拥有者，只阻塞受影响实现；平台能力缺失转 setup，不凭空选数据库或身份方案。

### 领域行为

- **触发与输入**：领域判断或状态变化；读取规则、场景、身份及业务时间，按[领域映射](../architecture/domain-mapping.md)确定实体、Description、ContextRole 或拥有者关联。
- **粒度与产物**：同一拥有者、同一操作的相关规则与正常/边界/反例合为任务，保留全部检查。共享最小契约只交付一次；不按字段、每条规则或每个场景重复实现。
- **测试边界与退出**：真实领域对象与必要的关联 Fake，不启动 HTTP/数据库，不 mock 被测规则。固定事实和时间，验证结果、身份/实例匹配及失败不变性；按[领域测试入口](testing.md)运行本次具体测试。规则不移入 Service、Resource 或 Mapper。
- **前置与转向**：仅依赖所需身份/值/能力契约，不等数据库或 API 完工。行为错误在任务内修复；拥有者或契约改变返回设计，事实未知返回澄清。

### 持久化适配

- **触发与输入**：领域契约需要新增或改变保存、查询与装配；读取领域契约、数据/事务设计、[后端规范](backend.md)和[数据库 howto](../howtos/database.md)。
- **粒度与产物**：按拥有者的存储操作或一致性边界生成 Mapper、XML、适配器、迁移及测试任务，不按每条关系建表。适配任务通过有来源的设计单元消费领域契约，不重复占有其规则单元。
- **测试边界与退出**：真实 H2/MyBatis/XML/Flyway及领域对象，验证写后重读、关联装配、参数绑定、行数和回滚，查询另验排序与边界。测试命令见[持久化检查](testing.md)；H2 证据不证明生产方言、隔离级别或生产并发安全。
- **前置与转向**：依赖领域契约与必要环境，不依赖 API。SQL/装配错误局部修复；表归属或事务边界变化重规划；生产数据库未知只阻塞相应生产验收。

### HTTP 契约

- **触发与输入**：已约定 API 能力或协议表现变化；读取实际能力/角色变体、[API 规范](api.md)与领域公开契约。本地资料接口与正式业务 API 分开取源。
- **粒度与产物**：按相关能力的可观察结果交付 Jersey 子资源、请求/表示和测试；可合并共享同一导航与调用边界的变体，但保留每项能力覆盖，不创造全局 CRUD。
- **测试边界与退出**：真实随机端口 HTTP、Jersey、序列化、官方分页与超媒体；mock 领域根集合，不 mock 被测 Resource/序列化器/分页，不依赖 app、persistent 或数据库。验证调用、拒绝时不写、状态码、响应及适用链接/HAL-FORMS；命令见[API 检查](testing.md)。这些证据不证明真实 SQL/事务或领域规则正确。
- **前置与转向**：消费领域契约，API 不因层次顺序依赖持久化。协议映射错误局部修复；契约与框架冲突交回 API/设计拥有者，不静默改业务接口。

### 应用装配与模块协作

- **触发与输入**：真实适配器接入或协作/配置变化；读取各模块公开契约、装配配置、数据所有权与本地事务设计。
- **粒度与产物**：围绕一条真实协作链交付组合根装配和集成/架构测试；业务编排仍归领域拥有者，不在 app 新建业务 Service，不通过本应用 HTTP 绕行模块调用。
- **测试边界与退出**：真实领域与持久化，涉及 HTTP 时从真实 HTTP 进入；检查装配效果、模块公开接口/禁止依赖、失败回滚及 profile 隔离。按[应用检查](testing.md)运行，不能只断言 Bean 存在或复制 API mock 用例。
- **前置与转向**：依赖实际参与的领域、持久化及 API 任务；仅有进程内协作时不强加 HTTP 前置。接线错误局部修复，事务参与者变化重规划，环境失败局部阻塞。

### 前端交互

- **触发与输入**：故事明确要求页面或交互变化；读取消费者流程、HTTP 契约及[前端规范](frontend.md)，不从后端能力自动推导页面。
- **粒度与产物**：按一个用户目标及相关加载/空/错误/提交状态交付 React 组件与交互测试，不按 DOM 元素拆任务，不自动引入表单平台或状态框架。
- **测试边界与退出**：真实组件、Vitest/jsdom/Testing Library，在 HTTP 边界控制响应，不 mock 被测组件；断言用户可观察操作、请求和导航。命令见[前端检查](testing.md)，真实浏览器另按[浏览器 howto](../howtos/browser-debugging.md)检查；按钮可见性不证明后端授权。
- **前置与转向**：组件测试消费已确定的 HTTP 契约，不机械等待后端实现；真实联调才依赖服务就绪。UI 错误局部修复，契约或软件职责缺失返回对应拥有者。

### 业务旅程验收

- **触发与输入**：软件切片可以整体交付，或已有旅程受到回归风险；读取已确认验收、质量要求与直接前置实际证据。
- **粒度与产物**：按用户/消费者目标与相关失败路径生成验收任务。可复用装配测试支撑验收 CHECK，但明确新增的业务断言与覆盖；不复制相同测试冒充两份证明。
- **测试边界与退出**：按交付边界使用真实应用/数据，含 UI 的旅程补真实浏览器；固定输入与时间，验证成功、拒绝、边界和失败后数据不变。CHECK 填实际命令或人工步骤、环境、预期和证据；未确定的自动化命令为 null 并关联 gap。健康检查、构建成功或截图不能单独证明旅程完成。
- **前置与转向**：依赖实际被验收的交付任务与环境。失败定位到责任工序；新增任务/依赖回 Plan，业务期望不清返回澄清。未确认外部渠道不伪装真实支付接入通过。

## 从工序生成 slicing 和任务 Guides

按下面的顺序应用[切片规则](../../.agents/skills/evidence-task-planning/references/slicing-policy.md)，不是让编译器根据工序名称猜设计。

1. 选有来源的软件结果与验收场景，指出确认状态、非目标和相关缺口；提取 inventory，不修改上游。
2. 确定拥有者、操作、最小共享契约；按变化选择工序。在任务 Guides 写清触发条件、采用的工序章节、测试边界及适用限制；未触发的工序不建空任务。
3. 按测试边界合并与拆分：同一操作的相关场景合并；拥有者、可独立交付结果、测试环境或失败定位边界不同则考虑拆开。不能合并到只剩“实现整个上下文”，也不拆成“写代码”“补测试”两个无法独立证明行为的任务。
4. 工作单元唯一拥有；其他任务通过依赖消费。SQL/装配/前端等无直接源单元的工作登记有实际 inventory 源引用和理由的 `design.*`；不要制造同义设计 ID 绕过去重。
5. 依赖来自消费的真实产物，不来自工序编号、技术层顺序或 FM 引用图。相同文件的并行编辑需协调文件边界；不能为解决调度冲突虚构业务依赖。
6. 按现有 schema 写 groups、详情步骤和 CHECK，再 compile。结构通过后仍人工核对工序是否适用、场景/能力是否有证据去向；已有 API 能力不能通过不选工序或 disposition 绕过覆盖。

| 工序实例信息                   | 现有字段或位置                                                                        |
| ------------------------------ | ------------------------------------------------------------------------------------- |
| 工程来源与版本/适用章节        | 索引 `sourceManifest`；任务 Guides                                                    |
| 拥有者、数据和事务决定         | `slicing.designItems`；任务局部设计                                                   |
| 唯一拥有的单元、身份成分、前置 | `slicing.groups` 的六个既有字段                                                       |
| 工序/规范/howto/范例文件       | 详情 `procedureRefs`，项目根相对路径；章节和用途写入 Guides，不把工序标签冒充文件路径 |
| 前置消费方式                   | `dependencyUsage`，不再次定义依赖图                                                   |
| 实现、复验或设计方式           | 索引 `taskNotes.mode`                                                                 |
| 行动、反馈与退出               | 详情 `steps`、`checks`、`completionCriteria`                                          |
| 实际结果与状态                 | 详情 `observedEvidence`；索引 `taskNotes`                                             |

工序名称不是新增 schema 枚举。本页不增加 `procedureId`、工序状态或第二份进度表。`groups` 仍只允许 `concern/ownerRef/operationRef/fileName/unitKeys/dependsOn`。前端 HTTP 消费适配可用现有 `integration` concern 和有依据的设计单元，旅程验收用 `acceptance`；不新增 `frontend` concern，也不把前端任务设为后端 API 能力的主交付者。若实际工作无法准确表达，登记规划能力缺口，单独授权扩展编译器及回归，不假装字段已支持。

常见依赖形态是“最小领域契约 → 领域行为 → HTTP 与持久化分别适配 → 真实装配 → 旅程验收”。这不是固定顺序：已经独立交付的契约可以被并行消费，前端组件可先针对已确定 HTTP 契约验证。API 支持任务闭包不包含下游验收任务，所以 `apiCoverage` 不证明完整旅程已验收。

以下是已有[本地切片契约](../../apps/backend/README.md)的工序映射练习，不是正式业务 plan，也不把源码存在标成任务完成。复验命令统一取[测试指南](testing.md)。

| 工序       | 具体落点与可核对行为                                                                                                                                                                                                  | 不应推导出的工作                                    |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------- |
| 领域行为   | [UserTests](../../libs/backend/domain/src/test/java/com/evidencepoc/backend/domain/UserTests.java)：描述合法性、重命名身份与原快照不变                                                                                | 每种非法名称单独实现一份实体                        |
| HTTP 契约  | [ApiTest](../../libs/backend/api/src/test/java/com/evidencepoc/backend/api/ApiTest.java)与[UsersApiTests](../../libs/backend/api/src/test/java/com/evidencepoc/backend/api/UsersApiTests.java)：真实 HTTP，mock Users | 等数据库完成才能测试协议；把 mock 通过当 SQL 通过   |
| 持久化适配 | [MyBatisUsersTests](../../libs/backend/persistent/src/test/java/com/evidencepoc/backend/persistent/MyBatisUsersTests.java)：读写、分页、缺失写入及回滚                                                                | 为 API 重复实现描述校验；推广物理删除到有引用的主体 |
| 装配与验收 | [应用测试目录](../../apps/backend/src/test/java/com/evidencepoc/backend/)：按具体测试核对真实链路与配置                                                                                                               | profile 隔离等于生产认证完成                        |
| 前端交互   | [App 测试](../../apps/frontend/src/app/app.spec.tsx)：当前导航页                                                                                                                                                      | 自动生成完整用户管理或订阅表单                      |

例如对“重命名保持身份且不改变原快照”的复验任务：`files.reuse` 定位 UserTests；`steps` 先核对切片契约和实现，再运行其中 `renameKeepsStableIdentityWithoutMutatingLoadedSnapshot`；CHECK 明确真实 User/Description、固定新旧名称、身份不变和原快照不变的预期。使用领域测试入口并指定该测试，`completionCriteria` 引用此 CHECK；`observedEvidence` 在执行前为空。它不证明 HTTP 更新已写入数据库，后者需要持久化和装配工序各自提供证据。

## 工序维护的检查与退出

维护本页或生成规则时，同步 Guides 路由、planning 前馈与任务模板，并运行[项目质量检查](testing.md)。现有回归的职责为：

- [Guides 测试](../../tools/guides/check.spec.mjs)：本页路由、七类工序的说明结构及既有权威链接；链接检查器另外检查维护范围内文件链接。
- [模板契约测试](../../.agents/skills/evidence-task-planning/tests/test_guides_contract.py)：选工序先于分组、任务模板保留工序实例说明和单一状态归属，不扩展 schema。
- [编译测试](../../.agents/skills/evidence-task-planning/tests/test_task_compiler.py)：合成图书案例的显式切片，规则唯一归属、HTTP/SQL 分支、验收汇合及确定性；不证明 Agent 会自动选对工序。

人工复核至少覆盖：同一操作多场景不重复实现；只改变 HTTP 表示不强制新建 SQL 任务；外部证明渠道未知只阻塞对应接入；前端仅在软件范围要求时生成。测试通过不代替这些语义判断。工序落地后停止，不自动生成业务计划、执行产品任务或提升审核状态。
