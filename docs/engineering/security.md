# 安全工程底线

本页规定已有工程安全边界，不设计未知业务权限。身份、审计、生产数据库与外部信任缺口见 [质量属性](../requirements/quality-attributes.md)。

## 身份与权限

- 当前用户 CRUD 只面向 local/test，默认后端绑定 `127.0.0.1`；不得用代理、隧道或修改监听地址暴露公网。
- 正式身份需可信认证来源、主体映射及代表权限依据。FM Role、客户端提供的 userId、路径参数都不自动证明授权。
- 在实际读写操作点核对实例归属与当前资格。前端按钮、HAL 链接或曾经成功访问不是持续授权。
- 生产启用受保护接口前完成 QA-IDENTITY 的决定和允许/拒绝测试；不复制参考工程的 JWT/OIDC/RBAC 作为默认方案。

## 输入、输出与数据

- 服务端严格检查结构、类型、范围和未知字段；客户端校验只是交互辅助。
- SQL 使用参数绑定；外部 URL、路径、标识不能未经检查转成任意文件或网络访问。
- 错误响应不暴露 SQL、内部栈或连接配置。前端不执行不可信 HTML。
- 不提交真实密码、token、私钥或数据库凭据；howto 只给变量名与非敏感本地示例。测试使用隔离数据，命令输出和截图先检查敏感内容。
- 日志避免记录私人内容和完整凭据。技术日志、安全审计和业务证据是不同记录；留存、删除及不可篡改要求需要明确依据。
- 幂等、并发和事务遵循实际契约；输入拒绝或授权失败时必须验证数据未改变。

## 集成与依赖

确认确有远程调用后再设计 TLS、验签、超时、重试、幂等及失败记录。本地事务不能回滚远程资金结果，不能自动新增补偿义务。

依赖使用仓库配置与锁文件，升级核对来源、兼容性和实际消费者测试。已安装或下载成功不等于无漏洞，也不证明运行时集成通过。

## 检查

代码评审核对信任边界、敏感输入/输出和失败不变性；API/app 测试验证实际拒绝及资源隔离；persistent 验证真实事务。生产专项未完成时明确未验证，不用本地健康检查或依赖扫描替代授权验收。
