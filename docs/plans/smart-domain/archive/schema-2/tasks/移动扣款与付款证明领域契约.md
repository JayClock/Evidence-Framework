# 移动扣款与付款证明领域契约

> 建立移动支付请求/结果与订阅 `PaymentProof` 之间的窄公开契约，不接真实支付协议。

## 1. Guides：当前任务前馈

- 项目入口：`AGENTS.md`、`docs/guides/index.md`；总索引：[`../index.md`](../index.md)。
- 交付目标：保留 `contract.mobile`、`request.mobile`、`confirmation.mobile` 的原始责任和时间，证明唯一合格机构结果可扮演 `role.payment-proof`。
- 非目标：无移动支付 HTTP API、真实 SDK、验签、超时/重试/补偿；不实现 `rule.mobile-expired`。
- 业务来源：移动支付 Context、协议、扣款请求/结果、`relation.mobile-as-payment-proof`、`rule.mobile-completed`。
- 工序实例：领域行为和模块公开契约；真实移动领域对象，Fake 结果集合只证明规则，不证明协议或 SQL。
- 前置产物：消费订阅任务的 `PaymentRequest` 和 `PaymentProof` 窄契约，不访问订阅内部关联。
- 已确认输入：local/test 固定使用 `PAY-001`、`MOBILE-001`、`MOBILE-REQ-001` 和移动请求业务开始时间 `2026-10-01T09:02:00Z`；付款请求开始时间仍为合同 `signed_at=09:00`。

## 2. 局部设计

- 移动支付模块拥有协议、扣款请求、机构结果；订阅模块只看 `PaymentProof` 接口。
- `MobileConfirmation` 直接实现或提供不可变 `PaymentProof` 视图，不复制凭证、签发时间或责任方。
- 一次移动请求最多一个有效结果；重复同一结果交由持久化幂等处理，两个不同结果不能合并。
- 请求截止引用订阅付款截止，不因接入动作延长。

## 4. 执行与交接纪律

真实支付接入另行授权。不得从“外部机构”推导网络协议，也不得把机构结果重建成订阅模块的新凭证。
