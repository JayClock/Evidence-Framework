# 订阅支付应用装配与模块协作

> 在统一后端应用中装配订阅、移动支付、MyBatis、Jersey 和 local/test 支付端口，并验证模块边界。

## 1. Guides：当前任务前馈

- 项目入口：`AGENTS.md`、`docs/guides/index.md`；总索引：[`../index.md`](../index.md)。
- 交付目标：让真实 Resource、领域公开契约、持久化适配器和 local/test 支付端口在 app 中可用；明确付款触发与事务分段。
- 非目标：组合根不实现业务 Service，不直接访问 Mapper/表，不把外部调用放入数据库事务，不接真实支付。
- 工程来源：`docs/architecture/{overview,modules}.md`、`docs/engineering/{procedures,backend,security,testing,examples}.md`。
- 工序实例：应用装配与模块协作；真实领域、persistent 和 HTTP；local/test Stub 替代外部机构。Q1 装配/架构检查支撑主链 Q2。
- 前置产物：真实订阅/移动持久化、local 支付端口和订阅 API。
- 已确认输入：合同登记成功后自动形成付款请求并进入 local/test 扣款调用；固定使用 `PAY-001`、`MOBILE-001`、`MOBILE-REQ-001` 和移动请求业务开始时间 `09:02`。

## 2. 局部设计

- app 只扫描/配置 Bean；实际业务流程由 Reader/合同拥有者关联和 Context 注入的公开端口表达。
- 合同 11 字段和付款请求在合同登记事务中形成；合同登记成功后自动调用支付端口，结果在独立事务中幂等登记。本地事务不声称回滚支付端口副作用。
- 模块协作走 Java 契约，禁止订阅包访问移动支付 Mapper 或反向访问订阅私有表。
- local/test profile 注册模拟器；正式 profile 在无真实端口时启动/能力暴露策略须按当前范围保持隔离。
