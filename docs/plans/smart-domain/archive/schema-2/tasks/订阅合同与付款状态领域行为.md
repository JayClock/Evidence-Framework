# 订阅合同与付款状态领域行为

> 交付合同登记、付款请求派生和 `pending/completed` 判断的纯领域契约与测试。

## 1. Guides：当前任务前馈

- 项目入口：`AGENTS.md`、`docs/guides/index.md`；总索引：[`../index.md`](../index.md)。
- 交付目标：落实 `US-001`、`US-002`、`US-003` 的纯领域部分；合同事实不可改写，付款请求由合同确定性派生，付款完成只消费合格 `PaymentProof`。
- 非目标：不实现 SQL、HTTP、真实支付、身份认证、逾期违约/退款/恢复/内容访问。
- 业务来源：`context.subscription`、`fulfillment.payment`、`contract.subscription`、`request.payment`、`role.publisher`、`role.payment-proof`、`relation.contract-payment`、`rule.payment-start/amount/deadline/completed`。
- 工程基线：`docs/architecture/domain-mapping.md`、`docs/engineering/{procedures,backend,testing}.md`。
- 工序实例：领域行为；真实 Description/实体/Reader/拥有者关联，小型内存关联 Fake 仅保存本次测试事实。Q1 直接支撑合同登记和付款状态 Q2。
- 前置产物：复用 `foundation::context.subscription::role.reader` 的 Reader Context 契约及实际复验证据。
- 已确认输入：合同按 FM/API 使用全部 11 个必填字段；自动触发由应用装配任务消费，不改变本任务的纯规则边界。

## 2. 局部设计

- `SubscriptionDescription` 保存 FM 合同的冻结字段；`Subscription` 有稳定 `subscriptionId`。
- Reader 通过拥有者关联登记/定位合同；同 ID 不覆盖既有合同事实。
- 每份合同最多一个 `PaymentRequest`；`startedAt=signedAt`、金额/币种引用合同、`expiredAt=startedAt+paymentSeconds`。
- `PaymentProof` 是只读能力；完成判断要求恰好一份全字段匹配、成功且 `confirmedAt` 位于闭区间的证明。
- 截止前无合格证明为 `pending`；本任务不实现 `rule.payment-expired` 或 breached 后续行为。
