# 本地移动支付端口模拟器

> 为 local/test profile 提供确定性支付端口，不把模拟器描述为真实机构集成。

## 1. Guides：当前任务前馈

- 项目入口：`AGENTS.md`、`docs/guides/index.md`；总索引：[`../index.md`](../index.md)。
- 交付目标：接收明确的 `MobileDebitRequest`，返回可配置的固定 `MobileDebitConfirmation`，供应用装配验证正常、截止和失败结果。
- 非目标：不联网、不验签、不重试、不自动补偿、不选择生产凭证信任机制。
- 工程来源：`docs/requirements/scope.md`、`docs/requirements/quality-attributes.md` 的 `QA-INTEGRATION`、`docs/engineering/{procedures,security,testing}.md`。
- 工序实例：集成适配；真实端口契约与 local/test Stub，固定时钟/结果。Stub 只证明调用边界，不证明机构行为。
- 前置产物：移动支付领域任务的端口、请求和结果契约。
- 已确认输入：local/test 固定协议 `MOBILE-001`、付款请求 `PAY-001`、移动请求 `MOBILE-REQ-001` 和请求业务开始时间 `2026-10-01T09:02:00Z`。

## 2. 局部设计

- 实现放在 `apps/backend` 的 local/test 配置，不进入 domain，也不在默认生产 profile 注册。
- 输入输出完整保留请求编号、订阅、读者、专栏、付款请求、金额、币种和业务确认时间。
- 测试可选择 success/failure 和 confirmedAt；模拟器不自行读取服务器当前时间。
