# 移动支付订阅主链验收

> 用真实应用边界验收 `US-001`～`US-003`，不把 local/test 结果扩大为生产保证。

## 1. Guides：当前任务前馈

- 项目入口：`AGENTS.md`、`docs/guides/index.md`；总索引：[`../index.md`](../index.md)。
- 交付目标：从真实 HTTP 登记合同，按已确认触发形成付款请求，调用 local/test 支付端口并登记结果，读取 completed/pending；付款请求未形成返回 404。
- 非目标：不验收前端、真实身份/403、生产数据库、真实支付协议、逾期违约、退款/恢复/内容访问/预付费。
- 业务来源：`scenario.mobile-subscription`、`scenario.payment-pending`、`scenario.cutoff-paid` 和 `AC-001`～`AC-003`。
- 工序实例：业务旅程验收；真实随机端口 HTTP、Jersey、领域、H2/MyBatis/Flyway，外部机构由 local/test Stub 替代。Q2 失败必须定位到前置 Q1，不修改业务预期。
- 前置产物：应用装配任务及其真实 HTTP/SQL、架构和故障证据。
- 已确认输入：合同采用 11 个字段；登记成功后自动触发；local/test 固定使用 `PAY-001`、`MOBILE-001`、`MOBILE-REQ-001` 和移动请求业务开始时间 `09:02`。QA-IDENTITY 仅阻塞 403/生产授权验收。

## 2. 局部设计

- 测试固定业务时间，不依赖服务器当前时间；每例隔离数据并验证失败不变性。
- completed：唯一全额匹配证明在 `[startedAt, expiredAt]`；cutoff 取 `expiredAt` 本身。
- pending：`asOf=2026-10-01T09:14:59Z` 且无证明；未形成付款请求则 404。
- 合同登记成功不等于付款完成；所有状态从领域规则计算。
