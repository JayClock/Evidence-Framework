# Evidence Modeling 使用指南

从 [项目宪法](../AGENTS.md)和 [Guides](guides/index.md)确定本次权限，再选择入口。建模只使用 Skill；Skills 提供专业方法与执行协议，普通对话是完整交互路径。

## 选择入口

| 目标                         | 入口                                                               | 本轮结果                                           |
| ---------------------------- | ------------------------------------------------------------------ | -------------------------------------------------- |
| 解释履约建模方法或术语       | [FM](../.agents/skills/evidence-fm/SKILL.md) 的讨论分支            | 方法解释、依据与未知                               |
| 记录建模过程或合同级交接     | [Handoff](../.agents/skills/evidence-handoff/SKILL.md)             | Markdown 进展交接及下一轮建议                      |
| 访谈、继续澄清、更正或停止   | [Discovery](../.agents/skills/evidence-discovery/SKILL.md)         | 共同理解、当前节点的独立问题组及模型定义的待改影响 |
| 生成、修改或校验 FM          | [FM](../.agents/skills/evidence-fm/SKILL.md)                       | 模型、场景及实际检查结果                           |
| 从整体 FM 设计或校验 API     | [API](../.agents/skills/evidence-api/SKILL.md)                     | API 设计、HTTP 契约及派生产物；FM 只读             |
| 生成或检查离线工作台         | [Visualization](../.agents/skills/evidence-visualization/SKILL.md) | 审核页面或检查结果                                 |
| 一次完成模型、API 与联合审核 | [Modeling](../.agents/skills/evidence-modeling/SKILL.md)           | FM → 整体 API → 联合审核                           |

```text
/skill:evidence-modeling 访谈并形成共同理解，沿用模型语言
/skill:evidence-handoff 下一轮继续运输签收证明，采购期限仍暂缓
/skill:evidence-modeling 核对准入后修改模型与 API，生成联合审核页
/skill:evidence-modeling 只修改 FM，不设计 API，不生成页面
/skill:evidence-modeling 只校验当前 FM 与 API，不写任何项目文件
/skill:evidence-modeling 生成联合审核页，不修改设计源
```

其他宿主使用各自 Skill 入口或显式读取 SKILL.md。显式一体生成默认授权两源与联合审核，更窄要求优先。

## 上下文总览与当前进度

业务分析以《如何落地业务建模》的四色建模与 8X Flow 为准：从收入流与成本结构出发，以现金权责、目标—实际对比发现业务，寻找实际约定与责任双方，直接识别双方主要请求—确认交互，配对后包裹为主要履约，再追溯凭证与异常交互。主要责任梳理与请求—确认识别合为同一动作，不先列抽象责任清单再转换，不保存空履约。收款追承担的义务，付款追取得的权利，没有现金往来则核对内部目标、实际产出及检查约定；业务凭证围绕现金往来或 KPI，通过关键数据关联。合同入口明确责任身份，已知个人或组织直接复用；经办人与证明提供方不自动成为合同一方。已有经营依据直接承接，不重复询问已知收支或目标；未知则先澄清，不以任意承诺替代。主履约清单与同一份 FM 随发现补全，不等全部澄清结束才首次保存，范围结束前核对完整责任。

明确目标或单一清晰入口直接进入，多个独立入口需要排序或用户要求查看／切换时才展示总览。总览说明当前已知合同、领域与协商的目的、边界及关联，不证明全局发现已经完成。合同项说明谁与谁达成什么约定、主要责任及协作；领域说明对象与规则，协商说明方案及回应。未知约定不作为合同选项，功能或章节不直接作为上下文；边界疑问局部核对，不因领域归类删除合同责任。专业分析与阶段验收按[双层循环的验证与退出](../.agents/skills/evidence-modeling/references/workflow.md#双层循环的验证与退出)执行。

沿外部凭证发现其他独立约定时增量补充关联，不自动切换焦点，也不因出现第三方推定新合同。用户选择只决定分析焦点，合同承接双方和已知主履约，领域承接已有方案及连接点，协商承接邀请／方案／回应。已澄清结束项仅供查看；取消保留原问题与焦点，查看不解除停止或暂缓。结束确认覆盖当前完整范围，单合同、领域／协商分支及全局确认分别核对。

总览不展示“待追溯”一栏；未决问题保留，进入焦点后按依赖澄清。总览、日常问答及方法解释不附资料出处、参考资料段或内部检查报告；内部依据、版本与获授权交接的产物引用仍保留，业务凭证的证明作用仍需说明。导航与业务问题分轮，有效焦点直接恢复，不重复总览。

每轮按“履约判断 → 关键数据 → 凭证来源 → 深入追溯 → 返回判断”开展凭证追溯，显示当前位置、合同责任方、一段自然叙述和全部独立必要问题，各题分别编号。故事说明当前要求凭什么成立、实际结果凭什么符合约定；直接来源不足时继续追形成依据，取得依据后逐层返回原判断，不以操作时间线、用户故事模板或分析字段表组织问卷。相关请求、确认及支撑凭证都参与查找，共同前提与其他独立问题同轮提出，不因一项依据未知而整轮串行；只有用户要求一次一问或查找后确实只有一个可问项时才单问。已包裹的履约位置是 `合同名称 → 履约项名称 → 请求或确认`，未包裹时用 `合同名称 → 已知请求或确认`，不虚构履约 ID；凭证使用中文（英文）业务名称，类型作辅助标签。责任人就是所属合同的一方，位置紧接按约定负责的合同责任方及已明确实际主体；经办人、上传人和证明提供方另行说明，不替换合同责任方。请求与确认本身就是凭证；沿请求—确认追溯要求与结果的依据。故事讲清各来源追到了哪里、能证明什么，以及下一步深入或回溯的位置。协商与领域使用各自上下文与对象，不补造合同。

一个业务焦点下可以开展多凭证并行追溯，同一凭证也可有多条关键数据来源链。每轮先找齐当前可同时澄清的独立内容，各链依据回答深入及回溯；共同依据只追一次，局部依赖只约束相关分支，不机械逐字段问到底，也不先扫完所有凭证再深入。主焦点保持不变，各活跃凭证分别说明当前位置、关键数据与所属合同的合同责任方；一条链暂缓不封锁其他获准继续的独立链。已知业务目的自然融入开头，不重复列主焦点、业务目标或凭证分析栏目；各来源的所属合同、位置与责任嵌入故事。箭头表示寻找依据，不表示操作先后。来源查清不表示凭证证明充分或履约完成。描述不附资料出处，内部业务依据引用仍按权限保留。

收到回答后吸收全部事实并重算依赖，不预排整份问卷。部分回答立即承接已答项，未答不默认同意，不知道保持未决；逐项暂缓保留原标识，整轮停止或取消后等待。合同导航、单合同结束确认和全局结束确认各自单独一轮，不与业务问题组混问。问题组回答完毕不表示全部追责结束或授权生成。

问答、控制与承接由 [访谈协议](../.agents/skills/evidence-discovery/references/interview.md) 唯一维护；[追溯问答](../.agents/skills/evidence-discovery/examples/tracing.md)以脱敏合成的外观等级判断展示要求与结果两侧来源、部分回答、局部暂缓和返回判断的连续合成样例，边界反例集中在 [行为评测](../.agents/skills/evidence-discovery/evals/README.md)，不作为日常必读。表达质量评测核对每题是否由当前判断所需的数据与凭证缺口产生、来源深入后能否返回判断，以及事实复用、独立问题、责任与控制是否保持；格式或关键词出现不等于行为通过。

领域按“识别边界 → 优先复用成熟方案 → 澄清业务连接点 → 必要时深入”推进，不默认重建通用能力；成熟方案不能替合同决定权益或责任。能力抽象用 `role/domain`，既有系统边界用 `role/third_party`（图示 `3rd-system`），不按公司内外或部署分类；确需展开内部且获授权时才建 `context/domain`。角色不是完成证明，关系遵守 FM 语义。领域及协商按各自方法问答，不强套履约凭证格式。分支结束按本次复用连接范围或获授权深入范围，单独展示规则／方案、关联责任及实际正常和反例核对，等待人类确认本分支澄清结束，并确认本范围没有适用履约责任、无需继续追责。必要缺口仍阻塞；不将未闭合合同改名为领域来绕过准入。完整交互与样例见 [访谈协议](../.agents/skills/evidence-discovery/references/interview.md)及 [上下文导航](../.agents/skills/evidence-discovery/examples/navigation.md)。

## 正式编辑与产物

FM 随访谈渐进维护，业务依据与编辑授权决定本批可保存的内容。**凭证与责任角色及所属上下文共同落地**：普通凭证有责任角色，合同有双方角色；角色未知暂不写凭证，实际主体未知不虚构 Participant。对象、属性、关系、规则、履约与上下文共同生长，未知类型、必填性、时间或完成规则保持缺失，不造占位 ID、假凭证或恒真规则。履约请求从首次保存起直接引用所属根合同，上下文归属或其他凭证链不能替代；只有请求—确认配对及责任明确后才包裹履约。仅有单端时按[最小保存单元](../.agents/skills/evidence-fm/references/responsibility-closure.md)保存有据凭证，不补造另一端，未包裹交互保留在已有记录与获授权交接中。每批检查当前完整图的一致性，空履约、缺请求或结果端及请求缺少直接合同关联均是错误；范围结束和下游交付才核对合同全部主履约、各层异常、人类终点、必要证明、完整责任图、推演与结束确认，并执行显式范围完整性检查。相关未澄清合同以 Context Role 表达外部边界，不补造其内部履约，也不能用角色隐藏当前合同必要缺口；没有关联的合同只保留在交接中。

本范围全部合同闭合后，单独取得**人类明确确认全部追责结束**，核对跨合同关联与整体推演；不要求已闭合独立合同等待此全局确认。完整责任判断由 FM 方法逐项复核；渐进保存不代表责任完整，直接调用 FM、外部材料或已有模型都不能替代下游交付所需的范围完整性与人类结束确认。停止、暂缓、合同级结束与全局结束分别判断，结束确认与编辑授权分别核对。

| 默认路径                                        | 用途                                   |
| ----------------------------------------------- | -------------------------------------- |
| `.evidence/handoffs/<主题>.md`                  | 显式请求或合同级自动保存的建模过程交接 |
| `.evidence/fm/`                                 | 正式 JSON、说明、validation 与生成物   |
| `.evidence/api/api.json`                        | API 设计源                             |
| `.evidence/api/generated/`                      | API 投影、OpenAPI、样例与流程          |
| `.evidence/views/index.html`                    | 当前源的只读工作台                     |
| `.evidence/checks/fm/`、`.evidence/checks/api/` | 获授权紧凑检查记录                     |

Entity 及其属性即统一语言：Entity 的 `label/notes` 承载规范名称与业务定义，属性的 `label/meaning` 承载名称与含义；访谈、需求、任务、测试和交接直接消费当前模型，不另设术语表或定义索引。优先复用已有规范映射，含义明确且缺英文时直接翻译，不等待人类澄清英文；显示翻译不自动修改已有 FM 标签、稳定 ID 或接口字段。尚无模型时承接实际材料，不为保存名称创建占位 Entity；有业务依据及编辑授权即可渐进新建或更正，不等追责结束；纯讨论、只读、仅访谈与仅记录限制优先。

建模入口访谈默认由 FM 增量维护模型；单合同澄清结束并经人类确认后，再检查范围完整性并接续获授权下游，相关未澄清合同使用 Context Role，随后调用 `evidence-handoff` 保存未澄清部分及恢复位置。独立领域／协商在对应分支准入与结束确认有效后，也按入口授权接续正式建模及未澄清上下文的 Handoff，不要求无关合同先结束，不把领域边界一律表达成 Context Role。只读、仅访谈、不生成或不保存交接等明确限制优先；普通回答在已有授权内可触发 FM 增量维护，但不触发 API 或页面。合同级自动接续的资源、失败及恢复规则由 [文件交接](../.agents/skills/evidence-modeling/references/workflow.md) 唯一维护；保存成功后停止，不自动切换合同。

FM 与 API 分别由独立 Skill 维护；独立 FM 调用只交付 FM。建模入口的完整生成依次委派 FM、API 与 Visualization；API 与规划只消费明确就绪范围及必要依赖，同一次结果须有 `consistent: true`、`complete: true`、明确 `scopeRefs/contextRefs`、空缺口和匹配摘要；不默默过滤同合同未完整义务。`check_fm.py` 默认只检查一致性，范围检查使用 `--scope`；`complete: null` 是未检查完整性，`simulationPassed: null` 是未执行，不能冒充通过。API 保留自身校验但不重复 FM 检查。联合页在独立页面运行中核对两源并完成浏览器检查。各阶段保存与检查分别交接，部分成功与完整交付分别报告。只读、仅 FM、仅页面等限定按本轮授权执行。
