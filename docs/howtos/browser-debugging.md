# 浏览器调试

## 准备

按 [本地启动](local-development.md)启动前后端，用浏览器打开 `http://localhost:4200/`。当前页面只展示用户 API 链接，不期待尚未实现的表单或订阅流程。

## 检查路径

1. 打开开发者工具 Console，检查加载错误和 React 异常。
2. 在 Network 开启 Preserve log，点击用户 API 链接，核对 `/api/users` 的请求、响应状态、媒体类型与 HAL 内容。
3. [Vite 配置](../../apps/frontend/vite.config.mts)将开发服务器的 `/api` 代理到 `http://localhost:8080`；直连后端 `127.0.0.1:8080` 也应按实际契约响应。
4. 代理失败时先用 curl 检查后端。若 localhost 解析地址与后端回环监听不匹配，记录具体网络错误并在获授权范围修配置，不开放公网监听来规避。
5. 检查 Root → users → 成员链接，以及 Location/self 解析后的资源一致性；媒体类型相关操作用 curl 明确指定 Accept，浏览器直接打开 JSON 不是 HAL-FORMS 交互 UI。
6. UI 变更检查键盘导航、可访问名称、加载/空/失败状态。当前没有的状态不能假称已验证。

## 限制与证据

Vite `preview` 的端口配置为 4300，但未配置与开发 server 相同的代理；不能假定静态预览即为完整联调或生产部署。没有代理/后端时 `/api` 失败应报告环境边界。

保存必要的 URL、操作、实际预期差异、状态码和控制台错误；截图/响应先检查敏感数据。不要粘贴 token、完整私人内容或生产凭据。

Vitest/jsdom 不是浏览器网络证据，浏览器打开页面也不证明后端授权、SQL 或事务。所需自动与人工检查在当前任务 CHECK 分别登记；调试结束停止自己启动的进程，不关闭无关服务。
