# 软件职责与范围

## 来源与状态

本页区分业务来源、已有实现和待决定的软件范围，不批准业务模型，也不把存在的代码追认为完整产品交付。

- [发现记录](../../.evidence/discovery.md)与 [FM 概览](../../.evidence/fm/00-overview.md)：专栏订阅、支付、内容访问、断更退款与免费恢复。
- [模型入口](../../.evidence/fm/model.yaml)：模型文件不保存审核状态；执行前核对实际源。
- [API 设计](../../.evidence/api/api.yaml)：业务接口契约，不是已部署接口清单。
- [用户切片说明](../../apps/backend/README.md)及其源码/测试：本地基础工程行为；其显示名称等软件字段不假称来自 FM。
- 本次授权的移动支付订阅主链进一步明确为：成功登记包含全部 11 个必填字段的订阅合同后，系统自动派生付款要求并调用 local/test 支付端口；local/test 使用 FM 场景已有的固定协议、请求标识与业务时间夹具。
- 本切片的正式 API 规划输入仅包含 `capability.register-subscription-reader`、`capability.list-subscriptions-reader`、`capability.read-subscription-reader`、`capability.read-payment-reader`；支撑资源随投影保留。其他能力仍属于统一 API 设计，但不进入本次实施计划。

## MVP 与非目标

本次授权的业务切片是移动支付订阅主链（登记完整合同 → 自动发起付款要求 → 调用 local/test 支付端口 → 判断完成 → 读取状态），由用户指令决定；它不等于全局业务 MVP 已经收敛。内容访问、退款、恢复、预付费与异常履约仍待后续取舍。当前可指认的工程范围是 Harness、本地用户基础切片与此切片。

以下不由此次前馈重构新增：生产身份系统、外部支付协议、多语言产品支持、法定审计留存、生产数据库选型、独立发布的后端服务。它们是否纳入软件交付，须有需求/技术依据；未定不等于永久排除。

## 下游使用

[故事与验收](stories.md)只登记有依据的需求或实现核对项。规划可以设计候选切片，但执行前须核对来源授权、局部缺口和审核状态。API 覆盖完整也不能替代软件范围决定。本次切片的授权、非目标与未决项只在本页与故事维护，计划索引引用而不复制。
