# 软件职责与范围

## 来源与状态

本页区分业务来源、已有实现和待决定的软件范围，不批准业务模型，也不把存在的代码追认为完整产品交付。

- [发现记录](../../.evidence/discovery.md)与 [FM 概览](../../.evidence/fm/00-overview.md)：当前模型是 CRM 电话销售绩效协议及其客户信息依赖；发现记录同时保留已移出当前 FM 的移动支付订阅澄清。
- [模型入口](../../.evidence/fm/model.yaml)：模型文件不保存审核状态；执行前核对实际源。
- [API 设计](../../.evidence/api/api.yaml)：当前是 `api.sales-performance`，三个登记能力与两条消费者旅程；业务接口契约，不是已部署接口清单。
- [用户切片说明](../../apps/backend/README.md)及其源码/测试：本地基础工程行为；其显示名称等软件字段不假称来自 FM。
- 本次授权的软件切片是绩效协议主链，授权来源为用户交付指令；计划的 `authorizationRefs` 引用[建模评估](../../.evidence/fm/crm-assessment.md)，收敛状态见缺口 `GAP-SCOPE-CRM`，故事与验收见[故事与验收](stories.md)。

## MVP 与非目标

本次授权切片是绩效协议主链（登记协议 → 提出月度目标 → 登记联系记录 → 完成判断），由用户交付指令决定；它不等于全局业务 MVP 已经收敛。当前可指认的工程范围是 Harness、本地用户基础切片与此切片。

以下不由本切片新增：前端页面、生产身份系统与生产数据库、协议参与方实例核验与 403、未达标后果（补偿、处分、违约）、周度进度检查、客户档案生命周期与读写接口。它们是否纳入软件交付须有需求或技术依据；未定不等于永久排除。

历史说明：移动支付订阅主链曾按用户当时指令授权，其 FM/API 来源已随模型收敛移出当前仓库（提交 `0e76410`）；该切片本轮未获授权澄清，故不作为当前验收输入，业务澄清仍保留在[发现记录](../../.evidence/discovery.md)。

## 下游使用

[故事与验收](stories.md)只登记有依据的需求或实现核对项。规划可以设计候选切片，但执行前须核对来源授权、局部缺口和审核状态。API 覆盖完整也不能替代软件范围决定。本次切片的授权、非目标与未决项只在本页与故事维护，计划索引引用而不复制。
